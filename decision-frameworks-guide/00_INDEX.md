## 为什么"AI 使用者"尤其需要决策框架

一个反直觉的事实：AI 越强，框架越重要，而不是越不重要。原因有三。

其一，**AI 负责生成，你负责判断**。模型能产出十个方案、十种论证，但"选哪个""该不该做""先做什么"仍是你的责任——决策框架就是判断力的显性化工具。其二，**框架是可复用的 prompt 骨架**。本书每个框架都能直接变成让 AI 结构化思考的模板，把"帮我想想"升级为"用 X 框架分析"。其三，**框架防止 AI 的流畅度俘获你**。模型的答案总是自信流畅的，一个外部框架强迫你检查它漏了什么维度——框架是你对抗"被说服"的锚。

## 元决策：先选框架，还是先想问题？

框架是工具不是仪式。错误用法是"拿着锤子找钉子"——为了用 SWOT 而做 SWOT。正确的元流程：

1. **先分诊问题类型**（这本身就用 Cynefin）：简单问题直接做，别套框架；复杂/混乱问题才值得上工具。
2. **按问题的动词选家族**：问题里的关键动词是"定义/理解" → 家族 1；"排序/选择" → 家族 2/3；"评估局面" → 家族 4；"在不确定中拍板" → 家族 5;"持续改进" → 家族 6。
3. **框架给结构，不给答案**。框架保证你不漏维度、推理可复核，但填什么内容、如何权衡仍是你（和你的领域知识）的事。**一个框架从不替你决策，它只是让你的决策过程可被检验。**

## 七条跨框架心法

1. **框架是脚手架，拆房子前先搭，住进去后就拆**。内化后的框架应该消失在直觉里，反复念叨"我在用 RICE"说明还没内化。
2. **多数框架的价值在"强制完整性"**：它们逼你看你本想跳过的维度（反例、成本、二阶后果）。
3. **量化类框架（RICE/ICE/期望值）的数字是沟通工具，不是真理**。它们让假设显式、可辩论，而不是让结果精确。别被小数点骗了。
4. **警惕框架被反向利用**：先有结论再填框架为其背书，是最常见的滥用。诚实检验：填之前你知道答案吗？如果知道，框架只是在表演。
5. **可逆性是元框架**（见 [[05_不确定性决策型]]）：先分诊"这个决策错了能不能撤"，再决定投多少分析精力。可逆的快做，不可逆的慢做。
6. **决策质量 ≠ 结果质量**：好框架好推理也可能撞上坏运气。复盘评过程，不评结果,否则会训练出赌徒。
7. **框架会过时，认识论不会**：具体框架是特定时代的产物，但"结构化思考、显式化假设、主动找反例"这些底层习惯永久有效。

## 框架特性速查

| 框架 | 定量? | 主要防御的偏误 | 上手难度 |
|------|-------|--------------|---------|
| 第一性原理 | 否 | 类比惰性、路径依赖 | 高 |
| 逆向思考 | 否 | 乐观偏差、盲区 | 低 |
| Cynefin | 否 | 一刀切、错配方法 | 中 |
| Eisenhower | 否 | 紧急压倒重要 | 低 |
| RICE / ICE | 是 | 拍脑袋排序、HiPPO | 低 |
| 80/20 | 半 | 平均用力 | 低 |
| 机会成本 | 半 | 忽略隐性成本 | 中 |
| 期望值 | 是 | 概率忽视 | 中 |
| 沉没成本 | 否 | 承诺升级 | 低 |
| SWOT | 否 | 视角狭窄 | 低 |
| 二阶思维 | 否 | 只看直接后果 | 中 |
| 贝叶斯 | 是 | 忽略基率、锚定 | 高 |
| 单向门/双向门 | 否 | 决策速度错配 | 低 |
| Pre-mortem | 否 | 过度自信 | 低 |
| OODA / PDCA | 否 | 分析瘫痪 / 不复盘 | 中 |
