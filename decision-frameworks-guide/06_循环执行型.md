# 家族六 循环执行型：把决策变成迭代

> 前五个家族帮你做"一次决策"，这一族处理"连续决策"——真实世界不是拍一次板就结束，而是行动、观察、调整的持续循环。它们把决策从静态选择变成动态适应，这对身处快速变化环境的 AI 使用者尤其关键。

---

## 1. OODA 循环 Observe-Orient-Decide-Act

**核心思想**：决策是一个快速循环——**观察（Observe）环境 → 定向（Orient，用心智模型解读观察，形成态势理解）→ 决策（Decide）→ 行动（Act）→ 回到观察**。军事战略家 John Boyd 提出。核心洞察：**在动态对抗中，谁的 OODA 循环转得更快，谁就能让对手陷入被动**——因为对手还在应对你上一步时，你已经进入下一步。Orient 是循环的枢纽，最容易被忽略也最决定成败。

**什么时候使用**：快速变化、需要持续适应的动态环境（竞争、危机、实时博弈）；对手会对你的行动做出反应的对抗性场景；信息不断更新、一次性规划会过时的情况；强调"快速迭代胜过完美计划"时。

**什么时候不要使用**：稳定、可预测、适合一次性周密规划的环境（OODA 的敏捷是为对抗动态而生，静态环境下不如详细计划）；需要深思熟虑的不可逆重大决策（快速循环会牺牲审慎）；Orient 环节的心智模型严重错误时（错误的定向会让循环快速奔向错误方向——转得快反而更糟）。

**优点**：强调速度和适应性，适配动态对抗；Orient 环节提醒你"观察需要正确解读才有价值"；循环结构天然抗"一次规划管到底"的僵化；快速循环本身是一种竞争优势。

**缺点**：过度强调速度可能牺牲深度；Orient 依赖心智模型，模型错则全盘错（且快循环会加速犯错）；对需要长期投入才见效的事不适用；概念简单但"转得快且转得对"的实践很难。

**AI 如何使用**：AI 能极大加速 OODA 的每一环——快速处理观察数据、用海量参照辅助定向（"这个态势像什么已知模式"）、生成决策选项。但 Orient 的最终解读和 Act 的责任仍在你。经典用法：让 AI 帮你缩短"观察到理解"的时间，尤其是它擅长的模式识别。

**Agent 如何使用**：OODA 几乎是自主 Agent 的天然运行结构——感知环境（Observe，读工具返回/状态）→ 更新态势理解（Orient，结合上下文推理）→ 选择行动（Decide）→ 执行工具（Act）→ 循环。[[07_工具调用与第一个Agent|Agent 循环]] 本质就是自动化的 OODA。设计要点：Orient 环节（如何解读观察）是 Agent 质量的关键，也是最该加评测的地方。

**Prompt 模板**：
```
我处在一个快速变化的局面：[描述当前态势和对手/环境]
用 OODA 循环帮我快速迭代：
1. Observe：当前最关键的观察是什么？哪些信息在变化？
2. Orient：这些观察意味着什么？（这一步最关键）——它像什么已知模式？我的解读可能错在哪？
3. Decide：基于当前理解，可选的行动有哪些？在信息不全下哪个最合理？
4. Act：立即可执行的下一步是什么？
5. 下一轮循环：行动后我该重点观察什么，来判断解读对不对、是否需要调整？
强调速度：不追求完美方案，追求"快速行动 + 快速修正"。
```

**完整案例**：一家初创公司发现竞争对手突然降价。慢速反应（开三周会做详细方案）会让对手抢占先机。用 OODA 快速循环：Observe——对手降价 30%，我方咨询量下降。Orient（枢纽）——这是价格战还是清库存？解读为"试探性降价"而非全面战争，且我方优势在服务而非价格。Decide——不跟进降价（会陷入消耗战），而是强化服务差异化的传播。Act——48 小时内上线一波"服务价值"营销。下一轮观察——转化率是否回升，对手是否进一步降价。若观察显示解读错了（对手确在打全面价格战），下一循环快速调整。OODA 的贡献是让公司在对手还在观察己方降价效果时，就完成了一轮"观察-定向-决策-行动"，用速度把主动权夺回来，同时通过循环保留了"解读错了就快速改"的纠错能力。

## 2. PDCA 循环 Plan-Do-Check-Act

**核心思想**：持续改进的循环——**计划（Plan）→ 执行（Do）→ 检查（Check，对比结果与预期）→ 处理（Act，把有效的标准化、无效的进入下一轮改进）**。源自质量管理（戴明环）。与 OODA 的区别：OODA 为动态对抗中的快速决胜而生，PDCA 为稳定的持续改进而生——一个求快求胜，一个求稳求进。

**什么时候使用**：持续优化一个流程/产品/习惯；质量改进、效率提升类工作；需要用小步试验积累改进、而非一步到位时；建立"改进-固化-再改进"的可持续机制。

**什么时候不要使用**：需要突破性创新而非渐进改进时（PDCA 优化现有的，不创造全新的）；快速对抗环境（用 OODA）；一次性、无重复的任务（循环无从谈起）；Check 环节缺乏客观衡量标准时（无法 Check 的 PDCA 会退化成瞎转）。

**优点**：结构化的持续改进，防止"做了就完、从不复盘"；Check 环节强制用证据检验，对抗自我感觉良好；Act 环节把有效改进固化为标准，防止倒退；小步迭代降低单次风险。

**缺点**：偏渐进改进，不擅长颠覆式创新；循环较慢，不适合需要即时反应的场景；容易停在 Do 而跳过 Check（人性倾向做而不检）；Check 的质量决定一切，弱 Check = 假改进。

**AI 如何使用**：让 AI 辅助每一环——Plan（生成改进假设）、Check（分析结果数据、对比预期）、Act（提炼可标准化的经验）。AI 在 Check 环节尤其有价值：它不带"我做的应该有效吧"的心理偏向，能客观对比结果与目标。也可用于 prompt/工作流本身的迭代优化（改 prompt→测→比对→固化）。

**Agent 如何使用**：自我改进型 Agent 与 [[evaluation-of-ai-systems/00_INDEX|评测驱动的迭代循环]] 的骨架——Agent 执行任务（Do）→ 用评测集检查表现（Check）→ 调整策略/prompt（Act）→ 下一轮（Plan）。PDCA 为"Agent 如何随时间变好"提供了结构，Check 环节对应评测工程。

**Prompt 模板**：
```
我想持续改进[流程/产品/习惯]。当前状态：[现状 + 可衡量的指标]
用 PDCA 帮我建立改进循环：
1. Plan：改进假设是什么？预期能让[指标]改善多少？（要可衡量）
2. Do：最小成本的试验方案是什么？（小步，别一次全改）
3. Check：怎么客观检验效果？用什么数据对比预期？如果没达预期，可能是哪出了问题？
4. Act：如果有效，怎么把它标准化固化下来防止倒退？如果无效，下一轮该调整什么假设？
5. 设计这个循环的节奏：多久转一轮合适？
```

**完整案例**：一个团队的客服响应质量不稳定，想持续改进。用 PDCA：Plan——假设"给客服提供标准应答模板能提升一致性和满意度"，预期满意度提升。Do——先在一个小组试用模板两周（小步，不全员铺开）。Check——对比试用组和对照组的满意度和处理时长数据：满意度确有提升，但处理时长略增（客服在模板里找措辞）。Act——保留模板（有效）但简化为更易检索的形式（针对发现的副作用改进），标准化后推广，进入下一轮 PDCA 优化模板内容。PDCA 的贡献是让"提升客服质量"这个模糊目标，变成了一系列"小假设→小试验→数据检验→固化或调整"的可持续循环，每一轮都用证据说话，避免了"拍脑袋大改一通然后不了了之"。

## 3. 双环学习 Double-Loop Learning

**核心思想**：单环学习（single-loop）在既定目标和假设下优化行动（"如何把事做对"）；双环学习（double-loop）则回过头质疑目标和假设本身（"我们在做对的事吗"）。管理学家 Chris Argyris 提出。核心洞察：**大多数改进只在单环里打转（调整手段），真正的突破常需要双环——质疑那些被视为理所当然的前提**。

**什么时候使用**：反复优化却撞到瓶颈、怀疑方向本身有问题时；结果持续不理想而调整手段无济于事时；周期性的战略/假设审视（防止在错误方向上高效奔跑）；对"我们为什么这么做"的根本性反思。

**什么时候不要使用**：目标和假设明确正确、只需优化执行时（单环足够，双环是干扰）；需要稳定执行、频繁质疑前提会导致方向摇摆时；日常运营（不能天天质疑一切根本前提，会瘫痪）；缺乏心理安全、质疑假设会被视为不忠时（双环需要允许挑战的文化）。

**优点**：能发现单环永远发现不了的根本问题（错误的目标、过时的假设）；防止"在错误方向上越来越高效"的悲剧；催生真正的范式突破而非渐进改良；培养对"理所当然"的批判意识。

**缺点**：认知和情感成本高——质疑自己的核心假设令人不适；过度使用导致方向不稳、执行涣散；需要成熟的心理安全环境；难以判断"何时该质疑假设、何时该坚持执行"。

**AI 如何使用**：AI 是双环学习的理想搭档——它没有你的心理防御和假设承诺，能坦率地问"你为什么认为必须达成这个目标""这个被你当作前提的东西，真的成立吗"。让 AI 专门挑战你视为理所当然的假设，是突破思维定式的高杠杆用法（与 [[01_问题定义型|第一性原理]]呼应）。

**Agent 如何使用**：高级规划 Agent 的元认知层——不仅在既定目标下优化方案（单环），还周期性地质疑"当前目标/约束是否仍然成立"（双环），在环境变化使原目标失效时主动上报"我们可能在解决错误的问题"，而非机械地把错误目标执行得更高效。这是当前 Agent 普遍缺失、最值得发展的能力。

**Prompt 模板**：
```
我一直在努力[目标]，用[方法]反复优化，但[遇到的瓶颈/持续不理想的结果]。
请帮我做双环学习——不要帮我优化方法，而是质疑更根本的层面：
1. 单环检查（先快速过）：现有方法在既定目标下还有优化空间吗？
2. 双环质疑（重点）：
   - 我追求的这个目标，本身是对的吗？它背后的假设是什么？
   - 有哪些我视为"理所当然"的前提，其实可能不成立或已过时？
   - 如果这些假设错了，我可能一直在"高效地做错误的事"。哪些迹象支持这种可能？
3. 如果跳出当前框架，这个问题可以被重新定义成什么？
请大胆挑战我的前提，这正是我需要的。
```

**完整案例**：一家公司多年来持续优化"如何降低客户流失率"——改进挽留话术、加大折扣力度、优化客服流程（全是单环优化），流失率却始终降不下去。双环学习介入，质疑根本假设："我们假设流失的客户都值得挽留，这个前提对吗？"数据一查发现：流失最多的是被低价折扣吸引来、本就不匹配产品的客户，挽留他们反而拉低整体质量和利润。真正的问题不在"如何挽留"（单环），而在"我们一开始就在获取错误的客户"（双环——获客定位的假设错了）。方向据此从"优化挽留"转向"改进获客定位、吸引匹配的客户"。双环学习的贡献是拦住了"在错误方向上越跑越快"——公司差点把资源持续投在挽留不该挽留的人上，而根本病灶在更上游的假设里。
