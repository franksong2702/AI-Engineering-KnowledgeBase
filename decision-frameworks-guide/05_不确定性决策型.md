# 家族五 不确定性决策型：信息不全也要拍板

> 现实决策几乎从不在信息充分时做出。这一家族处理"不确定性"本身——如何随证据更新、如何按可逆性调节谨慎、如何在信息不全时依然做出可复盘的好决策。这是决策框架里最深、也最保值的一族。

> 关联 Laws：[[laws-of-ai-engineering/07_认识论与真理定律#Law 61 — 贝叶斯更新定律（Bayesian-Updating Law）|Law 61：贝叶斯更新定律]]给出不确定性下的更新纪律，[[laws-of-ai-engineering/07_认识论与真理定律#Law 64 — 可证伪性定律（Falsifiability Law）|Law 64：可证伪性定律]]要求经验性决策假设说明什么证据会使其改判，[[laws-of-ai-engineering/08_可靠性与失败定律#Law 74 — 不可逆性定律（Irreversibility Law）|Law 74：不可逆性定律]]参与决定审慎度。

## 1. 贝叶斯思维 Bayesian Thinking

**核心思想**：信念是概率而非非黑即白，新证据到来时按比例更新，而非推倒重来或固执不变。结论 ≈ 先验（基础概率）× 证据强度（似然比）。核心纪律：**重视基础概率（base rate），并问"这个证据在我的假设为假时出现的概率有多大"**。

**什么时候使用**：几乎所有涉及不确定判断的场景；有新信息进来、需要更新看法时；评估罕见事件（诊断、风险、异常）——最容易忽略基率的地方；对抗过度自信和固执己见；判断 AI 或他人给的"证据"到底有多大说服力时。

**什么时候不要使用**：需要果断行动、没时间精算概率时（可用其定性版：别忘基率、按证据调整信念）；概率和基率完全无从估计时（贝叶斯需要先验，纯无知下退化为猜测）；有明确因果和确定性答案的问题（杀鸡用牛刀）。

**优点**：把"确信/不确信"的二元思维升级为可校准的概率；显式处理基础概率，防御最常见的统计错误；提供了"如何理性改变主意"的机制——更新而非崩溃或固守；量化了证据的真实价值（似然比）。

**缺点**：先验主观，"从哪个先验出发"影响结论；概率估计本身容易有偏；认知负荷高，日常小事套用不现实；容易产生"精确的错觉"（给猜测标上 73% 并不让它更真）。

**AI 如何使用**：让 AI 帮你结构化贝叶斯更新——明确先验、评估新证据的似然比、算出后验，尤其提醒你**忽略了的基础概率**。经典用法：当某个证据让你想下强结论时，问 AI"这个证据在结论为假时也会出现吗"，戳破被似然性伪装的巧合。

**Agent 如何使用**：这正是 [[multi-agent-patterns-handbook/00_INDEX|Multi-Agent 手册]]、诊断/推理型 Agent 的核心——Agent 维护对各假设的概率分布，每获得新观察（工具返回、检索结果）就做贝叶斯更新，据此决定下一步查什么最能区分假设（信息增益最大化），而非盲目穷举。

**Prompt 模板**：
```
我在判断[某个不确定的假设]。目前的信息：[已知证据]
请帮我做贝叶斯式分析：
1. 先验：在看到任何具体证据前，这个假设的基础概率大概是多少？（基于同类情况的基率）
2. 逐条评估证据：每条证据的似然比——它在"假设为真"vs"假设为假"时出现的概率各是多少？
   （关键：一个证据如果在真假两种情况下都容易出现，它其实没有区分价值）
3. 综合得到后验概率（定性即可：显著上调/小幅上调/几乎不变）
4. 我是不是忽略了基础概率，被生动的证据带跑了？
5. 什么样的新证据最能改变这个判断？（指导下一步该找什么信息）
```

**完整案例**：一位管理者听说某员工"效率低"，想据此调整安排。贝叶斯分析：先验——该员工过往绩效一贯不错（高先验可信度）。新证据——"最近一个项目延期"。似然比检验：项目延期在"员工确实变差"和"项目本身超难/依赖外部"两种情况下都很可能发生 → 这条证据的区分价值很低，不足以大幅下调对该员工的评价。基率提醒：优秀员工偶尔一次延期是常态而非信号。结论：后验只小幅调整，不该据单次事件下重结论，而应观察是否形成模式。贝叶斯的贡献是拦住了"一个生动负面事件 → 推翻长期判断"的过度反应，把单点证据放回它应有的分量。

## 2. 单向门 vs 双向门 Reversible / Irreversible

**核心思想**：决策先分诊可逆性。**双向门**（可逆决策）：错了能低成本退回，应该**快速、授权、少分析**。**单向门**（不可逆决策）：错了难以挽回，应该**放慢、升级、反复推演**。贝索斯的核心洞见：大多数决策的失败不是决策本身错，而是**用错了决策速度**——用单向门的谨慎处理双向门（错失、瘫痪），或用双向门的草率处理单向门（灾难）。

**什么时候使用**：面对任何决策的第一道分诊（这该快做还是慢做？）；感觉决策太慢、被过度分析拖累时（多半是把双向门当单向门了）；重大不可逆决策前，确认自己给了足够的审慎；设计组织授权机制（哪些决策可下放）。

**什么时候不要使用**：可逆性判断本身一目了然的琐事；可逆性处于灰色地带、需要更细致分析时（不是所有决策都干净地二分）；用"反正可逆"给草率决策找借口时（可逆不等于无成本）。

**优点**：极其简单却解决了决策中最普遍的错配问题；同时对抗两种病——分析瘫痪和鲁莽；提供了组织授权的清晰逻辑（双向门下放、单向门集中）；是元框架，决定其他框架投入多少。

**缺点**：可逆性有时难判断，且人会系统性误判（把可逆的当不可逆而恐惧，或反之）；二分过于简化，现实是连续谱；"可逆"忽略了即使能退回也已付出的时间和机会成本。

**AI 如何使用**：决策前让 AI 帮你判断可逆性——"这个决定如果错了，撤销的成本有多大？是真不可逆还是我心理上觉得不可逆？"人常把可逆决策情绪化为不可逆（恐惧放大），AI 的冷静评估能校准。

**Agent 如何使用**：Agent 权限设计的核心原则（贯穿 [[multi-agent-patterns-handbook/00_INDEX|三本手册]]）——可逆操作（读取、生成草稿、可撤销的修改）放手让 Agent 自主快速执行；不可逆操作（删除、发送、支付、发布）强制人工审批。可逆性直接决定自主性边界。

**Prompt 模板**：
```
我面临决策：[决策]。请先做可逆性分诊：
1. 如果这个决定错了，撤销/退回的成本有多大？（时间、钱、机会、声誉）
2. 判定：这是双向门（可逆，错了能低成本退回）还是单向门（不可逆或代价高昂）？
3. 据此给出决策建议：
   - 若双向门：别过度分析，快速试，保留纠错机制。我是不是想太多了？
   - 若单向门：值得放慢、多方求证、做 pre-mortem。我准备充分了吗？
4. 有没有办法把这个单向门"改造成"双向门？（如小范围试点、加退出条款、分阶段投入）
```

**完整案例**：一个团队为"选哪个数据库"争论了三周迟迟不决。可逆性分诊：换数据库虽然有成本，但在早期数据量小时其实是**双向门**（迁移可行，非致命）——他们把它当成了单向门来恐惧，导致瘫痪。建议：快速选一个合理的先用起来，把省下的三周投入产品本身。对比另一决策"要不要签三年期的独家排他合同"——这是真正的单向门（锁死未来选项），值得反复推演、找退出条款。同一个团队的两个决策，一个被误当单向门而拖延，一个才真需要审慎。这个框架的最大贡献是把"该快还是该慢"这个元问题显式化——它常比决策内容本身更重要。第 4 点尤其有价值：很多单向门能通过试点/分阶段改造成双向门。

## 3. 遗憾最小化 Regret Minimization

**核心思想**：把视角推到人生的远端（"80 岁的我回望"），问"哪个选择会让未来的我最少后悔"。贝索斯离开稳定工作创业时用的正是这个框架。核心洞察：**远期视角能过滤掉短期的恐惧和噪音**，让真正重要的价值浮现——人临终最后悔的通常是没做的事（未走的路），而非做过的失败。

**什么时候使用**：人生尺度的重大选择（职业、创业、重大关系、居住地、是否追求某个梦想）；被短期恐惧/舒适困住、看不清长期时；决策的情感权重大、纯理性算不清时；单向门级别的、影响深远的选择。

**什么时候不要使用**：短期、可逆、低影响的决策（用它是杀鸡用牛刀，且会把小事戏剧化）；日常战术选择（用期望值/RICE 更合适）；当下情绪极端时（此时"想象的遗憾"会被情绪扭曲）；需要精确权衡而非价值澄清时。

**优点**：穿透短期恐惧，直达长期价值；对"该不该冒险追求重要的事"这类决策极有力；把难以量化的人生选择转化为一个清晰的问句；心理上强大——它诉诸你最深的价值排序。

**缺点**：只适用于人生大尺度决策，滥用于小事会瘫痪生活；"想象未来的遗憾"本身可能不准（人会误判未来的自己）；容易被"做了才不后悔"的偏向裹挟，忽视做错事的真实代价；无法处理需要精确权衡的决策。

**AI 如何使用**：让 AI 引导你做遗憾最小化的思想实验——不是替你回答，而是帮你把"哪个选项让远期的你更少后悔"这个问题展开，追问你真正看重什么。这类价值澄清适合对话式展开，AI 做提问者而非答题者。

**Agent 如何使用**：这是少数**不适合自动化**的框架——它诉诸个人的深层价值和人生意义，是人类保留的决策领地。Agent 的正确角色至多是"提醒你有个重大选择值得用长期视角想一想"，而非替你判断你会后悔什么。（诚实标注：不是所有框架都该交给 Agent。）

**Prompt 模板**：
```
我面临一个重大人生选择：[选项 A vs 选项 B]
当下我倾向于[某选项]，主要因为[原因，往往含短期恐惧或舒适]。
请引导我做遗憾最小化思考（用提问帮我想清楚，不要直接替我决定）：
1. 想象 80 岁的我回望这个决定。哪个选择更可能让我后悔"当初没试"？
2. 我现在倾向的理由里，哪些是短期恐惧（会过去的）、哪些是真实长期的顾虑？
3. 最坏情况下选了冒险的那条路失败了，未来的我会后悔吗，还是会庆幸自己试过？
4. 抛开当下的舒适和恐惧，哪个选择更符合我真正看重的东西？
```

**完整案例**：一个人有稳定高薪工作，纠结要不要辞职去做热爱但高风险的事。当下倾向留下，理由主要是"怕失败、怕不稳定"（短期恐惧）。遗憾最小化思想实验：想象 80 岁回望——如果一直没试，很可能会带着"如果当年试了会怎样"的遗憾；而如果试了失败，80 岁的他大概率会庆幸自己至少走过那条路、不留悬念。这个远期视角揭示出：他的短期恐惧（失败、不稳定）是会过去的，而"未走之路"的遗憾是持久的。注意框架不保证答案是"辞职"——若那件事失败会危及家人生计（真实长期顾虑，非短期恐惧），结论可能不同。它的贡献是把决策从"我现在害怕什么"重新锚定到"我最终会珍视什么"，同时配合可逆性分诊（能不能先兼职试而不裸辞）让冒险变得可承受。

## 4. Pre-mortem 事前验尸

**核心思想**：在行动**之前**,想象它已经彻底失败,然后倒推"为什么会失败"。区别于事后复盘（post-mortem，木已成舟），pre-mortem 在还能改变结果时暴露风险。心理学家 Gary Klein 提出。核心机制：假设失败已成事实，能解锁人在"评估风险"模式下打不开的坦诚（"前瞻性事后聪明"）。

**什么时候使用**：重要计划/项目启动前；团队对方案过于乐观、一致叫好时（危险信号，最需要 pre-mortem）；不可逆或高投入决策前；任何"感觉这次稳了"的时刻。

**什么时候不要使用**：琐碎、可逆、低风险的行动（成本不值）；团队已陷入过度悲观、信心不足时（再想失败会瘫痪）；纯执行阶段、已无调整空间时；作为拖延决策的借口。

**优点**：绕过乐观偏差和群体思维——"假设已失败"比"可能有什么风险"更能撬出真实担忧；把沉默的疑虑合法化（给了唱反调的心理安全）；产出可直接转为风险缓解清单；成本极低、收益高。

**缺点**：需要团队心理安全，否则流于形式；可能生成过多低概率风险，需筛选（配合概率/影响排序）；想象的失败不等于真实的失败模式；一次性活动，不覆盖执行中新生的风险。

**AI 如何使用**：让 AI 扮演 pre-mortem 主持人，生成"这个计划失败的 N 种方式"。AI 无社交顾虑、不怕唱反调、见过海量失败模式，特别擅长说出团队成员碍于气氛不敢说的风险。是 [[01_问题定义型|逆向思考]] 在项目决策上的具体应用。

**Agent 如何使用**：规划型 Agent 在输出重要方案前的强制自检步骤——生成方案的失败场景与早期预警信号，据此在方案里预置缓解措施和检查点，把"事后救火"提前为"事前设防"（与红队、二阶思维协同）。

**Prompt 模板**：
```
我们的计划是：[计划详情]。团队目前比较乐观。
请主持一次 pre-mortem：
1. 假设现在是[未来时点]，这个计划已经彻底失败了。这是既成事实。
2. 生成失败的 8-10 种可能原因（不要保留、不要顾及情面，尽可能坦诚和多样）
3. 每个失败原因：现在有什么早期预警信号？发生概率和影响多大？
4. 按"概率×影响"排序，锁定最该防的 top 3
5. 对 top 3，给出现在就能采取的最小成本预防/缓解措施
你的角色是那个敢说真话的人,把所有人心里隐约担心但没说出口的风险摆到台面上。
```

**完整案例**：一个团队即将上线一个大版本，士气高涨、一致看好——这种"全体乐观"恰是 pre-mortem 最该介入的信号。主持 pre-mortem："假设上线后成了灾难，为什么？"坦诚倒推暴露出一批被乐观情绪掩盖的风险：新功能没做灰度直接全量、依赖的第三方接口没有降级方案、客服团队没提前培训、回滚流程从没演练过。按概率×影响排序，"无灰度全量上线"和"无回滚预案"排前列。团队据此在上线前补了灰度发布和回滚演练。上线时果然触发一个未预料的 bug，但因为有灰度（影响面被限制在 5%）和演练过的回滚（几分钟恢复），一次潜在灾难变成了小插曲。pre-mortem 的核心贡献是趁一切还能改变时，把"上线稳了"的集体乐观撬开，逼出了那些没人愿意在庆功气氛里提的风险。

## 5. 决策与结果分离 Decision vs Outcome（Resulting）

**核心思想**：决策的质量和结果的质量是两回事。好决策（基于当时可得信息的最佳推理）可能因运气得到坏结果；坏决策可能侥幸成功。扑克冠军 Annie Duke 称用结果反推决策质量为"resulting"——一种普遍的思维错误。核心纪律：**复盘时评估决策时点的信息与推理过程，而非事后的结果**。

**什么时候使用**：复盘任何决策时（尤其结果很好或很坏时——两种极端都最容易误导）；从经验中学习、想提炼真正的教训时；评价他人（下属、自己）的决策质量时；对抗"结果好就是决策对"的归因偏差。

**什么时候不要使用**：这更是一种始终该有的复盘纪律而非情境工具，没有真正"不适用"的场景。唯一的提醒：别走向另一个极端——用"运气不好"为一切坏结果开脱，逃避真实的决策缺陷。区分"决策时无法预知"和"决策时本可预知却没做功课"。

**优点**：让你从经验中学到真教训，而非被运气误导；防止因一次好结果而固化坏习惯（赌徒的养成路径）；建立公平的决策评价文化（不因运气奖惩）；培养过程导向而非结果导向的成长心态。

**缺点**：违反直觉和人性（人天然用结果论英雄）；可能被滥用为"我决策没错只是运气差"的甩锅工具；区分"运气"和"实力"本身很难；在结果导向的组织/社会里践行有阻力。

**AI 如何使用**：复盘时让 AI 帮你把"决策质量"和"结果质量"拆开评估——"在当时能获得的信息下，这个决策的推理站得住吗？"AI 不受结果的情绪冲击，能冷静区分"你运气不好"和"你当时就该看到这个风险"。

**Agent 如何使用**：评估型 Agent（复盘助手、决策日志分析）的评价逻辑——记录决策时点的信息与推理，评价时基于当时上下文而非事后结果，避免用结果给决策贴标签，从而积累真正可复用的决策改进数据（与 [[evaluation-of-ai-systems/00_INDEX|评测工程]]的"评过程不评单次结果"同源）。

**Prompt 模板**：
```
我要复盘一个决策：[决策 + 结果如何]
请帮我把决策质量和结果质量分开评估：
1. 回到决策时点：当时能获得哪些信息？基于那些信息，这个推理合理吗？
2. 结果是好是坏？这个结果多大程度来自决策质量，多大程度来自运气（决策时无法预知的因素）?
3. 四象限定位：好决策好结果 / 好决策坏结果（运气差）/ 坏决策好结果（运气好，危险）/ 坏决策坏结果
4. 真正的教训是什么？——是"改进决策过程"，还是"这次只是运气，过程没问题别乱改"?
5. 诚实检验：如果我在甩锅给运气，当时是否其实有本可获取却没去获取的信息？
```

**完整案例**：一位投资者重仓押注一只股票大涨，赚了钱，得意地认为自己"眼光独到"、打算下次加倍下注。用决策与结果分离复盘：结果好（赚钱），但决策质量如何？回到决策时点——他其实没做充分研究，只是跟风+运气好赶上大盘普涨。这是"坏决策 + 好结果"象限，最危险的一种，因为好结果会强化坏习惯，诱导他下次押更大而终将翻车。真正的教训不是"我眼光好，加倍下注"，而是"我这次赚钱靠运气，决策过程有严重缺陷，必须补上研究纪律"。反过来，若他当时做足了功课、基于扎实推理下注，即便某次亏了钱（好决策+坏结果），也不该推翻方法。这个框架的核心贡献是斩断"结果好=决策对"的致命归因，让人从经验里学到真教训而非被运气训练成赌徒。
