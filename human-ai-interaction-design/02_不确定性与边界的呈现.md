# 第二章 不确定性与边界的呈现：诚实的界面语言

> 模型内部有不确定性，用户需要知道它——中间隔着一个设计问题：怎么显示才是校准，而非表演或噪音。这一章处理四件事的呈现：置信度、拒答、来源、能力边界。

> 关联 Laws：[[laws-of-ai-engineering/03_统计与泛化定律#Law 26 — 校准定律（Calibration Law）|Law 26：校准定律]]是显示置信度的前提约束——未校准的置信度不配被显示，[[laws-of-ai-engineering/07_认识论与真理定律#Law 62 — 流畅度非正确性定律（Fluency-Is-Not-Truth Law）|Law 62：流畅度非正确性定律]]要求呈现层不放大流畅感，[[laws-of-ai-engineering/01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|Law 4：信息守恒定律]]决定"来源"是事实类输出的必备界面元素。

## 底层原则

**原则一：显示未校准的置信度比不显示更糟。** "87% 确信"这个数字若与实际正确率无关，它就是披着精度外衣的噪音——用户会按它分配信任，被精确地误导（[[laws-of-ai-engineering/03_统计与泛化定律#Law 26 — 校准定律（Calibration Law）|Law 26]]）。**显示置信度的资格来自校准数据，不来自模型给得出数字。**

**原则二：不确定性的呈现粒度应匹配用户的决策粒度。** 用户的决策通常是三档：直接用 / 核验后用 / 别用它。呈现也三档就够——数字化的假精度（73% vs 78%）不改变任何用户决策，反而制造"被量化的错觉"。粒度超过决策需要的部分全是噪音。

**原则三：拒答是产品特性，不是产品失败。** 一个从不说"不知道"的系统在它不知道的时候必然在编（[[laws-of-ai-engineering/01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|Law 4]]）。拒答体验的好坏决定用户如何理解拒答：设计得好，它是系统诚实的证据（提升长期信任）；设计得差，它被体验为故障（用户流失或诱导系统硬答）。

**原则四：来源不是脚注，是事实类输出的承重结构。** 带出处的断言把核验成本从"自己查一遍"降到"点开看一眼"（[[laws-of-ai-engineering/02_计算与验证定律#Law 12 — 验证-生成不对称定律（Verification-Generation Asymmetry Law）|Law 12]] 的界面应用）；无出处的事实断言，界面应让它**看起来就和有出处的不一样**——同样的排版是在均贫富信任。

## 设计模式

**模式 1 · 三档置信呈现**：高置信（正常呈现）/ 中置信（显式标注"对此不完全确定"+ 给出不确定在哪）/ 低置信（转为"我的猜测是…建议核验"或直接拒答）。档位切换由校准过的信号驱动（多次采样一致性、检索命中质量），不是模型的自我感觉。

**模式 2 · 定位的不确定性**：不说"以上回答可能有误"（全局免责=零信息），说"其中 X 的数字来自 2023 年数据，可能过时"——把不确定性**定位到具体断言**。可疑处内联标记，用户的核验注意力被引导到刀刃上（[[human-ai-collaboration-foundation/04_对抗自动化偏见|警惕配额]]的呈现版）。

**模式 3 · 建设性拒答**：拒答三件套——说清**为什么**答不了（超出知识范围/检索无结果/问题歧义）、给出**能做的部分**（"我可以回答相关的 X"）、给出**下一步**（怎么改问题/去哪里查/转人工）。裸拒答（"我无法回答"）教会用户的是"再问一遍或换个说法骗过它"。

**模式 4 · 出处的可核查设计**：引用直达原文位置（不是文档首页）；引用与断言逐条对应（不是文末堆一列链接）；无出处断言视觉降权。RAG 场景加"检索置信"：材料不足时说"资料里没有直接答案，以下是基于相近内容的推断"——把 [[llm-design-patterns/00_INDEX|RAG 拒答纪律]]翻译成用户语言。

**模式 5 · 能力边界的主动传达**：空状态写"我擅长/我不擅长"（各三条，具体到任务而非"复杂问题"）；越界请求触发边界提示而非硬答（"精确计算不是我的强项，我用工具算了：…"——把[[textbook-zero-to-agent/01_AI认知启蒙|能力地图]]内建成界面行为）。

## 工程手册：置信呈现的落地决策树

```
这个输出类型有校准数据吗（置信信号与实际正确率的对照）？
├── 没有 → 不显示任何置信数字/等级。
│         能做的：出处（有无本身就是信号）、定位的不确定标注（基于
│         检索命中/工具校验等客观信号）、语气纪律（见下）
└── 有 → 用户的决策是三档吗？
      ├── 是（绝大多数）→ 三档呈现（模式 1），档位阈值用校准曲线定
      └── 是专业用户且有数字素养（如内部风控）→ 可给数字+可靠性图，
          且必须同屏给"该置信档的历史正确率"
```

**语气纪律**（没有任何校准数据时唯一诚实的杠杆）：禁止系统性使用强化确定性的措辞（"显然""毫无疑问""一定是"）修饰未经核验的断言——这是 prompt 层的呈现设计（写进 system prompt 的输出规范），也是[[model-adaptation/03_对齐与偏好|谄媚检测]]的表面特征之一。反向同理：不许可为免责而通篇"可能也许大概"——那是把校准责任推给用户的语气版免责声明。

**拒答体验的三个实测指标**：拒答后的用户行为分布——改写重问（好：拒答教育了提问）/ 原句重试（坏：被理解为随机故障）/ 流失（坏：被理解为无能）。三个比例是拒答文案的评价数据，按 [[ai-systems-in-production/03_可观测性|L3 代理指标]]的纪律监控其漂移。

**"检索无果"与"知识有界"要区分呈现**：前者是本次没找到（可建议换词、扩大范围），后者是系统性不覆盖（应更新能力边界说明）。混为一谈的"抱歉我不知道"让用户无法学习系统的真实边界。

## 反例与边界

- **三档不是普适真理**。生成类任务（写作、头脑风暴）没有"对错"轴，置信呈现基本不适用——那里的诚实呈现是"多候选"（同题三个方向的草稿，本身就传达了"这是采样不是答案"）。置信呈现主要服务事实类、判断类、计算类输出。
- **定位标注有成本上限**。每句话都带不确定性标记=没有标记（视觉疲劳，同[[ai-systems-in-production/03_可观测性|告警疲劳]]）。标注预算：单次输出的内联标记以个位数为宜（经验量级），只标最要害的。
- **出处会被表演**。模型可能给出真实存在但不支撑断言的链接（引用装饰）——出处的可信度需要[[evaluation-of-ai-systems/00_INDEX|忠实度评测]]兜底，界面层的责任是让"点开核对"足够便宜，让装饰性引用容易被拆穿。
- **过度拒答是另一种失败**。拒答率骤升会摧毁可用性，且可能是[[model-adaptation/03_对齐与偏好|对齐过度保守]]的症状——拒答率与拒答正确率（该拒的拒了吗、不该拒的放过了吗）要一起监控。

## 失败模式

- **假精度**：显示未校准的"87% 确信"，用精确的样子放大误导。
- **全局免责**：唯一的不确定性呈现是底部灰字，等于没有呈现。
- **裸拒答**：不给原因、不给替代、不给下一步，教用户"重试直到它肯答"。
- **引用堆砌**：文末一排链接与断言无对应关系，核查成本没有下降。
- **均一语气**：确凿事实与临场推断用同一种笃定语气呈现（Law 62 的界面版违反）。
- **边界靠撞**：能力边界从不主动传达，用户靠踩坑自己归纳（且常归纳错）。

## 评价方法

- 校准曲线：呈现的置信档 vs 实际正确率（有校准数据才有资格显示——先审资格）。
- 用户核验行为差异：对低置信标注的输出，用户核验率是否显著高于高置信输出？（无差异=呈现没起作用）
- 拒答三指标：改写率 / 原句重试率 / 流失率。
- 引用点击与拆穿实验：抽样检查被点开的引用是否支撑断言。

## 验收清单

- ☐ 显示的每一种置信信号，背后有校准数据吗？
- ☐ 呈现粒度和用户决策粒度（三档）匹配吗？有假精度吗？
- ☐ 不确定性是定位到断言的，还是全局免责？
- ☐ 拒答有三件套吗（原因/能做的/下一步）？拒答三指标在监控吗？
- ☐ 事实断言有出处直达吗？无出处断言视觉上有区别吗？
- ☐ 能力边界有主动传达点吗（空状态/越界提示）？
- ☐ 语气纪律进 system prompt 输出规范了吗？

## 收束

不确定性呈现的四件事：置信（有校准才显示、三档粒度、定位到断言）、拒答（建设性三件套，是特性不是失败）、来源（承重结构、直达、逐条对应）、边界（主动传达不靠撞）。诚实的界面语言是校准的第一战场——它把模型内部的不确定性翻译成用户可用的判断资源，而不是翻译成焦虑或盲信。

最该记住的一句：**未校准的置信度不配被显示，无出处的断言不配与有出处的长得一样——呈现的每个细节要么在帮用户校准，要么在帮剪刀差张嘴。**
