# 第四章 输入与意图的塑造：把提问变成设计对象

> 输出质量的上限在输入处就被决定了一半——而"怎么问"的全部负担，默认被一个空白文本框推给了用户。这一章设计输入侧：自由与引导的平衡、意图的澄清、以及"AI 知道什么"的可见与可控。

> 关联 Laws：[[laws-of-ai-engineering/01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|Law 4：信息守恒定律]]——模型无法回答输入中不存在、上下文中也没有的信息，输入设计就是给这条定律让路；[[laws-of-ai-engineering/09_人机与信任定律#Law 84 — 信任-可靠性剪刀差定律（Trust-Reliability-Scissors Law）|Law 84]] 提醒：输入越顺畅，用户越容易高估系统对意图的理解。

## 底层原则

**原则一：空白文本框是被误当作"自由"的设计弃权。** 它把三重负担全推给用户：知道系统能做什么（能力发现）、知道怎么表述有效（prompt 素养）、知道要提供什么上下文（信息完整性）。专家用户视之为自由，多数用户体验为"空白页恐惧"——然后用搜索引擎的习惯提交三个词，得到平庸结果，归因为"AI 不行"。**输入界面的设计目标是降低这三重负担，而不是外包它们。**

**原则二：意图与字面之间有鸿沟，澄清是桥。** 用户说的（字面）与用户要的（意图）经常不一致（[[laws-of-ai-engineering/09_人机与信任定律#Law 83 — 意图-指令鸿沟定律（Intent-Instruction-Gap Law）|意图-指令鸿沟]]）。系统面对歧义有三个选择：猜（快但错了浪费一轮且损伤信任）、问（慢但准）、带假设地做（折中——"我按 X 理解来做，如果你是指 Y 告诉我"）。**选哪个是设计决策，且应随风险分级**，而不是模型的临场脾气。

**原则三："AI 知道什么"必须可见，否则用户在盲写输入。** 用户对"它能看到我哪个文件、记得哪段历史、检索了什么"的错误假设，是输入失败的最大来源之一——以为它知道（其实不知道）导致缺上下文的提问；以为它不知道（其实记着）导致重复粘贴或隐私意外。上下文的可见性是输入设计的地基（[[laws-of-ai-engineering/01_信息与压缩定律#Law 2 — 上下文即状态定律（Context-is-State Law）|上下文即状态]]的用户侧）。

**原则四：输入界面在教用户提问——教好教坏都在教。** 每次交互都在训练用户的提问习惯：好的引导（示例、结构、改写建议）沉淀为用户的 prompt 素养；坏的容忍（模糊输入也硬答）训练出永远模糊的用户。输入设计是[[textbook-zero-to-agent/03_Prompt工程系统化|Prompt 工程教育]]的隐性课堂。

## 设计模式

**模式 1 · 结构化引导与自由输入并存**：高频、可预期的任务用结构化入口（模板、表单、参数化选项——把"怎么问"编码进界面）；开放任务保留自由文本，但配脚手架：占位符示例（展示一条好输入长什么样）、可选的引导追问（"要什么风格？给谁看？"）。**判据：任务的输入要素是否可枚举——可枚举就别让用户徒手写。**

**模式 2 · 分级澄清**：低风险+轻歧义→带假设地做（显式声明假设，一键纠正）；中歧义→做前给一句理解复述（"你是想要 X 对吧？"内联确认，不打断流）；高风险或高歧义→显式澄清问题，且一次问最关键的一个（连环追问是审讯不是澄清）。分级阈值与[[human-ai-collaboration-foundation/01_人机分工原则|可逆性]]挂钩：结果可逆时大胆假设，不可逆时必须澄清。

**模式 3 · 上下文面板**：以用户语言展示"本次对话我能看到的东西"——挂载的文件、启用的工具、引用的历史、生效的记忆——可查、可增删。发送前的上下文状态即"AI 的视野"，让用户在盲写前先对齐视野。

**模式 4 · 记忆的可见可控**：AI 记住的偏好/事实要有一个用户可见的清单，可编辑可删除（[[human-ai-collaboration-foundation/09_长期协作关系|协作记忆治理]]的界面实现，也是[[data-foundation-of-ai-systems/05_数据治理与伦理|删除权]]的落点）；记忆被写入时给轻量通知（"已记住你偏好简短回复"），写入不应是暗箱。

**模式 5 · 输入的改写建议**：对模糊输入，系统可以展示"我把你的问题理解/扩写为：……"——既是意图确认，也是一次现场 prompt 教学。用户看十次好的扩写，自己就学会第十一次。

## 工程手册：输入设计的落地细节

**"猜 vs 问"的成本账**（模式 2 的阈值怎么定）：猜错的成本 = 一轮浪费 + 用户重述 + 信任损耗；问的成本 = 一次打断 + 用户可能不耐烦。经验规则：**输出耗时越长、越不可逆，越该问**——十秒的回答猜错重来无所谓，十分钟的 Agent 任务方向猜错是重大浪费（[[laws-of-ai-engineering/02_计算与验证定律#Law 14 — 误差累积定律（Error Compounding Law）|Law 14]]），发送/支付类永远先确认。把这条规则写进 Agent 的行为规范（system prompt 层），而不是每次即兴。

**澄清问题的质量纪律**：一次一个问题；问区分度最大的那个（答案会改变做法的问题才值得问——[[decision-frameworks-guide/00_INDEX|似然比]]思维）；给选项优于开放问（"报告是给管理层还是工程团队？"好过"你想要什么风格？"）；用户已经说过的信息绝不再问（重复问 = 宣告"我没在听"，对信任的伤害远超一次澄清的收益）。

**上下文面板的三个状态要显式区分**：本次会带上的（当前上下文）/ 可以带但未带的（可挂载资源）/ 带不了的（能力边界——"我无法访问你的邮箱"）。第三类的显式化省掉大量"它怎么不知道 X"的失败交互。

**输入历史的资产化**：用户的高质量输入（产生了被采纳输出的那些）可以被系统提炼为个人模板（"把上次那种周报格式存为模板？"）——把一次性的好 prompt 变成可复用资产，这是输入侧的[[human-ai-collaboration-foundation/09_长期协作关系|判断日志]]镜像。

**新手/专家的双速设计**：同一入口，新手看到引导脚手架，专家一键折叠直达裸输入（并可用快捷语法/斜杠命令）。判断依据用行为不用自称：输入长度、结构化程度、改写采纳率——脚手架对专家是摩擦，对新手是扶手，静态一刀切两头得罪。

## 反例与边界

- **结构化不是越多越好**。把开放任务硬塞进表单，会砍掉用户本可以表达的关键上下文（表单没这一栏）——结构化服务"要素可枚举"的任务；要素不可枚举时，自由文本 + 好示例优于假结构。
- **澄清不能成为甩锅**。系统把本可从上下文推断的信息也拿来问（"你说的'这个文件'是指你刚上传的文件吗？"），是把理解成本推回用户——澄清的前提是**先穷尽已有上下文**，问的是真正缺的。
- **上下文可见性有认知上限**。把 200k token 的上下文全部罗列给用户不是透明是倾倒——面板展示的是**类别与来源**（哪些文件、哪段记忆），不是原文堆砌；细节按需展开（渐进披露，同[[01_交互设计的第一性|第一章三层]]）。
- **记忆通知的频率要克制**。每条小事都通知"已记住"，通知本身变噪音——重要类别（工作偏好、长期事实）通知，琐碎的进面板可查即可。

## 失败模式

- **空白框弃权**：唯一的输入设计是一个占位符写着"问我任何事"。
- **硬答文化**：无论输入多模糊都硬给答案，从不澄清——把猜错的成本全转给用户。
- **审讯式澄清**：连环追问五个问题才开始干活，用户体验为官僚主义。
- **重复问**：用户说过的信息被再次询问，宣告系统没在听。
- **视野黑箱**：用户不知道 AI 能看到什么，输入建立在错误假设上。
- **暗箱记忆**：系统悄悄记住并使用用户信息，被发现时体验为背叛（信任的不可逆损耗，[[laws-of-ai-engineering/08_可靠性与失败定律#Law 74 — 不可逆性定律（Irreversibility Law）|Law 74]] 在信任上的形态）。

## 评价方法

- 首次输入质量：新用户第一条输入的要素完整度（好的输入设计应该抬高这个值）。
- 澄清效率：澄清后的采纳率 vs 直接猜的采纳率；澄清被用户放弃（不回答）的比例。
- 重复问发生率：从对话日志抽样，统计"询问已提供信息"的频次——应趋零。
- 视野对齐度：用户测验"你觉得它现在能看到什么"，与实际上下文对照（心智模型审计的输入版）。
- 输入素养趋势：同一用户群的输入结构化程度随时间的变化（输入界面在教好还是教坏的直接证据）。

## 验收清单

- ☐ 高频可枚举任务有结构化入口吗？开放输入有示例脚手架吗？
- ☐ 猜/复述/澄清的分级规则写进行为规范了吗？与可逆性挂钩了吗？
- ☐ 澄清问题遵守"一次一个、给选项、不重复问"吗？
- ☐ 上下文面板存在吗？三个状态（带上/可带/带不了）区分了吗？
- ☐ 记忆可见可编辑可删除吗？写入有分级通知吗？
- ☐ 有输入改写/扩写的现场教学机制吗？
- ☐ 新手脚手架对专家可折叠吗？
- ☐ 重复问发生率在监控吗？

## 收束

输入设计把"怎么问"从用户的独自负担变成系统的共同责任：可枚举的结构化、开放的给脚手架、歧义按风险分级澄清（可逆大胆假设、不可逆必须问）、AI 的视野可见可控、记忆不进暗箱、每次交互顺手教一点提问素养。输入侧做好了，输出侧的一半问题不会发生。

最该记住的一句：**空白文本框不是自由，是设计弃权——它把能力发现、提问素养、上下文完整性三重负担一次性推给了最没有准备的人。**
