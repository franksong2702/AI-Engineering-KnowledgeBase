# 第 1 章 AI 认知启蒙：把 LLM 用成第二大脑

## 学习目标

- 用自己的话解释 LLM 是什么、为什么会"胡编"、什么任务可靠什么不可靠
- 每天用 AI 完成至少一件真实任务，并能判断输出质量
- 建立"AI 是概率系统而非数据库"的核心直觉

## 知识点

1. **LLM 的一句话工作方式**：从海量文本学习统计结构，再逐个 token 生成可能的续写。语言建模可以从压缩式预测理解，但参数直答不是带来源的知识查询——所以流畅不是正确性的充分证据。
2. **幻觉是生成系统需要治理的固有风险**：模型会在缺少足够证据时仍生成“像答案”的文本，但成因不只一种，不能全部归结为有损压缩。越冷门、越具体（人名、数字、引文、链接）的事实，越应要求可核查来源。
3. **能力地图**：强——改写、总结、翻译、头脑风暴、解释概念、写初稿；弱——精确事实、数学计算、最新信息、数长文本的字数。
4. **对话是无状态的**：模型没有记忆，"记忆"是每次把历史重发一遍。上下文窗口有限，太长的对话会"忘头"。
5. **温度与随机性**：同一问题两次答案不同是特性。重要任务问两遍，比较答案是免费的质检。
6. **主流产品版图**：对话产品（Claude、ChatGPT、Gemini）、API、开源模型三条线的区别与适用场景。

## 练习

1. 让 AI 分别写一封辞职信的三个版本（正式/温和/简短），观察指令措辞如何改变输出。
2. 故意诱导幻觉：问一个不存在的书名的内容简介，观察模型如何编造；再问"这本书存在吗"，比较差异。
3. 把一篇 3000 字文章分别要求压缩成 100 字、3 个要点、1 条推文，体会"格式约束"的威力。
4. 同一个数学题（如 3 位数乘法）问 5 次，统计正确率——建立"LLM 不是计算器"的体感。

## 项目

**七日 AI 工作流日记**：连续 7 天，每天用 AI 完成一件真实任务（写邮件、做计划、学概念、分析文档），记录：任务、你的指令、输出质量评分（1-5）、你做了什么修正。第 7 天写一页总结：AI 在你的生活里最强/最弱的三个场景。这份日记是你后续所有章节的"需求来源"。

## 阅读资料

- Andrej Karpathy《Intro to Large Language Models》（1 小时视频，B 站有搬运）——零基础最佳入口
- Ethan Mollick《Co-Intelligence》（中译《同频共智》）——非技术视角的使用哲学
- Anthropic 官方文档的 "Getting started" 部分——了解产品化 AI 的官方表述
- Stephen Wolfram《What Is ChatGPT Doing … and Why Does It Work?》（长文）——数学不多但深度足够

## 容易犯的错误

- **把 AI 当搜索引擎**：问事实性问题不要求来源、不核实。正确姿势：让它解释和推理，事实交给搜索或要求联网核查。
- **一次性提问**：问一句就接受答案。对话式 AI 的价值在追问和迭代，第一个回答只是草稿。
- **用礼貌浪费上下文**：大段寒暄和道歉不改善输出，清晰的任务描述才会。
- **被流畅度说服**：写得越像专家越要警惕，流畅是模型的默认属性而非质量信号。

## 推荐 Prompt

```
我想学习[概念X]。我的背景是[你的背景]，请：
1. 先用一个我熟悉领域的类比解释它
2. 然后给出准确定义
3. 指出这个类比在哪里失效（类比总会失效）
4. 出 3 道检验我是否真懂的问题，等我回答后再点评
```

这个 prompt 模板体现了本章核心技能：把 AI 从"答题机"变成"苏格拉底式私教"。

## 推荐 Agent

- **Claude / ChatGPT 对话产品本体**——本章不需要任何专门工具，先把对话用到极限
- **NotebookLM**：上传你的七日日记，让它生成回顾问答，体验"基于你自己资料的 AI"
- 若你用 Obsidian：从本章起建一个 `AI学习` 目录，所有练习产出直接入库——你在同时练习知识管理
## 自测题

1. **为什么参数直答不能当作事实来源？这个认知改变你的哪些使用习惯？**
   要点：模型生成续写而不是查询一条带来源记录；写得像答案不等于有证据。习惯上应做到：关键事实要求出处、核对来源是否支持断言、把流畅度与正确性分开评价。
2. **同一个数学题问 5 次得到 3 个不同答案，说明了模型的什么本质？工程上怎么利用这个特性？**
   要点：输出是概率抽样，方差是特性不是故障；利用法——重要任务问两遍对比是免费质检，答案不一致本身就是"低置信"信号。
3. **"对话是无状态的"——那你和 AI 的多轮对话是怎么实现的？这解释了什么现象？**
   要点：每次把完整历史重发一遍；解释了长对话"忘头"（超出窗口被截断）和长对话成本越来越高。
4. **列出模型的三强三弱，并说明为什么"数长文本字数"是弱项。**
   要点：强——改写/总结/翻译/头脑风暴/解释/初稿；弱——精确事实/数学/最新信息/数数；因为模型看到的是 token 不是字符，"数字数"超出它的感知粒度。
5. **第 1 章的核心直觉是"AI 是概率系统而非数据库"。用这句话解释：为什么把它当搜索引擎用很危险？**
   要点：搜索引擎返回"存在的文档"，模型生成"像答案的文本"——后者没有存在性保证；没有出处的答案默认按草稿对待，需要验证后才能当事实用。
