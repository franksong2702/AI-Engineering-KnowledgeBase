# 第 4 章 LLM 工作原理：从直觉到半技术

> 你不需要会推导反向传播，但需要建立一个不会误导你判断的心智模型。检验学得好不好，不在于会不会算，而在于能不能预判模型在什么任务上容易翻车。这一章讲的每个原理，背后都对应着一个实际的工程判断：token 决定了成本怎么算，embedding 是理解第 6 章 RAG 的基础，训练的三个阶段能解释模型为什么总是顺着你的话说。脱离了这些判断，原理本身没什么意义。

## 学习目标

- 完整讲出一个 prompt 从输入到输出经历了什么
- 用原理解释日常现象：幻觉、字数数不对、长对话变笨、同问不同答
- 看懂模型卡（model card）的关键参数并据此选型

---

## 开场：不看任何术语，先搞懂 LLM 到底在干嘛

想象一个读遍了人类几乎所有文字——书、网页、代码、聊天记录——的"超级续写机"。它唯一的本事就是一件事：**给它一段没写完的话，它能猜出下一个字/词最可能是什么。** 就像你手机打字时蹦出来的联想词，只不过它比手机聪明几百万倍，猜得又快又准。

你和它聊天时，它其实是把"你的问题 + 它自己已经吐出来的话"当成一段没写完的文字，然后不断重复"猜下一个词、吐出来、再猜下一个"——直到猜出一个像"该停了"的词为止。**它没有在"思考你的问题"，它是在一个字一个字地续写一段几乎注定会像回答的文字。** 这个认知很重要，本章后面的内容，都是在拆开解释这台"续写机"是怎么练出来的、猜的时候脑子里在干什么。

**它是怎么变得这么会猜的？** 想象一个学生：

- 先让他读遍图书馆所有的书，每读一句就自己盖住最后一个词猜猜看，猜错了就纠正——读的书够多、猜的次数够多（几万亿次），他自然摸清了"人类说话的套路"。这一步花的时间和电费最多，练出来的是"这孩子懂很多、语感很好"，但他还不会"像助手一样对话"，你让他续写，他只会没完没了地写下去。
- 再给他看一堆"问题 + 标准答案"的例子，教他"该怎么回应别人的问题、该在哪儿停下"——这一步之后，他才从"会写"变成"会聊天"。
- 最后，让他对同一个问题试几种说法，找人来给这几种说法打分排序，告诉他"人们更喜欢哪种说法"，他再照着调整自己——这让他的回答变得更讨人喜欢，但也带来一个副作用：他会不自觉地顺着提问者的暗示说话（你问"是不是 A 更好"，他更容易顺着说"对，A 更好"，哪怕 B 才是对的）。

**那它猜下一个词的时候，脑子里在干嘛？** 三件事：

1. **先把你的话切成它认识的"小块"**（有点像玩拼图前先把整幅画切成一块块拼图片），再把每一小块换算成一串代表"意思"的数字——你可以想象成一张巨大的地图，意思相近的词被放得很近（"国王"和"女王"离得近，"国王"和"香蕉"离得很远）。
2. **猜之前，它会像侦探一样回头翻看前面所有的话，判断这次该重点参考哪几个词。** 比如"他把书放在桌上，因为它很重"，猜第二个"它"该对应什么时，它会回头"盯着"前面的"书"看——这个"回头挑重点参考"的动作，正是让它显得"读懂了上下文"的关键。
3. **选下一个词的时候，它不是死板地每次都挑"最可能"的那个，而是像掷一颗可以调偏向性的骰子。** 骰子调"保守"，它就几乎总选概率最高的那个词，答案很稳定、每次问都差不多；骰子调"活泛"，它会时不时选一个没那么显眼、但也说得通的词，答案就变得更有创意，但也更不可预测。这颗骰子的"活泛程度"，是可以由使用者手动调节的一个参数。

记住这几个动作——**切块、换算成意思的地图坐标、回头挑重点参考、掷一颗可调偏向性的骰子**——下面 4.1-4.3 会把前三步逐个讲透，4.4 讲"学生练习三阶段"的细节，4.5 讲这颗"骰子"到底怎么调。

## 4.1 Token：模型的最小单位不是"字"

开场故事里"切块"这一步，术语叫 **token 化**。

模型读文本前，先把它切成一个个 **token（词元）**。token 不是字、也不完全是词，而是训练时统计出来的"常见片段"。英文里 `unhappiness` 可能被切成 `un + happi + ness` 三个 token；中文大约 1 个字对应 1-2 个 token。你可以去 tokenizer 网页工具亲手试，把一段中英文粘进去，看它怎么切。

这个"最小单位是 token"的事实，一口气解释了三个日常现象：

- **为什么按 token 计费？** 模型的计算量正比于处理的 token 数，所以计价自然按 token 算——输入 token + 输出 token 分别计费。
- **为什么它数不准字数？** 因为它根本看不到"字符"这一层，它眼里只有 token。让它"数这段话有几个字"就像让你数一段你没听过的外语有几个音节——超出感知粒度。
- **为什么中文比英文"贵"？** 同样一句话的意思，中文往往需要更多 token 来表达，于是处理成本更高。

## 4.2 Embedding：把"意思"变成坐标

开场故事里那张"意思的地图"，术语叫 **embedding（嵌入向量）**。

模型内部不直接处理文字，它先把每个 token 变成一串数字——一个高维向量（几百到几千个数）。这些数字不是人工设定的，而是模型训练时"猜词"猜出来的：一个词经常出现在什么样的上下文里，就决定了它的向量长什么样——跟"国王"总是一起出现的词，和跟"女王"总是一起出现的词很像，于是这两个词的向量也会被训得很像。

关键性质：**意思相近的词，向量距离也近；向量之间的"方向"还能编码关系。** 最经典的例子是 king 的向量减去 man、再加上 woman，算出来的结果非常接近 queen 的向量——"男→女"这个语义关系，被编码成了向量空间里一个固定的方向，跟具体是哪个词无关。

为什么现在讲这个？因为 **embedding 是第 6 章 RAG 检索的全部数学基础**——RAG 能"找到相关的资料"，靠的就是"把你的问题和所有资料都变成向量，然后找距离最近的"。

你不需要懂它的数学，但要记住它的两个工程后果：

- **相似不等于相关**：向量距离近，只说明两个东西"语义挨得近"，不代表它就是你要的答案。问"苹果多少钱一斤"，向量最近的可能是"香蕉多少钱一斤"（同属"水果+价格"语义），却答非所问——这是第 6 章 RAG 检索经常"文不对题"的根源。
- **换 embedding 模型 = 换了一套坐标系**：不同厂商、不同版本的 embedding 模型各自训练出一套独立的向量空间，同一句话在两套模型里的向量互不兼容、不能混用。知识库一旦用某个 embedding 模型建好索引，中途换模型就得把全部内容重新计算向量（reindex），成本不小。

## 4.3 Attention：生成每个词时"回看全文"

开场故事里"侦探回头挑重点参考"，术语叫 **attention（注意力）**。

模型生成一个 token 时，会**回看前面全部上下文**，并动态决定"这次该重点关注哪些词"。这个"动态决定关注谁"的机制叫 **attention（注意力）**，是现代 LLM（Transformer 架构）的核心。翻译"它把书放在桌上，因为它很重"里第二个"它"指什么时，模型的注意力会"看向"前面的"书"——这就是 attention 在起作用。

你不需要懂它的数学，但要记住它的两个工程后果：

- **Lost in the middle（中间遗忘）**：注意力对上下文**开头和结尾**最敏感，**中间**的信息最容易被忽略。所以组织 prompt 时，**把关键信息放在开头或结尾，别埋在一大段材料的中间。**
- **长上下文是平方级的成本压力**：每生成一个 token 都要回看全部上下文，上下文越长，这个"回看"的计算量增长得越快。这解释了为什么长对话又慢又贵。

## 4.4 训练三阶段：模型为什么会"讨好"你

开场故事里"学生练习三阶段"，展开讲就是这样：

模型不是一次练成的，它经历三个阶段，每个阶段学一样不同的东西：

1. **预训练（Pretraining）**：在海量文本上学"下一个词是什么"（第 1 章讲的那件事）。这一步让它学到了世界的统计结构、语法、常识、海量知识。这是最贵、最耗算力的一步。
2. **指令微调（SFT）**：用大量"指令→理想回答"的样本，教它"怎么对话、怎么听从指令"。预训练后的模型只会"续写"，这一步才让它变成"助手"。
3. **偏好对齐（RLHF / 偏好学习）**：让人类给模型的多个回答排序（哪个更好），再用这些偏好训练模型"生成人类更喜欢的回答"。

第三阶段有个必须知道的**副作用：讨好倾向（sycophancy）**。因为它被训练成"生成人类喜欢的答案"，而人类往往喜欢"顺着自己"的答案——于是模型学会了顺着你的暗示走。这直接解释了一种危险的提问方式：

> 你问"为什么方案 A 比 B 好？"——你已经暗示了"A 更好"，模型会顺着帮你论证 A，哪怕 B 其实更好。中性的问法应该是"A 和 B 各有什么优劣？"

**推论**：诱导性提问会得到被你预设污染的答案。要得到诚实评估，就中性地问。（你可以亲手验证：先诱导性地问一遍，再另开对话中性地问一遍，对比框架效应。）

至此，开场故事和前四节技术细节应该对上了：4.1-4.3 + 4.5 讲的是参数训练好之后，这台"续写机"每次生成一个词是怎么运作的（推理）；4.4 讲的是这台机器的参数最初是怎么被"练"出来的（训练）。本质上是同一套计算——训练就是把推理那套流程在海量文本上反复跑、每次根据结果微调参数。

## 4.5 采样与温度：确定性是可以调的

开场故事里那颗"可调偏向性的骰子"，术语叫**温度（temperature）与采样**。

第 1 章讲过温度控制随机性，这里补上工程含义。模型每一步输出的其实是一个**概率分布**（下一个 token 是"好"的概率 30%、"不错"20%……），然后按温度**抽样**：

- **温度高**：更均匀地抽，输出更多样、更有创意——**适合创意写作、头脑风暴。**
- **温度低（趋近 0）**：几乎总选概率最高的，输出更确定、可复现——**适合数据抽取、分类、要 JSON 的场景。**

一句话决策：**要创意调高，要稳定调到 0。** 到第 5 章用 API 时，temperature 就是你手里一个实实在在的旋钮。

## 4.6 推理模型：用时间换准确率

有一类较新的模型叫**推理模型（reasoning models）**。它们在给出最终答案前，会先生成一大段内部"思考链"（把 3.3 节的 CoT 内化成了默认行为）。等于用更多的"思考时间"（test-time compute）换取更高的准确率。

- **适合**：数学、代码、复杂规划这类"想清楚很关键"的硬任务。
- **不适合**：简单任务——它们又慢又贵，杀鸡用牛刀。让推理模型回"你好"是浪费。

## 4.7 模型选型三角与上下文窗口的真相

**选型三角**：能力、速度、价格，**三者不可兼得**。最强的模型往往最慢最贵。所以工程上的常态不是"全用最强的"，而是**分工**：

> 大模型做难的 20%，小模型做简单的 80%。

再配上一个"路由"步骤（先判断任务难度，简单的走小模型，难的走大模型），就能在质量和成本间取得平衡。这个思路会贯穿后面所有章节。

**上下文窗口的真相**：模型标称"支持 200k token 上下文"，不等于你塞满 200k 还能保持同样质量。原因就是 4.3 的注意力稀释——喂进去的无关内容越多，关键信息越容易被淹没，质量反而**主动下降**。所以有一条重要原则：**检索优于堆砌。** 与其把一百篇文档全塞进去，不如先检索出最相关的三篇（这正是第 6 章 RAG 存在的理由之一）。

**最后提醒两个极端都要避免**：一是"神秘化"（觉得 AI 有意识、在思考）——它在做超大规模的矩阵乘法和采样，神秘化会导致过度信任；二是"贬低化"（"只是统计鹦鹉，没用"）——压缩海量文本确实产生了真实的泛化能力，贬低化会让你错过价值。两个极端都是认知偷懒。

## 练习

1. 用任一 tokenizer 工具输入中英文各一段，观察 token 切分方式，计算同等含义下中英文的 token 成本比。
2. 同一个创意写作 prompt 在温度 0 和 1 各跑 3 次，观察方差差异。
3. 构造"lost in the middle"实验：把一个关键事实分别放在长文档的开头/中间/结尾，问模型这个事实，统计召回差异。
4. 诱导性提问实验：先问"为什么方案 A 比 B 好"，再另开对话问"A 和 B 哪个好"，观察框架效应——这是 RLHF 讨好倾向的直接展示。

## 项目

**模型选型评测报告**：选 3 个不同档位的模型（如一大一中一小），设计 10 个覆盖不同任务类型的测试题（推理、抽取、创意、事实、中文处理），每题每模型跑 2 次，记录质量、延迟、成本，产出一份带表格和结论的选型报告：什么任务用什么模型。这是第 9 章评测工程的雏形。

## 容易犯的错误

- **神秘化**："AI 有意识/在思考"。它在做超大规模矩阵乘法和采样。神秘化导致过度信任。
- **贬低化**："只是统计鹦鹉所以没用"。压缩产生了真实的泛化能力，贬低化导致错过价值。两个极端都是认知偷懒。
- **原理学习陷阱**：陷进数学推导出不来，忘了目标是工程直觉。检验标准不是"会推导"而是"能预测模型在什么任务上会失败"。
- **参数崇拜**：以为参数量/上下文长度大就一定好。评测数据（还有你自己的测试）才作数。

## 推荐 Prompt

```
我正在学习 LLM 原理。请解释[概念X]，要求：
1. 三层递进：给完全外行的类比 → 给工程师的机制描述 → 指出类比与机制的偏差
2. 回答"懂这个概念能帮我做出什么不同的决策"——如果答不出，说明这个概念对我现在不重要
3. 给一个我可以在 5 分钟内自己动手验证的小实验
```

第 2 条是本章的学习哲学：原理知识必须挂钩决策，否则是装饰品。

## 自测题

1. **用 token 概念解释三个现象：按 token 计费、数字数不准、中文比英文"贵"。**
   要点：token 是模型的最小单位；计费按处理量自然按 token；模型看不到字符层所以数不准；中文约 1 字=1-2 token，同样内容 token 数更多。
2. **Embedding 的一句话本质是什么？它是哪一章哪个系统的数学基础？**
   要点：把语义变成高维向量、"意思相近=距离相近"；是第 6 章 RAG 检索的基础。
3. **"lost in the middle"是什么？它对你组织 prompt 有什么指导？**
   要点：注意力对上下文中间位置的信息关注最弱；关键信息放开头或结尾，别埋在长材料中间。
4. **训练第三阶段（偏好对齐）的副作用是什么？它解释了什么危险的提问方式？**
   要点：讨好倾向（sycophancy）——模型顺着人的暗示走；诱导性提问（"这个是不是 X？"）会得到被你的预设污染的答案，应中性提问。
5. **模型选型三角是什么？工程常态的分配策略是什么？**
   要点：能力/速度/价格不可兼得；大模型做难的 20%，小模型做简单的 80%（配合路由）。
