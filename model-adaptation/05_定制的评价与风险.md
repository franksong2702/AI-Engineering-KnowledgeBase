# Part 5 定制的评价与风险：如何知道定制成功了，以及它的代价

> 定制模型不是训练完就结束——你必须知道它是否真的更好、以及它悄悄失去了什么。这一部分讲定制的评价和它独有的风险。它与 [[evaluation-of-ai-systems/00_INDEX|Evaluation]] 深度咬合：定制的成败最终由评价判定。

## 5.1 定制的评价：三个必答问题

微调/对齐之后，必须回答三个问题（否则你不知道定制是否成功）：

**其一，目标任务真的变好了吗？** 用独立的评测集（[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|测试集污染]]——不能用训练数据评）测目标任务的表现。这是定制的直接目的，必须量化验证提升，而非"感觉变好了"（[[ai-engineering-anti-patterns/00_INDEX|vibe check]]）。

**其二，它失去了什么？（灾难性遗忘）** 定制在目标任务上的提升，常以其他能力的退化为代价——见 5.2。必须评测定制前后的**通用能力**，确认没有严重退化。这是最常被忽略的一问。

**其三，它对齐得如何，还是学会了钻空子？** 尤其对齐后，要用[[evaluation-of-ai-systems/00_INDEX|独立评价]]检验是真对齐还是[[03_对齐与偏好|奖励黑客/谄媚]]——因为对齐优化的分数会撒谎（古德哈特）。

### 定制的标准评测协议（工程手册）

把三问落成一份可复用的协议——每次定制（含每次重训）都过同一套：

```
评测集三件套：
  A. 目标任务集      ── 独立采样，含长尾/边界例；对照组=基座+最优prompt
  B. 通用回归集      ── 冻结不变（跨版本可比），覆盖你业务实际依赖的通用能力
  C. 安全回归集      ── 拒答边界、注入抵抗、谄媚探针（对齐类定制必测）
判定门（发布前全过）：
  ① A 上显著优于对照组（不是优于旧版自己——是优于 prompt 基线）
  ② B 上回归幅度 ≤ 预设容忍度（见 5.2）
  ③ C 上无恶化
灰度：影子流量/小比例 A-B 上线，生产指标确认后放量
回滚：旧版本保持可一键切回（模型版本管理，见 5.3）
```

两个细节：**B 集要"覆盖你业务实际依赖的通用能力"而非通用大杂烩**——你的产品用不到的能力退化了无所谓，列出"我们实际依赖什么"本身就是有价值的练习。**判定门在训练之前就写死**——训完再定标准，标准就会向结果妥协（评价版的[[laws-of-ai-engineering/03_统计与泛化定律#Law 24 — 古德哈特定律（Goodhart's Law）|古德哈特]]）。

## 5.2 灾难性遗忘：定制的隐形代价

**灾难性遗忘**是定制最独特、最隐蔽的风险：模型在学习新任务时，忘掉了原有的能力。

为什么隐蔽：你盯着目标任务的提升（可见），却看不到通用能力的退化（不可见，除非专门测）。一个在目标窄任务上微调得很好的模型，可能在其他任务上悄悄变差了——这是[[laws-of-ai-engineering/08_可靠性与失败定律#Law 76 — 静默降级危险定律（Silent-Degradation-Danger Law）|静默降级]]在训练层的形态。

缓解：
- **PEFT/LoRA**（[[02_微调技术|冻结原权重]]）大幅缓解遗忘——这是它相比全参微调的一大优势。
- **混入通用数据**——微调数据里保留一部分通用任务，防止过度专门化。
- **控制训练强度**——学习率/轮数适度，改动太大遗忘越重。
- **评测通用能力**——定制前后都测通用基准，量化遗忘程度。

**核心纪律**：**永远评测定制"失去了什么"，而不只是"得到了什么"。** 只看目标任务提升的定制评价，是被峰值误导（[[ai-engineering-anti-patterns/00_INDEX|峰值驱动设计]]反模式的训练版）。

**容忍度怎么设**：遗忘不是零容忍——纯窄任务专用模型（只走专线流量、不接开放输入）可以接受较大的通用回归；面向开放输入的模型容忍度要严得多。原则是**按"退化的能力会不会被真实流量踩到"定容忍度**，并把数字写进 5.1 的判定门。不写数字的"注意遗忘"等于没说。

## 5.3 定制的其他风险

**过拟合**——数据少时模型记住训练数据而非学会泛化（[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|过拟合定律]]）。用验证集监控，验证集表现停止提升甚至下降就是过拟合信号。

**数据偏见固化**——微调数据的偏见被直接学入权重，且比 prompt 层的偏见更难修正（要重训）。这让 [[data-foundation-of-ai-systems/00_INDEX|数据质量]]在微调场景加倍重要。

**分布漂移下的退化**——定制模型是对某个数据分布的适配，当真实分布[[laws-of-ai-engineering/00_INDEX|漂移]]，定制模型可能比通用模型退化更快（它更专门化，更脆）。**含义：定制模型的漂移监控（[[data-foundation-of-ai-systems/04_数据评价与漂移|Data Foundation Part 4]]）要比通用模型更勤，且要预设"漂移超限→触发重训评估"的流程，而非等投诉。**

**维护负担**——定制模型需要随数据漂移、需求变化而重新定制，这是持续的负担（不是一次性的），且每个定制模型都是要维护的资产（[[laws-of-ai-engineering/04_系统与控制定律#Law 41 — 复杂度累积定律（Complexity-Accumulation Law）|复杂度累积]]）。

**版本管理**——定制产生了新的模型版本，需要[[laws-of-ai-engineering/00_INDEX|版本管理和回滚]]（哪个数据、哪次训练、什么表现），否则无法归因和回退。**模型版本的 manifest 至少含：基座版本、数据版本（连到 [[data-foundation-of-ai-systems/02_数据管线|数据 manifest]]）、训练配置、三件套评测分数、发布/回滚状态。模型-数据-评测三者版本互链，出问题才能归因。**

## 5.4 定制的成本-收益复盘

定制不是免费的（[[laws-of-ai-engineering/06_经济与资源定律#Law 54 — 质量有成本定律（Quality-Costs Law）|质量有成本]]、[[decision-frameworks-guide/00_INDEX|机会成本]]）。完整的成本包括：数据准备、训练算力、评测、部署、以及最容易被低估的**持续维护**。

复盘要诚实回答：定制带来的收益（目标任务的提升 × 价值），是否超过了它的全部成本（含维护）？很多定制项目在短期看划算，算上长期维护负担后其实不如用 API + 好的 prompt/RAG。这是[[decision-frameworks-guide/00_INDEX|沉没成本]]的陷阱——已经投入训练了，就倾向继续维护，而非诚实评估"现在从头看还值得吗"。

**复盘的固定节拍**：给每个定制模型设一个"重新立项日"（比如每半年，或每次基座大版本更新时）——在那天用当时最新的基座 + prompt/RAG 重跑一次对照。**对照赢了就退役定制模型。** 把退役设为默认预期而非失败：在模型能力快速上升期，定制模型的正常宿命就是被更强的基座免费取代（[[01_优化阶梯|换代税]]的另一面）。抗拒退役才是沉没成本谬误。

## 5.5 验收清单：怎么判断定制的评价做对了

- ☐ 三件套评测集（目标/通用回归/安全回归）齐吗？B 集冻结了吗？
- ☐ 判定门（含遗忘容忍度数字）是训练**之前**写死的吗？
- ☐ 对照组是"基座+最优 prompt"而非旧版自己吗？
- ☐ 上线走了影子流量/灰度吗？回滚演练过吗？
- ☐ 模型 manifest 与数据 manifest、评测分数互链了吗？
- ☐ 漂移监控对这个定制模型比通用模型更勤吗？触发重训评估的阈值定了吗？
- ☐ "重新立项日"在日历上吗？上次对照的结果是什么？

## Part 5 收束

定制的评价必答三问：目标任务真变好了吗（独立评测、对照 prompt 基线）、失去了什么（灾难性遗忘，容忍度写成数字）、是真对齐还是钻空子（独立检验）。灾难性遗忘是最隐蔽的代价——只看得到的提升、看不到的退化，是[[laws-of-ai-engineering/08_可靠性与失败定律#Law 76 — 静默降级危险定律（Silent-Degradation-Danger Law）|静默降级]]的训练版。定制还有过拟合、偏见固化、维护负担等持续成本——所以要有标准评测协议、版本互链、和固定节拍的"重新立项"复盘，并把退役当作定制模型的正常宿命。

**最该记住的一句**：**永远评测定制失去了什么，而不只是得到了什么——只看目标任务提升的定制，是被峰值误导。**

## 全书收束：定制是最后手段，不是高级感

《Model Adaptation》补齐了知识库的第二大缺失。五个 Part 的主线是一条克制的原则：**模型定制是优化阶梯的最后手段，先穷尽 prompt/RAG/工具；确实要定制时，用最简单够用的技术（LoRA/DPO），且成败首先取决于数据质量；对齐逃不过古德哈特；评价定制必须看它失去了什么。**

它与知识库深度咬合：前置 [[data-foundation-of-ai-systems/00_INDEX|Data Foundation]]（数据是训练地基）、上承 [[01_优化阶梯|优化阶梯]]（prompt/RAG 之上一级）、受 [[evaluation-of-ai-systems/00_INDEX|Evaluation]] 判定（含古德哈特这个共同敌人）、呼应 [[laws-of-ai-engineering/00_INDEX|Laws]]（阶梯、古德哈特、质量>数量、峰值陷阱）。

**最该记住的一句**：**当模型能力与 API 获取已经充分降本时，“能定制模型”可能不再是瓶颈，“判断该不该定制、以及诚实评价定制的真实代价”反而更稀缺。** 这对应 [[foundation-of-ai-engineering/00_INDEX|条件性的稀缺性转移]]；如果数据、算力或领域知识仍是瓶颈，就应按实际约束重新排序。
