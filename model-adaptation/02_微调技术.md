# Part 2 微调技术：确实该微调时，用什么

> 通过了 [[01_优化阶梯|Part 1]] 的守门（确认该微调、有好数据），这一部分讲技术选择。刻意讲原理和取舍而非具体代码——因为具体 API 会变（[[foundation-of-ai-engineering/00_INDEX|知识半衰期]]），而"什么时候用哪种"的判断保值。

## 2.1 微调技术地图

```
全参微调（Full Fine-tuning）  ── 改所有权重，效果上限高，成本最高
    │
参数高效微调（PEFT）           ── 只改少量参数，成本低，主流选择
    ├─ LoRA                    ── 低秩适配，加小矩阵，最常用
    └─ QLoRA                   ── 量化 + LoRA，单卡可跑大模型
    │
指令微调（SFT）                ── 用"指令-回答"对，教对话/任务行为
    │
偏好优化（RLHF/DPO）           ── 用偏好数据对齐（见 Part 3）
```

## 2.2 全参微调 vs 参数高效微调（PEFT）

**全参微调**改动模型的所有权重。效果上限最高，但成本最高（需要大量算力和显存）、容易[[05_定制的评价与风险|灾难性遗忘]]（改动太大，忘掉原有能力）、每个任务一份完整模型副本（存储贵）。

**参数高效微调（PEFT）**只改少量新增参数，冻结原模型。**LoRA**（低秩适配）是主流——它假设微调的改动是低秩的，于是只训练两个小矩阵，加到原权重上。**QLoRA** 进一步把原模型量化（压缩），使得单张消费级显卡就能微调大模型。

**判断**：绝大多数场景用 PEFT/LoRA——它便宜、快、显存友好、不易灾难性遗忘、一个基座可挂多个 LoRA 适配器（[[laws-of-ai-engineering/11_演化与元定律#Law 99 — 简单性存活定律（Simplicity-Survives Law）|简单性存活]]、[[laws-of-ai-engineering/06_经济与资源定律#Law 56 — 成本结构决定架构定律（Cost-Structure-Shapes-Architecture Law）|成本结构决定架构]]）。只有当 LoRA 效果确实不够、且有充足算力时，才考虑全参微调。这又是一个[[01_优化阶梯|阶梯]]——先试便宜的 PEFT。

### "LoRA 不够"的信号（何时升级全参）

升级要有证据，不是感觉：

- **容量信号**：训练损失早早进入平台且验证表现不达标，提高 LoRA 秩（rank）后确有改善但仍不够——说明改动可能不是低秩的（任务离基座行为太远）。
- **先试的便宜手段**：升秩（小步倍增）、扩大 LoRA 挂载的层范围、检查数据（**多数"LoRA 不够"其实是数据不够好**——先回 [[data-foundation-of-ai-systems/00_INDEX|Data Foundation]] 而不是先上全参）。
- **仍不够再全参**：并接受它的全部代价——算力、每任务一份权重、更高的遗忘风险（[[05_定制的评价与风险|Part 5]] 的通用能力回归测试从"建议"升为"必须"）。

## 2.3 指令微调（SFT）

**监督微调（SFT）**用"指令→期望回答"的配对数据，教模型如何遵循指令、如何以特定方式回答。它是让基座模型变成能对话、能执行任务的助手的关键一步。

SFT 的核心是数据（再次呼应 [[data-foundation-of-ai-systems/00_INDEX|数据质量]]）：指令的多样性、回答的质量、覆盖的任务范围，直接决定微调后的行为。**几千条高质量、多样的指令数据，常胜过几十万条重复单调的**（质量>数量）。

### SFT 数据的构建纪律（工程手册）

- **数据量的量级感**（经验值，非阈值）：固定格式/风格类任务，数百到数千条精选样本常已见效；行为覆盖面越广需要越多。先小规模跑通闭环、看边际收益，再决定扩数据——不要先囤十万条。
- **回答质量重于指令数量**：每条回答都应是"你希望模型每次都这么答"的示范。混入平庸回答 = 教模型平庸。宁可少而精。
- **多样性有意设计**：同一意图的不同表述、不同长度输入、边界情况、**该拒绝的输入**（教会说"不"也是行为）。全是顺境样本训出的模型，遇到逆境就即兴发挥。
- **和评测集的隔离**：SFT 数据与评测集按[[data-foundation-of-ai-systems/01_数据质量|组切分 + 近重复检测]]隔离——微调场景的测试集污染尤其容易发生，因为两者常出自同一批人之手。
- **格式一致性**：对话模板、系统提示、特殊标记在训练与推理时必须逐字符一致——模板不一致是微调后"表现莫名变差"最常见的低级原因，先查它再怀疑别的。

## 2.4 微调的关键取舍

**学习率与训练轮数**——太大/太多会[[05_定制的评价与风险|灾难性遗忘]]和过拟合（模型死记训练数据，失去泛化）；太小/太少则学不到。这是[[laws-of-ai-engineering/00_INDEX|偏差-方差权衡]]在训练中的形态。

**数据量与过拟合**——数据少时容易[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|过拟合]]，模型记住而非学会。需要留验证集监控（[[evaluation-of-ai-systems/00_INDEX|Evaluation]]、[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|测试集污染]]）。

**基座模型选择**——从多强的基座开始微调，影响效果上限和成本。通常从"接近够用"的基座微调，而非从最弱或最强的。

**灾难性遗忘**——微调新任务时忘掉原有能力。PEFT 缓解此问题（冻结原权重），全参微调需小心（见 [[05_定制的评价与风险|Part 5]]）。

### 训练过程盯什么（工程手册）

一次规范的微调，训练期间至少看三条曲线、跑一个对照：

1. **训练损失**——只证明"在学"，不证明"学对"。它是最不重要的一条。
2. **验证损失/验证任务分**——真正的信号。验证分停滞或回落即停（早停），继续训只会过拟合。
3. **通用能力抽测**——每隔若干检查点，在一小撮通用任务上快测，及早发现遗忘（不要等训完才发现，[[05_定制的评价与风险|Part 5]]）。
4. **基线对照**——微调模型 vs "基座+最优 prompt"在同一评测集上对比。**微调的成绩单永远是相对这个基线的增量**，不是绝对分——赢不了自己的 prompt 基线的微调，应该下线。

超参的入手姿势：从该方法的社区常用默认值起步，先跑通小数据闭环验证管线正确，再在数据量和轮数上做梯度实验。**微调工程的多数时间应该花在数据和评测上，而不是超参搜索上**——超参带来的方差通常小于数据质量带来的方差。

## 2.5 微调的反模式（对照 Anti-Patterns 精神）

- **微调当银弹**——prompt/RAG 没穷尽就微调（[[01_优化阶梯|违反优化阶梯]]）。
- **脏数据微调**——用低质量数据微调，把问题固化进权重（[[data-foundation-of-ai-systems/00_INDEX|违反质量>数量]]）。
- **无验证集**——不留验证集，过拟合了还以为成功（[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|过拟合]]、[[laws-of-ai-engineering/03_统计与泛化定律#Law 30 — 过拟合定律（Overfitting Law）|测试集污染]]）。
- **过度训练**——训太多轮，灾难性遗忘 + 过拟合。
- **全参微调滥用**——LoRA 够用却上全参，成本翻倍无收益。
- **模板不一致**——训练与推理的对话模板/特殊标记不一致，表现莫名劣化（最常见的低级错误，见 2.3）。
- **无 prompt 基线对照**——不和"基座+最优 prompt"比，微调的提升无从谈起。

## 2.6 验收清单：怎么判断这次微调做对了

- ☐ 有"基座+最优 prompt"的基线分数吗？微调赢它多少？
- ☐ 验证集独立且做过近重复检测吗？
- ☐ 训练用了早停吗？停在什么信号上？
- ☐ 通用能力抽测跑了吗？遗忘幅度在容忍范围内吗？
- ☐ 训练与推理的模板逐字符一致吗（专门检查过）？
- ☐ 如果用了全参：升级证据（升秩实验记录）存在吗？
- ☐ 训练配置（数据版本、基座版本、超参）写进 manifest 了吗（[[data-foundation-of-ai-systems/02_数据管线|可复现]]）？

## Part 2 收束

微调技术的主线：绝大多数场景用 PEFT/LoRA（便宜、快、不易遗忘），全参微调是少数需要极致效果的例外——且升级要有升秩实验的证据。SFT 用指令数据教行为，核心仍是数据质量（少而精、多样、含拒答、与评测隔离）。关键取舍是学习率/轮数/数据量之间的偏差-方差平衡，主要风险是过拟合和灾难性遗忘；训练过程盯验证分和通用抽测，成绩单永远相对 prompt 基线。

**最该记住的一句**：**先试 LoRA（阶梯思维贯穿到底），且微调的成败首先是数据质量，不是算法选择。**
