# Part 1 优化阶梯：什么时候才该定制模型

> 这一部分是整本书的守门人。它的核心信息反直觉：**大多数想微调的场景，其实不该微调。** 在教你怎么定制之前，先教你何时不该定制。

## 1.1 优化阶梯：成本递增，先穷尽上一级

改善一个 AI 系统的表现，有一个成本递增的阶梯。**纪律是：先穷尽便宜的一级，被证据推着才上下一级**（[[llm-design-patterns/00_INDEX|LLM Design Patterns 原则 1]]）。

```
① 提示工程（prompt）      ── 最便宜，改一句话，即时
② Few-shot 示例           ── 便宜，加几个例子教它
③ RAG / 工具              ── 中等，注入知识和能力
④ 微调（fine-tuning）     ── 贵，改动模型权重
⑤ 继续预训练 / 从头训练   ── 最贵，极少数场景
   ↓ 成本、复杂度、维护负担递增
```

**为什么必须按阶梯来**：每一级的成本、复杂度、维护负担都比上一级高一个数量级。跳过便宜的直接上贵的，是[[ai-engineering-anti-patterns/00_INDEX|过度工程]]——你付出了微调的全部代价，可能一个更好的 prompt 就解决了。

### "穷尽"的判据：每一级何时算试完了

"先穷尽上一级"如果没有判据，会退化为两个极端——要么"随便试了个 prompt 不行就微调"（假穷尽），要么"永远还能再调调 prompt"（无限滞留）。每级的停留判据：

- **① prompt 算穷尽**：在同一个评测集上，至少尝试过明确指令化（把隐性期待写成显式规则）、结构化输出约束、拆步骤这三类改法，分数不再提升。**没有评测集就谈不上穷尽**——你连"有没有提升"都不知道（[[ai-engineering-anti-patterns/00_INDEX|vibe check]]）。
- **② few-shot 算穷尽**：示例试过 3→5→10 的数量梯度和不同的示例选择（含难例/边界例），提升进入平台期。若加示例反而变差，检查示例质量与一致性（示例也是数据，[[data-foundation-of-ai-systems/00_INDEX|质量>数量]]）。
- **③ RAG/工具 算穷尽**：确认失败案例不是知识缺口（错误在"不知道"之外——知道了材料还是做错），且检索质量本身已排查（[[ai-engineering-case-library/00_INDEX|80% 的 RAG 问题在检索，经验值]]）。
- **每级的证据要留档**：评测分数 + 失败案例分类。走到 ④ 时，这份档案就是"为什么微调"的立项依据——没有它，微调是拍脑袋。

### 反例与边界：允许"计划性跳级"的两种情况

阶梯是强默认，但有两种情况可以在**计划里**提前纳入下层（注意：是提前规划，不是跳过验证）：

1. **硬约束已知不可满足**：延迟预算或单价预算在数学上就排除了大模型+长 prompt 的方案（如超高频、毫秒级、单次成本要求极低的窄任务）。此时"prompt 调到完美"也没用，可以直接规划蒸馏/小模型路线——但仍要用大模型先把任务做对（它就是未来的教师模型），这本身就是在走阶梯。
2. **数据不出域的硬合规**：API 被合规排除时，自部署+定制成为前提而非选择（见 [[04_蒸馏与部署|Part 4]]）。此时阶梯依然适用，只是整体平移到自部署的模型上执行。

这两种都不是"跳级"，是**约束把某些级从选项里删掉了**。区别于"觉得微调高级"的假跳级：前者有硬约束证据，后者只有偏好。

## 1.2 微调擅长什么、不擅长什么（最关键的一节）

微调最大的误区是把它当能力提升的万能钥匙。真相是它有明确的适用边界：

**微调擅长**：
- **固定风格/语气/格式**——让输出稳定符合某种风格（品牌语气、特定格式）。
- **窄任务的稳定表现**——把一个明确的窄任务做得又快又稳。
- **让小模型达到大模型的特定任务表现**——蒸馏降本（[[04_蒸馏与部署|Part 4]]）。
- **领域术语和惯例**——密集的领域语言。

**微调不擅长（用错工具）**：
- **注入新知识**——想让模型"知道"新事实？[[llm-design-patterns/00_INDEX|RAG]] 更合适、更便宜、可更新、可溯源。微调注入知识是有损、不可溯源、更新要重训（[[laws-of-ai-engineering/01_信息与压缩定律#Law 5 — 检索优于记忆定律（Retrieval-Over-Memorization Law）|检索优于记忆定律]]）。
- **提升通用推理**——微调不会让模型变得"更聪明"，它只是把行为往你的数据的方向调。
- **修复能力缺陷**——模型根本不会的事，微调少量数据补不上。

**一句话判据**：**微调改的是"怎么表现"（风格/格式/行为），不是"知道什么"（知识）或"多聪明"（能力）。** 想改知识用 RAG，想改能力换模型，想改表现才微调。

**边界情况的裁决**："领域术语密集"横跨知识和表现——判别方法是做一个对照实验：把术语表/示例放进上下文（RAG/few-shot 路线）测一次。够用，说明它其实是知识问题；仍不行（模型有材料仍不会"说行话"、格式不稳），才是表现问题，归微调。**先做便宜的对照实验再裁决，本身就是阶梯纪律。**

## 1.3 微调的正当场景与错误期待

**正当场景**（值得走到这一级）：
- 稳定的窄任务需要固定风格/格式，而 prompt 反复调仍不够稳。
- 需要小模型达到大模型的特定任务表现以降本（高频窄任务的成本优化）。
- 领域术语极度密集，通用模型水土不服（先过 1.2 的对照实验）。
- 有大量高质量的任务数据可用（数据是前提，见 1.4）。

**错误期待**（该用别的）：
- "微调让模型知道我公司的知识"→ 用 RAG。
- "微调让模型推理更强"→ 做不到，换更强的模型或改任务分解。
- "微调修复模型的某个能力缺陷"→ 少量微调补不上根本缺陷。
- "微调显得高级"→ 这不是理由，是[[ai-engineering-anti-patterns/00_INDEX|过度工程]]的诱惑。

**还有一个常被忽略的隐性成本**：微调把你锁在一个基座版本上。基座模型更新换代时（通常一年数次），你的微调要重做、重评，而 prompt/RAG 方案几乎可以无缝迁移。**在模型能力快速提升的时期，这条"换代税"常常单独就足以否决一次微调**——今天花一个月微调出的提升，可能三个月后被新基座免费超越（[[foundation-of-ai-engineering/00_INDEX|知识半衰期]]在训练层的形态）。

## 1.4 数据质量是微调的前提

一个常被忽略的真相：**微调的成败，首先取决于数据质量，而非算法选择**（[[data-foundation-of-ai-systems/00_INDEX|Data Foundation]] 的核心在这里再次出现）。

- **质量 > 数量**——几百条高质量、一致、代表性好的样本，常胜过几万条脏数据。脏的微调数据会教模型学错（[[laws-of-ai-engineering/01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|信息守恒]]、[[data-foundation-of-ai-systems/03_标注与合成|系统性标签错误]]）。
- **数据决定行为**——微调后的模型行为是训练数据的镜子，数据的偏见、错误、风格会被直接学入。
- **没有好数据就别微调**——如果你没有高质量的任务数据，微调只会把坏数据的问题固化进权重。

所以在走到微调这一级之前，先问：**我有微调需要的高质量数据吗？** 没有的话，先回到 [[data-foundation-of-ai-systems/00_INDEX|数据工程]]。

## 1.5 可操作决策流程

面对"要不要定制模型"，按序问：

1. **prompt 调到位了吗？**——没有，先调 prompt（最便宜）。
2. **few-shot 试过了吗？**——难以描述的任务，先用示例教。
3. **问题是"不知道"吗？**——是知识缺口，用 RAG，不是微调。
4. **问题是"不会做/不够聪明"吗？**——是能力缺口，换模型或改分解，微调补不上。
5. **问题是"表现不稳定/风格不对"吗，且有高质量数据吗？**——**这才是微调的场景。**
6. **成本/维护负担值得吗？**——微调引入训练、部署、维护的持续负担（含 1.3 的换代税），确认收益超过它。

**走完这个流程，大多数"想微调"的场景会在第 1-4 步就被解决。** 这正是本书守门人角色的价值——防止你为了高级感付出微调的全部代价。

## 1.6 验收清单：怎么判断你守住了阶梯

- ☐ 有评测集吗？每一级的尝试都在同一个评测集上留了分数吗？
- ☐ "上一级已穷尽"的证据档案存在吗（改法清单 + 失败案例分类）？
- ☐ 失败案例做过"知识/能力/表现"三分类吗？各占多少？
- ☐ 领域术语类需求做过 RAG/few-shot 对照实验吗？
- ☐ 微调数据的质量报告有吗（[[data-foundation-of-ai-systems/01_数据质量|六维]]）？
- ☐ 算过换代税吗——基座更新时这次微调的重做成本是多少？
- ☐ 如果答案是"跳级"，跳级的硬约束证据（延迟/单价/合规）写下来了吗？

## Part 1 收束

优化阶梯：prompt → few-shot → RAG/工具 → 微调 → 训练，成本递增，先穷尽上一级——且"穷尽"有判据（同一评测集上证据留档），"跳级"只认硬约束。微调改的是表现（风格/格式/行为），不是知识（用 RAG）或能力（换模型）。数据质量是微调的前提，质量>数量>算法。

**最该记住的一句**：**大多数想微调的场景不该微调——它是最后手段，不是高级感的来源。** 走完决策流程，多数问题在更便宜的层就解决了。
