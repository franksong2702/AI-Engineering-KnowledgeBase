## Case 71 · 全量历史塞满上下文淹没关键信息

- **Problem**: 一个助手把用户过去所有对话全塞进上下文，被无关旧信息干扰，答不好当前简单问题。
- **Context**: 怕丢信息，全量倾倒。
- **Constraints**: 保持信噪比。
- **Analysis**: 记忆倾倒——多不等于好，无关信息稀释注意力。
- **Relevant Laws**: 信噪比 · 有效注意力有限
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（按需检索）
- **Architecture Decision**: 按相关性检索，只注入当前需要的记忆，而非全量倾倒。
- **Anti-Patterns Avoided**: [[agent-decision-system/03_ANTIPATTERN-DETECTORS#ANTI-08 · 记忆倾倒/上下文污染（Memory Dumping）— 🟠|ANTI-08]]（记忆倾倒）。
- **Evaluation Method**: 对比全量 vs 精炼上下文的质量。
- **Final Solution**: 检索式记忆，只注入相关的，质量回升。
- **Lessons Learned**: 检索优于倾倒。多不等于好。

## Case 72 · 关键信息埋在长上下文中段被忽略

- **Problem**: 把关键约束放在超长文档中段，模型经常视而不见。
- **Context**: 假设"窗口内=同等可用"。
- **Constraints**: 关键信息要被利用。
- **Analysis**: 有效注意力有限——lost in the middle，中段信息利用不足。
- **Relevant Laws**: 有效注意力有限
- **Relevant Patterns**: 关键信息放开头/结尾 + 检索重排
- **Architecture Decision**: 把关键约束放上下文开头或结尾；检索结果重排把最相关的放显著位置。
- **Anti-Patterns Avoided**: 假设窗口内同等可用。
- **Evaluation Method**: 把关键信息放头/中/尾分别测召回。
- **Final Solution**: 关键信息移到显著位置，召回恢复。
- **Lessons Learned**: 标称窗口≠有效可用。关键信息别埋中段。

## Case 73 · 长任务上下文腐烂决策变差（深度版）

- **Problem**: 一个长任务 Agent 的上下文积累了大量失败尝试、无关工具输出和过期假设，越到后面决策越差。
- **Context**: Agent 负责连续数小时完成调研、整理、生成和校对。系统把所有中间对话、工具结果、失败路径都塞回上下文，认为“信息越全越好”。
- **Constraints**: 长任务需要保持决策质量；不能丢关键约束；历史要可追溯，但工作上下文不能被噪声淹没。
- **Analysis**: 上下文是状态，不是垃圾桶。失败尝试、旧假设、长工具输出和已废弃计划会持续影响后续判断。坏状态会诱发坏行动，坏行动又产生更多坏状态，形成上下文腐烂的反馈环。
- **Relevant Laws**: [[agent-decision-system/04_LAW-INVARIANTS#LAW-07 · 上下文即状态（Context Is State）|LAW-07]]（上下文即状态） · [[agent-decision-system/04_LAW-INVARIANTS#LAW-02 · 压缩必然有损→会幻觉（Lossy Compression）|LAW-02]]（压缩有损） · [[agent-decision-system/04_LAW-INVARIANTS#LAW-06 · 误差多步累积 + 恢复优于预防（Error Compounding + Recovery）|LAW-06]]（错误沿长链累积）
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-11 · Context Compression（上下文压缩）|PAT-11]]（任务感知压缩） + [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（细节外置可检索）

**Trace 片段（腐烂前后）**：

```text
第 1 小时：
- 当前目标清楚：比较 A/B/C 三个方案
- 关键约束清楚：预算 < 10 万，必须本地部署
- 上下文 12k token，信噪比高

第 5 小时：
- 上下文 85k token
- 包含 14 次失败搜索、6 段无关网页、3 个已废弃假设
- 早期“必须本地部署”被埋在中段
- Agent 开始推荐一个云服务方案，并引用了已废弃假设
```

- **Architecture Decision**: 把“完整历史”和“工作状态”分离。完整历史外置保存；工作上下文只保留结构化状态摘要：当前目标、硬约束、已确认事实、待验证假设、已废弃路径、关键 artifact 指针。每个阶段结束时做任务感知压缩，并把长工具输出替换为可点击/可检索引用。
- **第一次修复与反转**: 第一版修复是“每 20 轮自动总结一次”，结果把具体预算、用户偏好、失败原因压成“讨论了部署限制”，后期需要时已经丢失。反转点是意识到通用摘要不是状态管理；真正需要的是带 schema 的状态账本，明确哪些字段不可丢、哪些噪声必须清理、哪些细节应外置。
- **Anti-Patterns Avoided**: [[agent-decision-system/03_ANTIPATTERN-DETECTORS#ANTI-08 · 记忆倾倒/上下文污染（Memory Dumping）— 🟠|ANTI-08]]（把所有历史都塞进上下文） · [[agent-decision-system/03_ANTIPATTERN-DETECTORS#ANTI-01 · 静默失败（Silent Failure）— 🔴最危险|ANTI-01]]（上下文腐烂后仍假装正常推进）
- **Evaluation Method**: [[agent-decision-system/05_EVAL-CHECKLIST#Q-08 · 对自主系统：轨迹合理吗，不只结果？🔴（仅自主系统）|Q-08]] + [[agent-decision-system/05_EVAL-CHECKLIST#Q-02 · 它可靠吗——看分布不是峰值？🔴|Q-02]]。用同一批长任务分别跑 1 小时、3 小时、6 小时，比较约束保持率、废弃假设复活率、最终决策质量。
- **Final Solution**: 引入阶段性状态账本 + 外置日志 + 可检索 artifact 指针。上下文不再无限增长，关键约束被显式保留，失败路径被归档而不是继续污染工作记忆。长任务后半段质量不再明显下滑。
- **Lessons Learned**: ① 上下文会腐烂，历史越多不等于状态越好。② 压缩一定有损，所以必须先定义什么不能丢。③ 完整历史用于审计，工作状态用于决策，两者不该混在一起。④ 数字为教学编排值，用于展示长任务退化，不代表实测数据。
## Case 74 · 假设模型"记得"导致失忆

- **Problem**: 一个多步 Agent 假设它记得第一步结果，不显式传递，到第五步已"忘记"，基于错误假设继续。
- **Context**: 被对话连续性错觉误导。
- **Constraints**: 状态要可靠保持。
- **Analysis**: 无状态假设陷阱——模型无状态，"记忆"要显式重注入。
- **Relevant Laws**: [[agent-decision-system/04_LAW-INVARIANTS#LAW-07 · 上下文即状态（Context Is State）|LAW-07]]（上下文即状态）
- **Relevant Patterns**: 显式状态管理
- **Architecture Decision**: 关键状态显式存文件，需要时重注入，不依赖模型"记得"。
- **Anti-Patterns Avoided**: 无状态假设陷阱。
- **Evaluation Method**: 检查是否有"依赖记得"但无显式存储的地方。
- **Final Solution**: 显式状态管理，长任务不再失忆。
- **Lessons Learned**: 模型无状态。"记忆"必须靠显式存储+重注入。

## Case 75 · 压缩丢掉了后续需要的细节（深度版）

- **Problem**: 一个长任务把前期具体参数压成“讨论了配置”，后期需要那个参数时已经丢失，Agent 只能猜。
- **Context**: 团队为了解决上下文过长，引入通用摘要器。摘要器追求“短”和“流畅”，没有任务 schema，也不知道哪些细节未来会成为硬约束。
- **Constraints**: 压缩要降成本，但不能丢关键约束、具体数值、用户偏好和外部承诺；细节丢了要能找回原文。
- **Analysis**: 压缩一定有损，问题是损在哪里。通用摘要倾向保留主题和结论，丢掉数值、例外、反对意见、临时约束这些“不像主旨”的信息；但工程任务后期最常需要的，往往正是这些细节。
- **Relevant Laws**: [[agent-decision-system/04_LAW-INVARIANTS#LAW-02 · 压缩必然有损→会幻觉（Lossy Compression）|LAW-02]]（压缩有损） · [[agent-decision-system/04_LAW-INVARIANTS#LAW-07 · 上下文即状态（Context Is State）|LAW-07]]（状态字段不能被散文化） · [[agent-decision-system/04_LAW-INVARIANTS#LAW-06 · 误差多步累积 + 恢复优于预防（Error Compounding + Recovery）|LAW-06]]（早期丢失会在后期放大）
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-11 · Context Compression（上下文压缩）|PAT-11]]（任务感知压缩） + [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（细节外置可检索）

**Trace 片段（错误摘要）**：

```text
原始对话：
用户：预算上限是 8 万；必须用本地部署；不要接触客户原始数据；
      如果必须用云服务，必须先找我确认。

通用摘要：
“用户讨论了预算、部署方式和数据安全要求，希望方案稳妥。”

第 4 小时：
Agent 需要选择部署方案，却看不到“8 万”“本地部署”“云服务需确认”三个硬约束，
于是推荐了一个 12 万/年的云服务方案。
```

- **Architecture Decision**: 摘要不再是一段自然语言，而是结构化状态：`hard_constraints`、`numbers`、`decisions`、`open_questions`、`discarded_options`、`source_refs`。自然语言摘要只作为阅读辅助，不能替代状态字段。所有被压缩掉的细节必须有原文引用或 artifact 指针。
- **第一次修复与反转**: 第一版修复是“把摘要 prompt 写成：请保留重要细节”。效果不稳定，因为“重要”取决于后续任务，模型无法预知。反转点是用 schema 定义重要性：数值、否定、例外、权限、不可逆承诺默认不可丢；其余内容才允许压缩。
- **Anti-Patterns Avoided**: [[agent-decision-system/03_ANTIPATTERN-DETECTORS#ANTI-08 · 记忆倾倒/上下文污染（Memory Dumping）— 🟠|ANTI-08]] 的反面误区：不是把所有东西都留在上下文，也不是把所有东西都散文化压掉；同时避免 [[agent-decision-system/03_ANTIPATTERN-DETECTORS#ANTI-01 · 静默失败（Silent Failure）— 🔴最危险|ANTI-01]]（摘要丢约束后仍继续执行）。
- **Evaluation Method**: [[agent-decision-system/05_EVAL-CHECKLIST#Q-08 · 对自主系统：轨迹合理吗，不只结果？🔴（仅自主系统）|Q-08]]。构造“前文有、摘要后没有”的细节追问，测关键字段保留率、原文可追溯率、后续决策违规率。
- **Final Solution**: 任务感知压缩 + 细节外置。工作上下文保留结构化状态和少量摘要；完整原文进入可检索存储。后续需要具体参数时，Agent 先查状态字段，再回源检索，而不是凭摘要猜。
- **Lessons Learned**: ① 压缩不是“写短”，而是决定什么可以损失。② 数值、否定、例外、权限、承诺默认不可丢。③ 摘要要服务后续决策，不是服务阅读美感。④ 示例为教学编排，用于展示压缩损失。
## Case 76 · 过时记忆导致错误推荐

- **Problem**: 系统记得"用户是素食者"，但用户早已改变，系统仍按旧记忆推荐。
- **Context**: 记忆无更新机制。
- **Constraints**: 记忆要反映当前。
- **Analysis**: 记忆即真理 + 无更新——过时记忆被无条件使用。
- **Relevant Laws**: 证据分级 · 分布漂移
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（记忆更新/遗忘）
- **Architecture Decision**: 记忆带时间戳；冲突时最新覆盖旧；定期核实关键记忆。
- **Anti-Patterns Avoided**: 记忆即真理。
- **Evaluation Method**: 测过时记忆的更新率。
- **Final Solution**: 更新机制，过时偏好被及时修正。
- **Lessons Learned**: 记忆会过时。需要更新和遗忘机制。

## Case 77 · 记忆检索召回相似但无关的条目

- **Problem**: 用户问"项目 A 的截止日期"，记忆检索召回大量关于"项目 A"的无关讨论，没找到那条日期。
- **Context**: 记忆检索只用语义相似度。
- **Constraints**: 检索要相关不只相似。
- **Analysis**: 错误记忆检索——语义相似≠相关。
- **Relevant Laws**: 语义邻近非相关
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（混合检索）
- **Architecture Decision**: 记忆检索用混合信号（语义+关键词+时间+重要性）。
- **Anti-Patterns Avoided**: 错误记忆检索。
- **Evaluation Method**: 测记忆检索的相关性（不只相似度）。
- **Final Solution**: 混合检索，精确记忆被命中。
- **Lessons Learned**: 记忆检索也是相似≠相关。用混合信号。

## Case 78 · 记忆平铺短期噪声干扰长期知识

- **Problem**: 一个系统把临时对话状态和长期用户档案存在一起，检索时互相干扰。
- **Context**: 记忆无分层。
- **Constraints**: 不同类型记忆要分管。
- **Analysis**: 记忆无分层——短期噪声和长期知识混杂。
- **Relevant Laws**: 关注点分离 · 信噪比
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-11 · Context Compression（上下文压缩）|PAT-11]] + [[agent-decision-system/02_PATTERN-CARDS#PAT-12 · Memory Retrieval（记忆机制）|PAT-12]]（分层记忆）
- **Architecture Decision**: 分层——短期（上下文）/中期（状态摘要）/长期（外部检索）+ 按类型分。
- **Anti-Patterns Avoided**: 记忆无分层。
- **Evaluation Method**: 测不同类型记忆的检索干扰。
- **Final Solution**: 分层记忆，各类型分管，干扰消除。
- **Lessons Learned**: 记忆要分层分类，不平铺。

## Case 79 · 无状态任务强加复杂记忆

- **Problem**: 一个纯粹的单次文本转换工具被加上完整记忆系统，徒增复杂度，从没用上。
- **Context**: 把记忆当默认好特性。
- **Constraints**: 简单任务要简单。
- **Analysis**: 强加记忆——无状态任务不需要记忆。
- **Relevant Laws**: [[agent-decision-system/04_LAW-INVARIANTS#LAW-10 · 简单优先（Simplicity First）|LAW-10]] · 机会成本
- **Relevant Patterns**: 记忆按需
- **Architecture Decision**: 无状态任务不加记忆；按需引入。
- **Anti-Patterns Avoided**: 强加记忆（过度设计）。
- **Evaluation Method**: 检查记忆是否被实际利用。
- **Final Solution**: 去掉不必要的记忆系统，简化。
- **Lessons Learned**: 记忆按需。无状态任务加记忆是过度设计。

## Case 80 · 子 Agent 独立上下文却假设它知道全局

- **Problem**: 主 Agent 派任务给子 Agent 时省略了背景，子 Agent 独立上下文看不到，跑偏。
- **Context**: 假设子 Agent 共享主 Agent 的上下文。
- **Constraints**: 子任务要自包含。
- **Analysis**: 上下文隔离被忽视——子 Agent 有独立上下文。
- **Relevant Laws**: [[agent-decision-system/04_LAW-INVARIANTS#LAW-07 · 上下文即状态（Context Is State）|LAW-07]]
- **Relevant Patterns**: [[agent-decision-system/02_PATTERN-CARDS#PAT-17 · Orchestrator-Workers（协调者-执行者）|PAT-17]]（自包含任务描述）
- **Architecture Decision**: 派给子 Agent 的任务描述包含全部必要背景。
- **Anti-Patterns Avoided**: 子任务不自包含。
- **Evaluation Method**: 检查任务能否被无上下文的 Agent 独立执行。
- **Final Solution**: 自包含任务，子 Agent 不再跑偏。
- **Lessons Learned**: 子 Agent 上下文隔离既是收益也是约束——任务必须自包含。
