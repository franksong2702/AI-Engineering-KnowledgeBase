# Part 5 成本工程：成本是架构属性，不是账单属性

> 很多 LLM 产品死于一道乘法：单次成本 × 规模。这一部分讲成本的结构解剖、单位经济学、按 ROI 排序的优化杠杆、和成本护栏。核心立场来自 [[laws-of-ai-engineering/06_经济与资源定律#Law 56 — 成本结构决定架构定律（Cost-Structure-Shapes-Architecture Law）|成本结构决定架构]]：成本要在设计期算，上线后才优化成本约等于重做架构。

## 5.1 成本的结构解剖

LLM 系统的成本不是"API 账单"一个数，是四块：

1. **Token 成本**，且**输入输出高度不对称**：多数系统输入 token 远多于输出（system prompt + few-shot + 检索材料 + 历史，换一句回答）——**上下文膨胀是第一大隐性成本源**，与延迟同根（[[02_Serving与延迟|token 既是钱也是时间]]）。先看自己的输入/输出比，再谈优化。
2. **调用倍增器**：单"任务"≠单调用。重试 ×、反思循环 ×、Self-Consistency ×N、多 Agent ×3-15（经验量级）、裁判抽检 ×——**架构里的每个质量模式都是成本乘数**（[[llm-design-patterns/00_INDEX|"每个模式都是拿 token 换质量"]]）。算任务成本要算乘完的数。
3. **隐形运营成本**：评测跑量（回归集 × pass@k × 发布频率，很容易超过小系统的生产流量本身）、trace 存储、在线裁判抽样、人工审核工时（[[human-ai-collaboration-foundation/05_避免盖章者陷阱|审批队列]]的人力）。
4. **固定成本**（自部署时）：见 [[model-adaptation/04_蒸馏与部署|TCO 清单]]，不重复。

## 5.2 单位经济学：从任务成本到业务成立

三步算清"这个产品在经济上成立吗"：

```
① 每任务真实成本 = (Σ 调用成本 × 倍增器) + 分摊的隐形成本
② 每任务价值   = 它替代/创造了什么（人工分钟数 × 时薪、转化增量、留存增量）
③ 成立判据     = 每任务成本 < 每任务价值 × 安全边际，且随规模不恶化
```

两个易错点：**用"演示时的成本"代入①**——生产的真实倍增器（重试、长输入、边角 case 的长循环）比演示高，要用生产 trace 的实测分布（P50 和 P95 的任务成本都要看，长尾任务可能贵一个数量级）；**忽略②的度量**——算不出价值就无法判断该在成本上投入多少，"越便宜越好"会把质量砍穿（见 5.4）。

## 5.3 优化杠杆：按 ROI 排序拉

顺序本身就是方法论——**先拉不伤质量的，后拉动质量的；每一级都比下一级便宜一个量级的工程投入**：

1. **砍无用（零风险）**：删上下文里"以防万一"塞的内容（[[laws-of-ai-engineering/01_信息与压缩定律#Law 3 — 信噪比定律（Signal-to-Noise Law）|信噪比]]——它们还在伤质量）；砍重复调用（同请求在流程里被算两次是常见 bug）；约束输出长度（schema/字数上限）。**多数系统第一次认真审计能砍两位数百分比**（经验量级）。
2. **缓存（低风险）**：精确/前缀/语义三层（[[02_Serving与延迟|Part 2]]），前缀缓存的上下文重排几乎是免费的钱。
3. **路由（中风险）**：简单流量下沉小模型——需要评测证明"简单流量"真的简单（路由错误率监控）。
4. **Prompt/流程精简（中风险）**：few-shot 从 8 个砍到 3 个、反思从 3 轮砍到 1 轮——每刀都要过评测门禁（[[04_发布与变更管理|Part 4]]），这是质量变更。
5. **蒸馏/量化/自部署（高投入）**：最后手段，见 [[model-adaptation/00_INDEX|Model Adaptation]]——它们是训练级投入，只有前四级拉完仍不成立时才值得。

**这个顺序是[[model-adaptation/01_优化阶梯|优化阶梯]]的成本版**：跳级（一上来就蒸馏）付出最大工程成本，可能砍无用一级就够了。

## 5.4 成本护栏与成本的古德哈特

**护栏（事故防线）**：
- **分级限额**：请求级（单次调用 token 上限、Agent 最大轮数——[[ai-engineering-anti-patterns/00_INDEX|循环无出口]]的成本形态）、用户级（防单用户滥用/被注入烧钱）、全局级（日预算熔断——宁可服务降级也不让账单失控）。
- **成本异常检测**：成本毛刺几乎总是信号——递归循环 bug、注入攻击（诱导长输出）、上游变更（模型悄悄变啰嗦）。**把"单任务成本分布"当 L3 级监控指标**（[[03_可观测性|Part 3]]），毛刺告警。
- **归因粒度**：成本要能按"功能 × 用户段 × 模型"切分——"这个月贵了 40%"如果不能在十分钟内定位到哪个功能，护栏就只是仪表。

**成本的古德哈特**（[[laws-of-ai-engineering/03_统计与泛化定律#Law 24 — 古德哈特定律（Goodhart's Law）|Law 24]] 在账单上的形态）：把"降本"设为 KPI，质量的损失是延迟且难测的（用户流失滞后于体验劣化），而成本的下降是即时可见的——**这正是反模式的标准温床**（可见的短期好处 × 不可见的长期代价）。纪律：每次成本优化都在评测门禁的看护下做，且"质量指标不变"写进优化的验收标准，不是事后解释。

## 5.5 反例与边界

- **省小钱伤大局**：关键路径上的贵模型（如出口审核、高风险判断）往往是全系统最值的钱——它兜住的事故成本远超模型差价。成本优化的对象是"量大且简单"的流量，不是"贵"的调用。
- **成本优化有截止点**：当每任务成本已远低于每任务价值，继续优化的工程时间是负 ROI（[[decision-frameworks-guide/00_INDEX|机会成本]]、[[laws-of-ai-engineering/06_经济与资源定律#Law 52 — 边际定律（Marginal Law）|边际]]）——去做能增长价值侧的事。
- **模型降价是外生红利也是陷阱**：行业价格持续下行，"等降价"有时胜过"做蒸馏"（三个月的蒸馏工程可能被一次降价抹平——[[model-adaptation/01_优化阶梯|换代税]]的价格版）。高投入的成本工程立项前，先问"这个优化在两次降价后还成立吗"。

## 5.6 验收清单

- ☐ 输入/输出 token 比测过吗？上下文里有多少是"以防万一"？
- ☐ 每任务真实成本（含倍增器、P95）来自生产 trace 实测吗？
- ☐ 每任务价值有估算吗？单位经济学的判据成立吗？
- ☐ 三级限额（请求/用户/全局）都在吗？全局熔断演练过吗？
- ☐ 成本毛刺有告警吗？能十分钟内归因到功能吗？
- ☐ 最近一次成本优化，评测门禁跑了吗？质量指标在验收标准里吗？
- ☐ 优化杠杆是按 1→5 的顺序拉的，还是直接跳到了蒸馏？

## Part 5 收束

成本 = token（输入居多）× 调用倍增器 + 隐形运营 + 固定成本；单位经济学用生产实测算，看 P50 也看 P95。优化杠杆按 ROI：砍无用 > 缓存 > 路由 > 精简 > 蒸馏——每一刀过评测门禁，防"降本 KPI"的古德哈特。护栏三级限额 + 毛刺告警 + 十分钟归因。

**最该记住的一句**：**很多产品不是死于模型不够好，是死于"单次成本 × 规模"这道乘法——而这道乘法在第一天就能算。**
