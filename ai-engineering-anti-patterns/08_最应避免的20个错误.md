# 总结 未来 AI Engineer 最应避免的 20 个错误

> 102 个反模式太多，记不住。如果只能带走一张清单，就是这 20 条——按"危害 × 普遍性 × 隐蔽性"排序。危害大（错了后果重）、普遍（几乎人人会犯）、隐蔽（表面合理、不易察觉）的排在最前。每条都指回它所属的反模式群和它违反的核心定律。

## 排序逻辑

不是随便挑 20 个，而是问三个问题给每个反模式打分：**它错了后果多严重？多少人会犯？犯了多久才会被发现？** 三者都高的最危险——因为它伤得重、伤得广、且伤了你还不知道。这个排序本身就是本书的一个隐性教益：**最该防的不是最明显的错，是最隐蔽的错。**

## 第一梯队：致命且隐蔽（Top 1–5）

**1. 静默失败（Silent Failure）——错误被掩盖，看起来成功。**
Agent 出错后编造成功结果继续、工具错误被吞掉、流程失败被静默跳过。这是全书最危险的错，因为它违背了[[01_评价的基础理论|"失败廉价可查"]]这个"好系统"的核心要件——错误不显性，就会传播、累积，到造成大损害才被发现。涵盖 [[01_Agent架构反模式|AP-12]]、[[02_多Agent反模式|AP-25]]、[[05_工具使用反模式|AP-64]]、[[06_工作流反模式|AP-78]]。违反 [[08_可靠性与失败定律#Law 71 — 显式失败定律（Fail-Loudly Law）|显式失败定律]]。**防它：让每个失败都显式、响亮、可查。**

**2. 过度信任（Over-Trust / 信任-可靠性剪刀差）。**
因为 AI"看起来强"而给它超过其实际可靠性的信任和权限，尤其在不可逆操作上。这是[[foundation-of-ai-engineering/00_INDEX|Foundation 预测的未来十年 AI 事故主源]]——信任涨得比可靠性快。涵盖 [[01_Agent架构反模式|AP-7 自主性错配]]、[[04_推理反模式|AP-53 过度自信输出]]、[[05_工具使用反模式|AP-67 危险工具无审批]]。违反 [[09_人机与信任定律#Law 84 — 信任-可靠性剪刀差定律（Trust-Reliability-Scissors Law）|信任-可靠性剪刀差定律]]、[[08_可靠性与失败定律#Law 74 — 不可逆性定律（Irreversibility Law）|不可逆性定律]]。**防它：信任跟随实测可靠性，不跟随感知能力；不可逆操作永远留人。**

**3. 古德哈特化的评价（Goodhart Evaluation）——优化代理而非真实目标。**
刷 benchmark、优化满意度、为分数优化、把评价当判断。评价错了比不评价更危险，因为它给虚假信心。涵盖整个[[07_评价反模式|评价反模式类]]。违反 [[03_统计与泛化定律#Law 24 — 古德哈特定律（Goodhart's Law）|古德哈特定律]]。**防它：永远问"我优化的是真实目标还是它的代理？这个代理还相关吗？"**

**4. 过度自动化（Over-Automation）——把该由人把关的自动了。**
不可逆、高风险、需价值判断的环节被全自动化，无人拦截。AI 会出错，而这些环节的错误代价高且[[09_人机与信任定律#Law 86 — 责任不可委托定律（Accountability-Cannot-Be-Delegated Law）|责任不可委托]]。涵盖 [[06_工作流反模式|AP-74]]、[[06_工作流反模式|AP-76]]。违反 [[09_人机与信任定律#Law 79 — 人在回路定律（Human-in-the-Loop Law）|人在回路定律]]。**防它：可逆的自动化，不可逆的留人。**

**5. 无评测就上线（Vibe-Check Deployment）。**
跑几个顺手的例子感觉不错就上线，无系统评测。无法发现[[03_统计与泛化定律#Law 31 — 长尾定律（Long-Tail Law）|长尾]]失败、无法比较版本、无法察觉退化。涵盖 [[07_评价反模式|AP-96]]、[[06_工作流反模式|AP-87]]。违反 [[08_可靠性与失败定律#Law 78 — 测试即真理定律（Untested-Is-Broken Law）|测试即真理定律]]。**防它：没有评测集的系统是薛定谔系统——你不知道它好不好。**

## 第二梯队：普遍且昂贵（Top 6–12）

**6. 过度 Agent 化（Over-Agentization）。**
把本可一次调用或工作流解决的任务做成自主 Agent，引入方差、成本、不可控。[[01_Agent架构反模式|AP-1]]。违反 [[02_计算与验证定律#Law 18 — 确定性优先定律（Determinism-First Law）|确定性优先定律]]。**防它：能用工作流不用 Agent。**

**7. 多 Agent 过度设计（Multi-Agent Overkill）。**
把"多"当"好"，不做基线对照，协调开销吞噬收益。[[02_多Agent反模式|AP-17、AP-23、AP-32]]。违反 [[06_经济与资源定律#Law 57 — 规模效应定律（Scale-Effects Law）|规模效应定律]]。**防它：对多 Agent 有罪推定，用单 Agent 基线证明"多"的价值。**

**8. 记忆倾倒与上下文污染（Memory Dumping / Context Pollution）。**
把信息量当信噪比，塞满上下文反而稀释关键信息。[[03_记忆反模式|AP-33、AP-34]]。违反 [[01_信息与压缩定律#Law 3 — 信噪比定律（Signal-to-Noise Law）|信噪比定律]]。**防它：检索优于倾倒，主动清理上下文。**

**9. 无目的反思（Reflection Without Purpose）。**
让 Agent 反思却无客观信号可依，反思沦为无锚的自我表演，甚至越改越错。[[04_推理反模式|AP-47]]。违反 [[04_自我评价|自我评价的外部锚原则]]。**防它：反思必须接客观信号（测试/事实/rubric），无锚不反思。**

**10. 工具返回值盲信（Tool Output Blind Trust）。**
把工具/检索返回的内容当可信数据，忽略它可能含注入指令。[[05_工具使用反模式|AP-65]]、[[03_记忆反模式|AP-38]]。违反 [[10_对抗与安全定律#Law 87 — 一切输入皆指令定律（All-Input-Is-Instruction Law）|一切输入皆指令定律]]。**防它：所有进入上下文的外部内容都当不可信。**

**11. 无失败恢复（No Failure Recovery）。**
流程一步失败就整体崩，无重试、无检查点、无降级。[[06_工作流反模式|AP-77]]、[[03_记忆反模式|AP-45]]。违反 [[08_可靠性与失败定律#Law 77 — 恢复优于预防定律（Recovery-Over-Prevention Law）|恢复优于预防定律]]。**防它：为失败而设计——幂等重试、检查点、优雅降级。**

**12. 黑箱系统（Black-Box / No Observability）。**
无 trace、无日志、无监控，出问题只能猜，无法评轨迹、无法察觉退化。[[01_Agent架构反模式|AP-13]]、[[06_工作流反模式|AP-79]]。违反 [[04_系统与控制定律#Law 36 — 可观测性定律（Observability Law）|可观测性定律]]。**防它：可观测性第一天就有。**

## 第三梯队：结构性且长期（Top 13–20）

**13. 复杂度蔓延（Complexity Creep）。**
Agent/工具/环节/流程只加不减，最终无人能理解。[[01_Agent架构反模式|AP-5]]、[[06_工作流反模式|AP-82]]。违反 [[04_系统与控制定律#Law 41 — 复杂度累积定律（Complexity-Accumulation Law）|复杂度累积定律]]。**防它：主动偿还复杂度，加之前先想减什么。**

**14. 权限过大（Excessive Permission）。**
给 Agent/工具超出任务所需的权限，扩大爆炸半径。[[05_工具使用反模式|AP-68]]。违反 [[05_接口与边界定律#Law 47 — 最小权限定律（Least-Privilege Law）|最小权限定律]]。**防它：按任务给权限，靠权限不靠自觉。**

**15. 循环无出口（Loop Without Exit）。**
自主循环无终止条件，死循环烧钱。[[01_Agent架构反模式|AP-11]]。违反 [[02_计算与验证定律#Law 21 — 停机与预算定律（Termination-Budget Law）|停机与预算定律]]。**防它：每个循环设最大轮数+预算+无进展即停。**

**16. 意图字面主义（Intent Literalism）。**
照字面执行指令，错过真实意图，歧义时猜而不问。[[01_Agent架构反模式|AP-15]]。违反 [[09_人机与信任定律#Law 83 — 意图-指令鸿沟定律（Intent-Instruction-Gap Law）|意图-指令鸿沟定律]]。**防它：服务真实目标，不确定就问。**

**17. 峰值驱动设计（Peak-Driven Design）。**
用"最好的一次"衡量能力和做承诺，忽略可靠性分布。[[01_Agent架构反模式|AP-10]]、[[07_评价反模式|AP-97]]。违反 [[laws-of-ai-engineering/11_演化与元定律#Law 95 — 能力-可靠性剪刀定律（Capability-Reliability-Scissors Law）|能力-可靠性剪刀定律]]。**防它：用分布而非峰值评价，为可靠性而非峰值设计。**

**18. 只评结果不评过程（Result-Only Evaluation）。**
对自主系统只看结果对不对，不看它是蒙对还是真会。[[07_评价反模式|AP-93]]。违反 [[evaluation-of-ai-systems/00_INDEX|评价必须分层]]。**防它：评轨迹，不只评结果。**

**19. 忽略成本结构（No Cost Accounting）。**
设计时不算成本，规模化后发现不可行。[[06_工作流反模式|AP-80]]、[[05_工具使用反模式|AP-63]]。违反 [[06_经济与资源定律#Law 56 — 成本结构决定架构定律（Cost-Structure-Shapes-Architecture Law）|成本结构决定架构定律]]。**防它：成本估算是设计阶段的事，不是上线后。**

**20. 忽略长期价值（Long-Term Value Blindness）。**
只优化即时表现和满意度，忽略对用户的长期影响，导向谄媚和有害依赖。[[07_评价反模式|AP-98、AP-99]]。违反 [[05_人类评价|长期价值原则]]。**防它：把"用户长期是否真的变好"作为终极标准，即使它最难测。**

## 20 条背后的 3 个元错误

如果连 20 条都太多，它们其实收敛到 3 个元错误——这是全书最该被记住的东西：

**元错误一：把可见的短期好处，换不可见的长期代价。**
过度 Agent 化（可见的"智能"换不可见的方差）、刷分（可见的分数换不可见的过拟合）、满意度优化（可见的满意换不可见的谄媚）、过度自动化（可见的省人力换不可见的失控）——几乎所有反模式都是这个交换。**解药：当一个选择的好处立即可见、代价延迟且隐蔽时，高度警惕。**

**元错误二：把代理当成目标本身。**
benchmark 分数、满意度、能力峰值、"看起来智能"——全是真实价值的代理，而把代理当目标必然被古德哈特反噬。**解药：永远追问"我盯着的这个东西，是我真正想要的，还是它的影子？"**

**元错误三：把复杂/自主/自动当成默认的好，而非需被证明的成本。**
过度 Agent 化、多 Agent 泛滥、过度自动化、能力堆砌——都源于把"更复杂/更自主/更自动"当美德。**解药：[[04_最值得记忆的设计原则|简单优先]]——复杂度、自主性、自动化都是成本，必须被收益证明；能减则减，能简则简，能留人则留人。**

## 收束：反面教材的正面价值

这本《AI Engineering Anti-Patterns》是《[[llm-design-patterns/00_INDEX|LLM Design Patterns]]》的镜像——那本教你该怎么做，这本教你别怎么做。但它的深层价值不在于列出 102 个坑，而在于训练一种[[foundation-of-ai-engineering/00_INDEX|Foundation 所说的"负空间"直觉]]：**成熟工程师和新手最大的区别，是知道什么不该做。**

正面知识容易传授、容易展示；反面知识通常只能靠踩坑获得，因为每个反模式在被采用的那一刻都显得合理。这本书试图把那些坑提前标出来——让你在掉进去之前，就认出那个"看起来是好主意"的东西其实是个陷阱。

如果你只记住一句话，记这句：**当一个设计让你感到"这样更智能/更自动/更全面/分数更高"的兴奋时，停下来，问问那个不可见的代价藏在哪里。** 兴奋是反模式最喜欢的伪装。

（本书是整套 AI_Lessons 体系的第九本，与《[[llm-design-patterns/00_INDEX|LLM Design Patterns]]》《[[laws-of-ai-engineering/00_INDEX|Laws]]》《[[evaluation-of-ai-systems/00_INDEX|Evaluation]]》互为一体：模式教你建，定律教你为什么，评价教你判断好坏，反模式教你避开陷阱。）
