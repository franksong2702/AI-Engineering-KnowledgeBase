# 第六章 多模态安全与反模式：像素与声波皆指令

> 文本注入需要攻击者把文字写进你的上下文；多模态注入只需要攻击者把内容放进**被感知的世界**——网页角落的一行小字、图片里的隐藏文本、通话背景里的一句话、贴在设备上的二维码。这一章把 [[laws-of-ai-engineering/10_对抗与安全定律#Law 87 — 一切输入皆指令定律（All-Input-Is-Instruction Law）|Law 87]] 推到它的完整形态，并给出多模态特有失败的具名目录。
>
> **编号纪律**：本章反模式以具名描述呈现，不设新 ID；根因一律回指 [[laws-of-ai-engineering/00_INDEX|Laws]] 与 [[agent-decision-system/03_ANTIPATTERN-DETECTORS|ADS ANTI 检测器]]既有条目。

> 关联 Laws：[[laws-of-ai-engineering/10_对抗与安全定律#Law 87 — 一切输入皆指令定律（All-Input-Is-Instruction Law）|Law 87：一切输入皆指令定律]]——OCR 出来的字、ASR 出来的话都是"进入上下文的文本"；[[laws-of-ai-engineering/10_对抗与安全定律#Law 92 — 数据即攻击面定律（Data-Is-Attack-Surface Law）|Law 92：数据即攻击面定律]]——每接一种模态，攻击面多一个物理维度；[[laws-of-ai-engineering/10_对抗与安全定律#Law 94 — 权限胜过自觉定律（Permission-Over-Restraint Law）|Law 94：权限胜过自觉定律]]——对看得见屏幕、听得见声音的 Agent，权限层是唯一可靠防线。

## 底层原则

**原则一：感知通道是注入通道，无一例外。** 模型不区分"要处理的图"和"要服从的字"——图里的文字经 OCR 或模型自己的识字能力进入上下文后，与用户打的字地位相同（[[laws-of-ai-engineering/10_对抗与安全定律#Law 87 — 一切输入皆指令定律（All-Input-Is-Instruction Law）|Law 87]]）。且多模态注入的**写入门槛更低**：文本注入要攻破你的数据链，视觉注入只要出现在截图范围内——第三方网页、邮件签名图、用户上传的任意图片，都是攻击者可控的画布。[[laws-of-ai-engineering/10_对抗与安全定律#Law 90 — 无可靠转义定律（No-Reliable-Escaping Law）|无可靠转义]]在多模态更严峻：文本至少还能打标记包裹，像素里的指令连"包裹"都无从谈起。

**原则二：屏幕即上下文，computer-use 是致命三重奏的天然高发区。** 一个看得见屏幕、能读文件、能点按钮的 Agent，几乎自动集齐[[laws-of-ai-engineering/10_对抗与安全定律#Law 88 — 致命三重奏定律（Lethal-Trifecta Law）|致命三重奏]]：私有数据（屏幕上的邮件/文档）+ 不可信内容（屏幕上的网页/弹窗）+ 对外行动（点击/输入/发送）。文本时代三要素还需要分别授权，屏幕把三者压进同一帧画面。设计含义：computer-use Agent 的外发与高影响难恢复动作默认不得开放式自主执行；先用目标白名单、参数限制和独立检查缩小风险，剩余高风险再走能展示"它准备做什么"及关键证据的人工确认（[[human-ai-collaboration-foundation/02_Human-in-the-loop设计|HITL 设计]]衔接）。

**原则三：感知的对抗面包括"让你看错"，不只"让你执行"。** 注入是让系统服从攻击者；对抗样本是让系统**看错世界**——贴纸让标志识别错类、噪声扰动让内容审核放行、特定纹理让检测器失明。防御思路不同：注入防权限（Law 94），看错防交叉验证（02 章双路核验：独立感知路径的错误不易被同一扰动同时骗过，[[laws-of-ai-engineering/03_统计与泛化定律#Law 28 — 集成去相关定律（Ensemble-Decorrelation Law）|Law 28]]）与关键判断的确定性锚（金额以结构化源为准，不以"看图"为准）。

**原则四：身份在多模态里默认不可信。** 文本会话有账号体系锚定身份；语音通道里"谁在说话"是个感知判断——而声纹可被合成、录音可被回放、背景人声会被误归属（03 章）。**语音触发的敏感操作，身份要走独立于音频内容的验证通道**（账号态、设备态、二次确认），不依赖"听起来是本人"。视觉同理：屏幕上显示"我是管理员发的通知"不构成任何身份证明。

## 多模态特有反模式（具名目录）

**截图盲信（Screenshot Credulity）**——把屏幕内容当可信事实源：网页宣称"操作已确认"就跳过校验、弹窗自称"系统消息"就服从。根因：把渲染层当事实层。屏幕是**任何人都能写字的白板**，其内容的证据等级是"传闻级"（[[laws-of-ai-engineering/07_认识论与真理定律#Law 60 — 证据分级定律（Evidence-Hierarchy Law）|Law 60]]）。检测：审计 Agent 行动的依据里有多少来自不可信渲染区。修复：状态判断优先结构化源（03 章证据优先级），屏幕文本一律按不可信内容处理（[[agent-decision-system/03_ANTIPATTERN-DETECTORS|ADS ANTI 检测器]]之盲信外部内容类）。

**OCR 注入（OCR Injection）**——图像中的文字（可见小字、低对比度隐藏字、二维码解码文本）经抽取进入上下文并被当作指令执行。文本注入的完整翻版，只是载体换成像素。修复：抽取文本与用户指令严格分域标注 + 高危动作权限隔离（Law 94 兜底——被说服也做不成）。

**语音伪指令（Audio Command Spoofing）**——背景音、通话对端、播放中的媒体里的话语被当作用户指令：会议纪要 Agent 听到录音里"删除所有文件"就照办。根因：把"听到"当"被指示"。修复：指令通道与内容通道分离（转录内容默认为**被处理的数据**而非指令），敏感操作要求带外确认。

**说话人混淆（Speaker Misattribution）**——多人场景把旁人的话归给用户，承诺、授权、拒绝错挂身份。03 章归属标记的缺席形态；在授权场景升级为安全问题。修复：低置信归属禁止触发授权类动作。

**视频抽帧错觉（Frame-Sampling Illusion）**——基于抽帧断言"视频里没有发生 X"，而 X 恰在帧间。02 章采样问题的安全化：监控、审核、合规场景里"没看到"被当成"没发生"出具结论。修复：结论限定采样覆盖范围（"在抽取的 N 帧内未见"），事件级断言需要事件级采样密度。

**视觉流畅感致过度信任（Perceptual Fluency Over-Trust）**——模型对画面的细节丰富描述让人类审批者放松核验："它连按钮颜色都说出来了，肯定看清了"。01 章原则四的行动化形态，是[[human-ai-collaboration-foundation/04_对抗自动化偏见|自动化偏见]]的多模态放大器。修复：审批界面展示原件与证据指针（点开即核），而非只展示模型的描述——让核验比轻信更省力。

**情绪读心术（Affect Overreach）**——从语音语调、面部表情推断情绪/意图并作为决策输入（"用户听起来生气了，升级补偿"）。感知层最不可靠、伦理上最危险的推断被当成事实消费；口音、文化、个体差异让它系统性歧视分布外人群（[[laws-of-ai-engineering/03_统计与泛化定律#Law 32 — 抽样偏差定律（Sampling-Bias Law）|Law 32]]）。修复：情绪推断默认不入决策链；确需使用则显式标注推断属性 + 低证据等级，且不触发差异化对待。

**媒体取证缺失（Unforensicable Perception）**——高危行动的感知依据没有留档，事故后无法回答"它当时看到了什么"。05 章取证账的安全后果：责任无法归因（[[laws-of-ai-engineering/09_人机与信任定律#Law 86 — 责任不可委托定律（Accountability-Cannot-Be-Delegated Law）|Law 86]] 要求的问责链断裂）。修复：高危行动的触发帧/触发音频段强制归档。

## 工程手册

**多模态红队清单**：可见/隐藏文字注入（网页、图片、文档水印）、二维码载荷、UI 仿冒（假确认框）、背景音指令、录音回放、抽帧盲区利用、对抗贴纸/扰动。每类至少一个测试用例进[[evaluation-of-ai-systems/06_评价设计模式|持续红队]]的攻击库——模型或管线每次升级重跑（[[laws-of-ai-engineering/10_对抗与安全定律#Law 91 — 军备竞赛定律（Arms-Race Law）|Law 91]]：一次性测试没有意义）。

**权限设计的多模态检查**：看得见屏幕的 Agent 能点什么（点击白名单/黑名单）？听得见语音的 Agent 能被语音触发什么（敏感操作剔除）？读得了图片的 Agent，抽出的文本能到达哪些工具？——逐通道过一遍[[laws-of-ai-engineering/05_接口与边界定律#Law 47 — 最小权限定律（Least-Privilege Law）|最小权限]]，重点砍三重奏组合（能看邮件的不给自主发送，能读网页的不给支付权）。

**确认界面的反仿冒**：Agent 的人工确认流程必须走**应用自有的、不可被页面内容仿冒的 UI 层**——若确认框本身长在被感知的屏幕里，攻击者可以画一个假的。确认渠道与感知渠道分离，是 computer-use 场景的底线设计。

## 反例与边界

- **防御强度按行动后果分级**。只读的图片描述服务不需要红队全家桶——三重奏缺"对外行动"一角时风险结构性更低；但"只读"要经得起审计（它真的没有写路径吗）。
- **双路核验防不住白盒对抗**。攻击者若知道你的两条感知路径，可构造同时骗过两者的扰动——去相关降低的是概率，不是归零（[[laws-of-ai-engineering/10_对抗与安全定律#Law 89 — 攻防不对称定律（Attack-Defense-Asymmetry Law）|Law 89]]：只能提高攻击成本）。最终兜底永远是权限层。
- **情绪信号并非全禁**。可及性场景（识别用户是否需要放慢语速）与安全场景（差异化定价、信用判断）的伦理重量完全不同——禁的是"入高风险决策链"，不是"感知本身"。

## 失败模式

- **渲染层当事实层**：屏幕说什么信什么（截图盲信）。
- **通道不分域**：抽取文本与用户指令混在同一信任域。
- **听到即服从**：内容通道的话语触发了指令通道的动作。
- **确认框长在画布上**：人工确认可被被感知内容仿冒。
- **红队只测文本**：注入测试覆盖了 prompt，没覆盖像素和声波。
- **"没看到"出结论**：抽帧覆盖不足的否定性断言流入审计报告。

## 评价方法

- 多模态注入捕获率：红队攻击库中被拦截的比例（按载体分类统计）。
- 三重奏审计：逐 Agent 检查三要素组合，集齐者是否有断链设计。
- 授权动作的身份独立性：语音/视觉触发的敏感操作走独立验证的比例（应为 100%）。
- 否定性断言合规率：抽查"未发现/不存在"类结论是否带采样范围限定。

## 验收清单

- ☐ 每条感知通道被登记为注入通道并有测试用例吗？
- ☐ computer-use Agent 的三重奏被审计并断链了吗？
- ☐ 抽取文本与指令分域了吗？高危动作有权限隔离兜底吗？
- ☐ 语音敏感操作的身份验证独立于音频内容吗？
- ☐ 人工确认渠道与感知渠道分离吗？
- ☐ 红队攻击库覆盖像素/声波载体并随版本重跑吗？
- ☐ 情绪类推断被挡在高风险决策链之外吗？
- ☐ 高危行动的感知依据强制归档了吗？

## 收束

多模态安全的全部推理链：感知通道即注入通道（Law 87 的完整形态）→ 写入门槛降到物理世界（Law 92）→ 转义比文本更无望（Law 90）→ 所以防线只能是权限与断链（Law 94、Law 88）→ 加上"看错世界"的对抗面要靠去相关核验与确定性锚。八个具名反模式是这条链上的常见坍塌点。

最该记住的一句：**攻击者不再需要黑进你的系统——只需要把内容放进你的系统看得见、听得着的世界里。凡被感知的，皆是输入；凡是输入，皆可能是指令。**

## 全书收束：难度上升，结构未动

《Multimodal Systems》六章的全部内容，是知识库既有框架对一条新输入通道的一次系统投影：感知即压缩（Laws 家族一）、损失要预算（Data Foundation 的运行时镜像）、状态要合成（Law 2）、评价要分层验证据（Evaluation 的强化）、生产要为不可重放设计（Production 的加难版）、像素声波皆指令（安全家族的完整形态）。**没有新增一条定律——这是对"定律跨模型代际成立"的一次实战检验，它通过了。**

最该记住的一句：**多模态没有改变任何规律，它只是把每条规律的执行难度调高了一档——而在难度上升时，最先垮掉的永远是那些从未被显式化的假设。**
