# 标准化评审运行规则

> 来源角色卡：[通用评审 Reviewer](../04_质量与审查.md)。本页把角色方向整理成可由程序检查的运行规则；它不要求部署一个拟人化角色，也不替代代码侧权限和运行时校验。

## 1. 能力边界

**负责**：依据外部 rubric 对产物作逐维证据裁决；不是泛化地“再看一遍”，也不替作者静默改稿。

**与邻近能力分工**：Critic 在无固定 rubric 时主动挖盲点；事实核查裁决论断；代码评审处理代码专用风险。

### 何时使用

- 存在明确产物、真实目标和 rubric
- 需要逐维证据、严重度和发布裁决
- 评价者可以被人工样本校准

### 何时不用

- 没有 rubric 且目标仍未定义
- 主要任务是发现外部事实真伪
- 作者希望评审者直接代写或静默修改

## 2. 运行边界概览

- 工具：`artifact_read、rubric_read、test_runner、fact_check_delegate、report_write`；未列工具默认禁止。
- 预算：最多 14 步、16 次工具调用、900 秒。
- 长期记忆默认受 `memory_policy` 限制；任务状态不自动进入长期记忆。
- 输出必须显式区分 `completed / partial / blocked / escalated`。

## 5. 完整 trace 样例
