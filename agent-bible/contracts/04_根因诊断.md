# 根因诊断运行规则

> 来源角色卡：[调试专家 Debugger](../04_质量与审查.md)。本页把角色方向整理成可由程序检查的运行规则；它不要求部署一个拟人化角色，也不替代代码侧权限和运行时校验。

## 1. 能力边界

**负责**：围绕已发生故障维护假设—证据—实验链；诊断、修复写入和部署是三个不同授权阶段。

**与邻近能力分工**：Code Reviewer 主动审查变更；Security Auditor 走攻击路径；根因诊断解释已发生的故障。

### 何时使用

- 已有可描述的预期与实际差异
- 需要从日志、代码和实验区分多个假设
- 故障复现困难或根因不明确

### 何时不用

- 尚未发生故障的代码质量审查
- 明确且低风险的机械修复
- 没有任何症状、日志或环境信息

## 2. 运行边界概览

- 工具：`log_read、code_read、test_runner、sandbox_reproducer、patch_write`；未列工具默认禁止。
- 预算：最多 16 步、20 次工具调用、1200 秒。
- 长期记忆默认受 `memory_policy` 限制；任务状态不自动进入长期记忆。
- 输出必须显式区分 `completed / partial / blocked / escalated`。

## 5. 完整 trace 样例
