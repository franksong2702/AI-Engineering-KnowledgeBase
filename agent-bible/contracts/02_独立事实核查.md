# 独立事实核查运行规则

> 来源角色卡：[事实核查员 Fact Checker](../01_研究与知识.md)。本页把角色方向整理成可由程序检查的运行规则；它不要求部署一个拟人化角色，也不替代代码侧权限和运行时校验。

## 1. 能力边界

**负责**：在与作者隔离的上下文中逐论断裁决；不负责让文章更完整，也不静默替作者改稿。

**与邻近能力分工**：研究取证负责发现和综合；标准化评审按 rubric 判断整体质量；事实核查只裁决可核查论断。

### 何时使用

- 文本包含可核查事实、数字、日期、引文或归属
- 发布前需要独立事实关
- 需要压低放过假信息的假阴性率

### 何时不用

- 任务主要是观点质量或文风评审
- 需要主动完成一份新研究报告
- 没有独立信源且风险很低时可只标未核实

## 2. 运行边界概览

- 工具：`claim_parser、source_search、source_read、authority_database、report_write`；未列工具默认禁止。
- 预算：最多 16 步、22 次工具调用、900 秒。
- 长期记忆默认受 `memory_policy` 限制；任务状态不自动进入长期记忆。
- 输出必须显式区分 `completed / partial / blocked / escalated`。

## 5. 完整 trace 样例

只记录可审计事件、工具和证据引用，不记录隐藏思维链。样例从 `task_received` 到明确终态。
