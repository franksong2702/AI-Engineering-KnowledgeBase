# M3《Multimodal Systems》立项审计

> 本文回答一个问题：M3《Multimodal Systems》是否应该成为本 Knowledge Base 的下一本内容增量？如果立项，应该写什么、不写什么、如何避免追热点。
>
> **状态（2026-07-10）**：正文已完成为 6 章 + INDEX；第 6 节 SIT-21 与第 7 节多模态案例已单独落地到 ADS 与 Case Library。

## 1. 结论

**建议立项，但不要直接写成“大而全的多模态百科”。**

推荐形态是：

```text
M3《Multimodal Systems》v0.1：多模态系统工程薄书
```

它应该是一本文本 KB 的“模态扩展层”，不是 CV / ASR / 视频理解 / 机器人学教材。核心任务是把本库的根命题——“用不可靠的概率部件造可靠系统”——扩展到图像、音频、视频、屏幕、传感器和具身环境。

优先级判断：

- **内容缺口真实存在**：当前 KB 基本默认文本 LLM。
- **不能无限期搁置**：Agent 越来越多地读取截图、网页、图像、语音、视频和环境状态。
- **但必须克制**：模型 API、benchmark、具体产品能力会快速过时；M3 应写稳定工程结构，不写当季模型排行榜。

### 2.2 现有覆盖是零散的，不是系统的

当前相关内容主要散落在：

- [[human-ai-interaction-design/00_INDEX|Human-AI Interaction Design]]：讲视觉层面的界面呈现、草稿态、控制感、过程感知，但它处理的是**界面如何呈现 AI**，不是 AI 如何可靠读取图像/音频/视频。
- [[ai-systems-in-production/00_INDEX|AI Systems in Production]]：讲 serving、延迟、可观测性、成本与降级，但没有系统展开多模态输入带来的采样、存储、带宽、隐私和同步问题。
- [[data-foundation-of-ai-systems/00_INDEX|Data Foundation]]：讲数据质量、管线、漂移、治理，但没有展开图像/音频/视频标注、帧采样、ASR/OCR 抽取、跨模态对齐等特殊问题。
- [[evaluation-of-ai-systems/00_INDEX|Evaluation]]：讲评价理论，但没有单独处理“模型看见了什么、听见了什么、漏掉了什么、是否和文本推理一致”的多模态评价。
- [[ai-engineering-anti-patterns/00_INDEX|Anti-Patterns]]：反模式很完整，但缺多模态特有反模式，例如截图盲信、OCR 注入、视频抽帧错觉、语音情绪过拟合。
- [[agent-decision-system/01_SITUATION-ROUTER|Agent Decision System · Situation Router]]：目前已有成本、人机协作、静默退化等情境，但还没有“我在做多模态输入系统 / 截图或语音驱动 Agent”的专门情境。

### 2.3 FABLE5 审阅也曾指出相关缺口

`_governance/fable5/FABLE5_总审报告.md` 对领域覆盖的评价中提到：文本 LLM 工程覆盖扎实，多模态是诚实标注的缺失领域。该报告还指出 ADS 情境覆盖曾缺“多模态输入”类常见处境。

## 3. 立项边界

### 3.1 M3 应该回答的问题

M3 应该回答这些工程问题：

1. **多模态输入如何进入系统？**
   - 直接喂图像/音频/视频？
   - 先做 OCR / ASR / object detection / frame sampling？
   - 哪些信息在预处理阶段已经丢失？

2. **模型到底“看见/听见”了什么？**
   - 多模态输入不是透明事实，而是被采样、压缩、切片后的表征。
   - 应暴露感知不确定性，而不是把视觉/音频判断包装成确定事实。

3. **多模态可靠性如何评价？**
   - 文本答案正确不等于视觉证据正确。
   - 需要区分感知错误、对齐错误、推理错误、表达错误。

4. **多模态 Agent 的权限和安全边界怎么设？**
   - 截图、网页、二维码、图片文字、语音指令都可能成为注入通道。
   - 不能因为“模型能看屏幕”就把屏幕内容当可信事实。

5. **多模态系统如何生产化？**
   - 图像/音频/视频带来更高成本、延迟、存储、隐私和观测压力。
   - 需要明确降级策略：看不清、听不清、抽帧不足、置信不足时如何拒答或升级给人。

### 3.2 M3 不应该写什么

M3 不应该变成：

- CV 算法教材；
- ASR / TTS / 视频模型综述；
- 机器人学或具身智能完整教材；
- 当季模型能力排行榜；
- 多模态 API 使用手册；
- 用一堆 benchmark 证明哪个模型更强。

这些内容过时太快，且会把本库从“AI Engineering 判断系统”拖向“工具快照”。

## 4. 与现有书的边界

### 4.1 与 HCI 的边界

[[human-ai-interaction-design/00_INDEX|Human-AI Interaction Design]] 管“人如何看懂并控制 AI”。

M3 管“AI 如何读取并处理非文本世界”。

一句话边界：

```text
HCI 讲界面如何呈现；M3 讲感知如何进入系统。
```

### 4.2 与 Data Foundation 的边界

[[data-foundation-of-ai-systems/00_INDEX|Data Foundation]] 管通用数据质量、管线、漂移与治理。

M3 管多模态数据的特殊形态：帧、像素、声波、时间轴、空间位置、跨模态对齐。

一句话边界：

```text
Data Foundation 讲数据工程通用规律；M3 讲非文本模态带来的额外信息损失和验证难题。
```

### 4.3 与 Evaluation 的边界

[[evaluation-of-ai-systems/00_INDEX|Evaluation]] 管评价理论和评价设计。

M3 管多模态评价的特殊切分：感知是否正确、定位是否正确、跨模态是否一致、时间序列是否被正确理解。

一句话边界：

```text
Evaluation 讲怎么评价 AI 系统；M3 讲多模态系统哪些地方必须被额外评价。
```

### 4.4 与 Production 的边界

[[ai-systems-in-production/00_INDEX|AI Systems in Production]] 管生产系统的 serving、观测、发布、成本和降级。

M3 管多模态生产中的特殊成本：大对象传输、帧采样、媒体存储、隐私脱敏、实时性、无法重放的环境输入。

一句话边界：

```text
Production 讲生产通用机制；M3 讲媒体/传感器输入让这些机制变难的地方。
```

### 4.5 与 Laws 的边界

M3 不新增一套“多模态定律”。它应该调用现有 Law System，例如：

- [[laws-of-ai-engineering/01_信息与压缩定律#Law 1 — 有损压缩定律（Lossy Compression Law）|Law 1：有损压缩定律]]：图像压缩、抽帧、转录都会丢信息。
- [[laws-of-ai-engineering/01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|Law 4：信息守恒定律]]：没有被看见、听见或采集到的信息，不能靠推理凭空补成可靠事实。
- [[laws-of-ai-engineering/01_信息与压缩定律#Law 9 — 表征决定能力定律（Representation-Determines-Capability Law）|Law 9：表征决定能力定律]]：模型能处理什么，取决于输入被怎样表征。
- [[laws-of-ai-engineering/02_计算与验证定律#Law 12 — 验证-生成不对称定律（Verification-Generation Asymmetry Law）|Law 12：验证-生成不对称定律]]：多模态输出更难核验。
- [[laws-of-ai-engineering/07_认识论与真理定律#Law 63 — 不确定性外显定律（Surface-Uncertainty Law）|Law 63：不确定性外显定律]]：看不清/听不清要显式说出来。
- [[laws-of-ai-engineering/10_对抗与安全定律#Law 87 — 一切输入皆指令定律（All-Input-Is-Instruction Law）|Law 87：一切输入皆指令定律]]：图像文字、截图、语音也可能携带指令。
- [[laws-of-ai-engineering/10_对抗与安全定律#Law 92 — 数据即攻击面定律（Data-Is-Attack-Surface Law）|Law 92：数据即攻击面定律]]：媒体输入扩大攻击面。

## 5. 推荐目录

如果立项，建议 M3 用 6 章，不超过 v1.0 中等体量：

```text
multimodal-systems/
  00_INDEX.md
  01_多模态系统的第一性.md
  02_感知管线与表征损失.md
  03_跨模态上下文与状态.md
  04_多模态评价与证据.md
  05_多模态生产系统.md
  06_多模态安全与反模式.md
```

### 5.1 各章职责

**01_多模态系统的第一性**

- 核心命题：多模态不是“模型多会一项技能”，而是“系统多了一条不可靠输入通道”。
- 解释感知、表征、推理、行动的分层。
- 明确 M3 与 HCI / Data / Evaluation / Production 的边界。

**02_感知管线与表征损失**

- 图像：分辨率、裁剪、OCR、对象识别、空间关系。
- 音频：ASR、说话人、噪声、情绪推断。
- 视频：抽帧、时间轴、动作、事件边界。
- 核心：每一步预处理都在压缩世界。

**03_跨模态上下文与状态**

- 截图 + DOM + 文本说明如何合成状态。
- 语音 + 屏幕 + 工具返回如何形成任务上下文。
- 视频/音频流如何做窗口、摘要、回源。
- 避免把“当前帧”误认为“完整事实”。

**04_多模态评价与证据**

- 感知正确性、定位正确性、跨模态一致性、任务成功率分开评估。
- 标注与测试集设计。
- 人类评价在多模态系统中的不可替代处。
- “答案对了但看错了”也算失败。

**05_多模态生产系统**

- 延迟、成本、带宽、存储、隐私、重放与观测。
- 低置信/不可读/不可听/抽帧不足的降级路径。
- 多模态日志怎么留，哪些不能留。

**06_多模态安全与反模式**

- OCR prompt injection；
- 图像/截图中的隐藏指令；
- 二维码/链接/界面文字的工具调用风险；
- 语音伪指令与说话人混淆；
- 视觉流畅感导致过度信任；
- 视频抽帧错觉。

## 6. 应补的 ADS 情境

如果 M3 开写，建议同步评估是否新增一个 ADS 情境：

```text
SIT-21 · 我在做多模态输入 / 截图 / 语音 / 视频驱动的 Agent
```

但这不应在立项审计阶段直接改 ADS。原因：ADS 是机器层，新增 SIT 会影响编译器、案例路由、Case Library 示例入口，应该等 M3 目录定稿后单独执行。

候选路由可能包含：

- 先判断输入模态是否可信；
- 区分感知错误与推理错误；
- 多模态输入默认不可信；
- 对高风险行动加人类确认；
- 不可读/不可听/不可见时必须拒答或升级。

## 7. 应补的案例类型

如果 M3 开写，建议 Case Library 后续补 5–8 个多模态案例，而不是立刻把 100 案全部改写：

1. 截图驱动的 computer-use Agent 误点高危按钮；
2. OCR 把发票/合同关键字段识别错，导致后续推理全错；
3. 图片中的隐藏文字触发 prompt injection；
4. 语音客服把背景声音/旁人指令当成用户意图；
5. 视频抽帧漏掉关键事件；
6. 医疗/教育/工业场景中视觉不确定性没有外显；
7. 多模态日志留存不当导致隐私泄漏；
8. “看起来能看懂屏幕”导致用户过度授权。

## 8. 是否现在开写？

建议：**可以立项，但分两步走。**

### Step 1：先写 00_INDEX + 01 章

先建立边界和总论，不要一口气写完整书。

验收标准：

```text
multimodal-systems/00_INDEX.md 存在
multimodal-systems/01_多模态系统的第一性.md 存在
README / 总图 / 学习路径接入
python3 _tools/kb_health_check.py 通过
GitHub Actions 通过
```

### Step 2：再决定是否补 02–06

如果 01 章能清楚划定稳定边界，再扩写后五章。

如果 01 章写出来像“模型功能综述”，应暂停，不继续扩写。

## 9. 暂缓项

以下内容不建议在 M3 第一轮做：

- 具体模型 API 教程；
- 实时视频 Agent 工程手册；
- 机器人/具身智能完整书；
- benchmark 对比表；
- 多模态工具链市场地图；
- 自动把 ADS 增加 SIT-21；
- 自动把 Case Library 扩 20 个多模态深度案例。

这些都可以以后做，但第一轮不做。

## 10. 最终建议

M3 是真实缺口，值得立项；但它的正确形态不是“追多模态热潮”，而是：

> 把本库已经成熟的可靠性、评价、生产、权限、安全和人机信任框架，扩展到非文本输入世界。

推荐下一步：

```text
先开 M3 v0.1，只写 00_INDEX + 01_多模态系统的第一性。
```

写完后再由强模型或人审查：它是否保持工程判断系统的稳定性，而不是变成工具综述。
