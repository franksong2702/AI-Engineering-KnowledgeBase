# 模式 12 投票 Voting（含 Self-Consistency）

## 为什么存在

LLM 输出有随机性：同一问题跑十次，对七次错三次。如果错误是**不相关的**（每次错得不一样），多数表决就能把 70% 的单次正确率放大到 90%+——这是集成学习（ensemble）的经典数学，Condorcet 陪审团定理的 LLM 版。Voting 用最笨的机制（数票）购买可靠性，**不需要任何成员变聪明**。Self-Consistency（同模型多次采样取多数）是它最简单的形态。

## 适合解决什么问题

答案可离散比较的任务：分类、多选、数学题（答案可对齐）、是/否判断、代码（以"通过测试"为等价判据）、抽取（字段值可比对）。判据两条缺一不可：**答案空间可机械比较**（散文没法数票）；**错误相对独立**（见缺点）。

## Agent 如何协作

零协作，这是它的特点：n 个投票者**完全独立**并行作答（温度调高以增加多样性，或用不同 prompt/模型），互相不知道彼此存在。聚合器（纯代码，不是 LLM）统计：多数决 / 加权 / 超阈值才采纳（如 5 票里要 4 票同意才输出，否则转人工——用弃权换精度）。

## 信息如何传递

只有输入进、答案出，无中间通信。聚合器只看最终答案，不看推理过程（这是与 Committee 的本质区别：Voting 数票不听理由）。**答案必须先规范化**（"42"、"42.0"、"答案是42"算同一票），规范化器的质量直接影响计票有效性。

## 什么时候结束

n 次采样完成 + 计票即结束，天然有界。可加提前终止：前 3 票全一致就不跑后 2 次（置信采样，省 40% 成本）。无多数时的路径要预定义：加采样、降级到人工、或输出"不确定"。

## 优点

- 实现成本最低的可靠性手段：不用改 prompt、不用调模型，纯工程包一层
- 完全并行，延迟 ≈ 单次调用
- 附赠**置信度信号**：5:0 和 3:2 的多数是完全不同的可信度，可用于分流（一致→自动通过，分裂→人工）
- 数学性质清楚，收益可预测可验证

## 缺点

- **相关错误是天敌**：同一模型的系统性偏见（比如某类陷阱题永远上当）意味着十次全错得一模一样，投票只是把错误答案盖上"高置信"的章——比单次更危险
- 只适用于可离散化的答案，开放生成任务用不了（要选最佳散文得配 Judge，那是另一个模式）
- 成本线性 ×n，而收益随 n 递减（3→5 票收益明显，5→9 票基本白花钱）
- 多数不等于正确：困难问题上多数可能稳定地错（模型集体盲区）

## Prompt 示例

（投票者的 prompt 就是普通任务 prompt；关键在多样化注入——以下是三个投票者的差异化前缀）

```
投票者A（默认）：直接解题。
投票者B（换路径）：先用与直觉相反的假设检验一遍，再解题。
投票者C（换表征）：把问题转写成表格/符号形式后再解。
统一输出约束：最后一行必须是 "FINAL: <答案>"（聚合器按此行计票）。
```

（聚合是代码不是 prompt——这是本模式的纪律）

## Workflow 示例

```
任务：1000 份保险理赔单的自动审核分类
每单 → [投票者 ×5 并行]（3 个同模型高温采样 + 2 个异构模型）
  → 规范化答案 → 计票
     ├─ 5:0 / 4:1 → 直接采纳（占 82%，错误率 0.4%）
     ├─ 3:2       → 转人工（占 18%）
监控：每周抽检"全票一致"样本 200 份，检测相关错误
  → 发现某类新单据全票错 → 说明是系统性盲区，修 prompt 而不是加票数
```

## 未来还能如何改进

- **异构化投票团**：不同基座模型 + 不同提示策略组合投票，直接攻击相关错误问题——收益比增加票数大得多
- **校准加权**：按各投票者的历史准确率加权计票（而非一人一票），用少量标注数据即可显著提升
- **推理路径审计**：答案一致但推理路径全都可疑时降低置信度（防"集体蒙对"），用轻量模型扫描推理摘要实现
- **与 Judge 复合**：开放生成任务先 n 个候选，Judge 选优——"生成投票化、选择裁判化"覆盖 Voting 的离散化盲区
