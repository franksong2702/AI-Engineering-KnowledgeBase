# 模式 08 Mixture of Experts（Agent 级）

> 注意区分：模型内部的 MoE（稀疏激活的网络架构，如 Mixtral）是训练技术；本章讲的是 **Agent 层面的 MoE**——多个专家 Agent 同时或选择性作答，由门控/聚合器融合。两者共享思想，实现完全不同。

## 为什么存在

Dynamic Routing 假设"每个输入恰好属于一类"，但复杂问题往往**同时需要多个专业视角**：一个架构决策既是技术问题又是成本问题又是团队问题。MoE 不做单选题：让多个专家**都**回答（或选 top-k 个），再把视角**融合**成一个答案。路由是"分诊"，MoE 是"会诊"。

## 适合解决什么问题

跨领域综合判断：技术方案评审（性能+安全+成本+可维护性专家）、投资/商业决策（市场+财务+法务）、医疗类咨询的多学科会诊、内容创作的多维打磨（事实+逻辑+文风）。判据：单一视角的答案系统性地不完整，且各视角有真实的专业分工（不同工具、不同知识库、不同评价标准——不只是不同头衔）。

## Agent 如何协作

三层：**Gate**（判断这个问题需要哪几位专家，权重各多少）→ **Experts × k 并行**（各自独立作答，互不可见——独立性保证视角不趋同）→ **Aggregator**（融合：不是平均，而是按专家权重与置信度综合，冲突处显式裁决）。

## 信息如何传递

Gate 输出专家选择与权重 → 每位专家收到原始问题 +"从你的专业视角"的角色约束 → 各专家输出结构化意见（结论+依据+置信度+边界声明"这超出我的领域"）→ Aggregator 收到全部意见与权重，产出融合答案 + 保留的分歧。

## 什么时候结束

所有被选专家返回（或超时按缺席处理）→ 聚合完成。单轮模式天然有界。进阶版：Aggregator 发现专家间存在关键冲突时，可发起一轮定向质询（把 A 的论点给 B 看），一轮为限——再多就该升级为 Committee。

## 优点

- 视角完整性：系统性减少"没考虑到 X 维度"的盲区错误
- 并行执行，延迟 ≈ 最慢的专家而非专家之和
- Gate 的稀疏激活控制成本：简单问题只叫 1-2 位专家
- 专家可独立进化（换模型、换工具、调 prompt）互不影响

## 缺点

- **融合是难点**：简单拼接 = 冗长报告；粗暴平均 = 把正确的少数派意见抹掉
- 同一基座模型扮演的"不同专家"相关性很高，视角多样性可能是装饰性的（见 INDEX 定律 2）
- 成本 = k 倍起步，Gate 自己也是一次调用
- 专家意见冲突时，Aggregator 实际上在做它可能不具备资格的裁决

## Prompt 示例

（Aggregator——融合环节的质量决定整个模式的价值）

```
你收到 {k} 位专家对同一问题的意见（附 Gate 分配的权重）。融合规则：
1. 共识部分直接吸收
2. 冲突部分：不要平均。判断冲突根源——事实分歧（可查证的，标记待核实）
   还是价值权衡（如性能vs成本，呈现权衡而非选边）
3. 尊重专业边界：安全专家对安全问题的意见 > 其他专家对安全的顺带评论
4. 输出：{"answer": 融合结论, "dissent": 保留的少数派意见及其理由,
   "confidence": 综合置信度, "blind_spots": 所有专家都没覆盖的疑点}
```

## Workflow 示例

```
问题：'我们要不要把核心服务迁移到 K8s？'
[Gate] → 选择：架构专家(0.35) 运维专家(0.30) 成本专家(0.20) 团队能力专家(0.15)
[4 专家并行] 各自带专属知识库/工具作答
  架构:利于扩展 | 运维:当前团队值班能力不足,高风险 | 成本:一年内更贵 | 团队:需3个月培训
[Aggregator] 识别出真正的权衡轴是"长期扩展性 vs 当期运维风险"
  → 融合建议：分阶段迁移,先非核心服务练手 + 保留少数派记录(成本专家反对全迁)
```

## 未来还能如何改进

- **真差异化专家**：不同基座模型 + 不同工具 + 不同语料做专家，把"装饰性多样"变成真多样
- **Gate 的历史校准**：记录"哪类问题哪些专家的意见事后被证明对"，动态调专家权重——从静态分工到学习型分工
- **专家自报无知**：训练/提示专家在领域外主动弃权（输出 abstain），比硬答后被 Aggregator 降权更干净
- **两轮稀疏激活**：先叫 1 位主专家，其答案的 blind_spots 字段触发追加专家——把 k 倍成本变成按需成本
