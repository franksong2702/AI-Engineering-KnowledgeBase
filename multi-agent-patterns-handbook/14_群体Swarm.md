# 模式 14 群体 Swarm

## 为什么存在

前面所有模式都有"中心"（协调者、主席、聚合器）。但自然界证明另一条路可行：蚁群没有指挥官，靠个体遵循简单局部规则 + 信息素，涌现出复杂的集体智能。Swarm 把这个搬到 Agent：**大量简单同质 Agent，只做局部交互，无中心控制，让解决方案从群体行为中涌现**。它存在的理由是探索中心化协调的天花板之外——当问题大到无法预先规划、且解空间需要大规模并行探索时。

> 注：业界也有产品把"Swarm"用作轻量 Agent 交接（handoff）框架的名字，那更接近去中心化路由。本章讲的是**涌现型 Swarm** 这一更本源的含义。

## 适合解决什么问题

诚实说：**当前生产环境的成熟用例很少**，多为研究性/探索性。理论适配：超大规模并行探索（同时从上千个角度试探一个开放问题）、无标准答案的创意涌现、群体模拟（模拟市场/社会中大量自主个体的交互）、鲁棒性极端要求（无中心 = 无单点故障）。判据：问题的价值在于"探索的广度和意外发现"，而非"可控地完成一个明确目标"。

## Agent 如何协作

无层级、无指派。每个 Agent 运行相同的简单策略：观察局部环境（邻居的产出、共享信号）→ 按局部规则行动 → 留下可被他人感知的痕迹（数字信息素：如"这个方向已被探索且贫瘠"）。全局行为不是被设计的，是被涌现的。关键设计是**局部规则**和**信息素机制**，不是单个 Agent 的智能。

## 信息如何传递

**间接、异步、通过环境**（stigmergy 共识法）——Agent 不直接对话，而是修改共享环境，其他 Agent 感知环境变化。信息素要能累积（强化好路径）和挥发（遗忘过时信息，防止早期噪声永久污染）。这种"通过留痕沟通"是 Swarm 区别于其他模式的本质。

## 什么时候结束

最难定义终止的模式。可用判据：全局信号收敛（信息素分布稳定）、达到资源预算、发现满足阈值的解、或外部观察者判定"涌现出的模式足够好"。**缺乏清晰终止条件是 Swarm 难以生产化的核心障碍之一**。

## 优点

- 无单点故障，个别 Agent 失败不影响整体（鲁棒性极强）
- 探索广度无与伦比：大规模并行触达中心化规划想不到的解
- 可能涌现出设计者未预期的创新解
- 理论上可近乎无限扩展（加 Agent 即可，无协调瓶颈）

## 缺点

- **不可预测、不可控**：涌现是双刃剑，可能涌现出你不想要的行为，且难以调试（没有"负责的那个 Agent"）
- 成本极高且难封顶：大量 Agent × 难以确定的终止 = 烧钱黑洞
- 收敛慢且不保证收敛：可能永远在探索，或收敛到糟糕的局部最优
- 对局部规则和信息素参数极度敏感，调参是玄学
- 成熟度最低，生产案例稀少，多数停留在论文和 demo

## Prompt 示例

（个体 Agent——注意它只有局部视野和简单规则）

```
你是探索群体中的一个个体。你只能看到局部信息，没有全局视野。
你的环境：{当前你所在的"位置"（如某个子问题/某个解方向）}
信息素读数：{邻近方向被探索的强度与产出质量信号}
局部规则：
1. 若当前方向信息素弱（少人探索）且看起来有潜力 → 深入，留下正信息素
2. 若当前方向信息素强但产出差 → 标记"贫瘠"（负信息素），迁移到邻近方向
3. 有概率随机跳转（保持探索多样性，防止全体扎堆）
输出：{"action": "explore|migrate|mark_barren", "finding": 本步产出,
"pheromone_delta": 你对当前方向留下的信号}
```

## Workflow 示例

```
任务：为一个开放式研究难题海量探索可能的解方向（探索优先于收敛）
初始化：50 个个体随机撒在解空间，共享信息素地图
循环（异步）：
  每个个体 观察局部信息素 → 按规则探索/迁移/标记 → 更新信息素地图
  信息素随时间挥发（旧探索的影响衰减）
观察者（非控制者）：监控信息素地图的聚集模式
  → 3 个高信息素簇涌现（= 群体自发认为有希望的 3 个方向）
终止：信息素分布 200 步内稳定 或 预算耗尽 → 人类接手评估涌现出的方向
定位：这是"生成候选方向"的工具，不是"给出答案"的系统。
```

## 未来还能如何改进

- **混合架构**：Swarm 负责发散探索，中心化模式（Committee/Judge）负责收敛评估——用涌现的广度喂给可控的深度，绕开纯 Swarm 的不可控
- **可控涌现**：给信息素机制加"护栏规则"，在保留涌现红利的同时排除不想要的集体行为
- **自适应种群**：动态增减个体数量与探索/利用比例，缓解成本失控
- **可解释涌现**：开发工具把"为什么群体收敛到这里"可视化，攻克调试难题——这是 Swarm 走向生产的关键前置
- **务实态度**：在绝大多数实际任务中，一个设计良好的中心化模式更划算；Swarm 的价值目前主要在研究和特定探索场景，选用前先确认你真的用尽了中心化方案
