# 模式 05 Planner-Executor

> **定义归属说明**：本章是 Planner-Executor 的权威定义；推断视角的精要版见 [[llm-design-patterns/05_编排模式|Design Patterns 家族五]]，决策系统操作卡见 PAT-09。

## 为什么存在

单 Agent 边走边想时容易鼠目寸光：陷入局部细节、忘记全局目标、重复劳动。规划与执行是两种认知模式——**规划需要全局视野和深思（贵、慢、一次），执行需要专注局部和行动（快、可并行、可用便宜模型）**。分开之后各自都变强，这是"先想清楚再动手"的架构化。

## 适合解决什么问题

多步骤、有依赖关系、但拆解后每步相对明确的任务：复杂研究、代码功能开发（先设计后实现）、活动策划执行、数据分析项目、迁移/重构类工程。判据：任务需要"想清楚步骤"，但想清楚之后每步不需要太多临场创造。

## Agent 如何协作

**Planner**：理解目标 → 产出结构化计划（任务列表 + 依赖图 + 每步验收标准）。**Executor（一个或多个）**：认领任务 → 执行 → 回报结果与状态。进阶版加一个循环：执行中发现计划失效（前提变了、路走不通）→ 回到 Planner **重规划**（带着已完成的进度和新信息）。

## 信息如何传递

计划是核心工件：任务清单（每项自包含）+ 依赖关系 + 验收标准，通常落在共享文件/状态库里。Executor 回报结构化状态（done/blocked/failed + 产出 + 新发现）。**Planner 不看执行细节只看状态摘要**；Executor 不看全局目标只看任务书——各自的上下文都保持干净。

## 什么时候结束

计划中所有任务完成（正常）；重规划次数达上限（防止规划震荡）；Executor 连续失败触发升级（人工介入）。重规划预算通常 2-3 次——超过说明任务本身不适合预先规划，该换 ReAct 式边走边想。

## 优点

- 全局一致性好：有人对整体负责，不会做了后面忘前面
- 成本结构优：贵模型只做规划（一次），执行用便宜模型（多次）
- 天然并行：无依赖的任务同时派发
- 计划本身可人工审查——在执行前拦截方向性错误，这是它相比自主 Agent 的巨大安全优势

## 缺点

- **计划赶不上变化**：现实与预案偏差时，僵化执行错误计划比没有计划更糟
- 规划-执行鸿沟：Planner 不了解执行端的真实约束，计划"看着很美"
- 重规划的状态同步复杂：哪些成果保留、哪些作废，容易出错
- 对"探索型任务"（做了才知道下一步）根本不适用

## 长时程 Agent 的边界（2026-Q4 重估补充）

本章描述的是"先规划、后执行、必要时重规划"的两段式。到 2026 年，长时程 Agent（尤其编码 Agent）更常见的形态是**交错式计划**：单个 Agent 在自己的循环里维护一份 todo 列表，规划和执行交替进行，每完成一步就更新列表，计划始终是"活的状态"而不是一份静态文档。

两种形态怎么选：

- **用两段式**：计划需要在执行前交给人审批（高风险、不可逆的任务）；或执行端要分发给多个 Executor 并行（这时计划就是派工单）。
- **用交错式**：做了才知道下一步、重规划会很频繁的任务。本章"什么时候结束"里说重规划超过 2–3 次就该换 ReAct 式，交错式计划就是这种"换法"的成熟版本：保留 todo 列表带来的全局视野，放弃预先定死的计划。

两种形态共同的纪律：计划写在上下文之外（文件或状态库），这样上下文压缩或会话中断后能恢复；每个任务都有可验证的完成标准。

## Prompt 示例

（Planner）

```
为以下目标制定执行计划。
输出 JSON 任务列表，每项：
{"id": n, "task": "自包含描述（执行者只看到这一条）",
 "depends_on": [ids], "acceptance": "可验证的完成标准",
 "estimated_difficulty": "low|med|high", "tools_needed": [...]}
规则：
- 每个任务应该能在 10 次工具调用内完成，否则继续拆
- 明确标注哪些任务是"探路"性质（其结果可能改变后续计划）,把它们排在前面
- 最后输出你对整个计划最大的不确定点
```

## Workflow 示例

```
目标：给产品写一份竞品分析报告
[Planner] → 计划：①确定竞品清单(探路) ②并行：逐家功能调研 ③定价对比
            ④用户评价挖掘 ⑤综合撰写(依赖②③④)
[Executor×3] 并行执行 ② ③ ④，任务①的结果先回来
  → ①发现竞品比预期多一倍 → 触发重规划
[Planner] 重规划：竞品分两档，一档深研、二档略过 → 更新任务表
[Executors] 完成 → [Planner] 验收各任务 acceptance → 派发⑤ → 交付
终止：全部验收通过；重规划 1/3 次
```

## 未来还能如何改进

- **交错规划（interleaved planning）**：不再"一次规划+偶尔重规划"，而是每完成一个任务就轻量更新计划——计划从静态文档变成活的状态（业界已在此方向收敛）
- **执行反馈进规划先验**：积累"哪类任务实际难度总被低估"的历史，Planner 越用越准
- **计划的可行性预演**：派发前用便宜模型对每个任务做 30 秒"能不能做"试探，提前暴露死路
- **双 Planner 制衡**：一个乐观规划、一个专挑计划漏洞，高风险任务的规划质量显著提升
