# 模式 15 黑板 Blackboard

## 为什么存在

有些问题的解决路径无法预先安排调用顺序：你不知道该先用哪个专家，因为要看到部分结果才知道下一步需要谁。黑板模式（源自 1970 年代 AI 语音识别系统 Hearsay-II）提供一个**共享工作区**：各路专家不被调度，而是持续观察黑板，一旦发现"我能贡献了"就主动上前添砖加瓦。它介于中心化与 Swarm 之间——有共享状态（比 Swarm 结构化），但无固定流程（比 Pipeline 灵活）。

## 适合解决什么问题

解题路径高度依赖中间发现的复杂问题：多源信息融合（不同专家在不同时刻贡献线索，逐步拼出全貌）、复杂诊断（医疗/故障排查，一个发现触发另一类检查）、逆向工程与调查分析、需要机会主义推理的开放任务。判据：**你无法预先排出专家的调用顺序，因为顺序取决于问题解到哪一步**。

## Agent 如何协作

三要素：**黑板**（结构化共享状态，记录问题当前的所有已知信息与部分解）、**知识源 KS**（各领域专家 Agent，每个声明"我在什么条件下能贡献"）、**控制器**（决定下一步激活哪个 KS——可以是规则、可以是 LLM 调度器）。KS 不互相调用，全部通过读写黑板间接协作：谁看到自己的触发条件被满足，就被激活去贡献。

## 信息如何传递

全部经由黑板，无点对点通信。KS 读黑板当前状态 → 判断能否贡献 → 写入新信息/假设/部分解 → 黑板更新 → 可能触发其他 KS 的激活条件。黑板是唯一真相源，天然留痕。**写入需管理冲突**（两个 KS 想改同一处）——通常控制器串行化写入，或 KS 只追加不覆盖。

## 什么时候结束

黑板上的解达到"完整"判据（预定义的目标状态满足），或没有任何 KS 能继续贡献（僵局），或预算耗尽。控制器负责持续检查终止条件——它比 Swarm 好在这里有明确的状态可判断，比 Pipeline 灵活在顺序不预设。

## 优点

- 处理"路径不可预知"问题的能力强，机会主义推理贴合真实调查/诊断过程
- 灵活可扩展：加一种专家 = 加一个 KS + 声明其触发条件，不动其他部分
- 黑板即完整的推理记录，可解释性和可审计性好
- 控制策略与专家能力解耦，可以独立优化"何时叫谁"

## 缺点

- **控制器是复杂度焦点**：决定"下一个激活谁"很难，差的控制器让系统要么空转要么颠簸
- 并发写入的一致性问题（竞态），需要认真设计写入协议
- 可能陷入僵局（无 KS 可贡献但问题没解完）或循环（KS 反复改写同一处）
- 相比 Pipeline 难以预测成本和延迟
- 成熟工业案例不多，多见于特定领域（调查、诊断），通用生产框架仍在演化

## Prompt 示例

（知识源 KS——注意"先自检能否贡献"是黑板协作的关键）

```
你是"{专业领域}"知识源。这是黑板的当前状态：{blackboard_state}
第一步自检：以你的专业，当前状态下你能贡献新信息吗？
  不能 → 输出 {"can_contribute": false, "waiting_for": "你需要黑板上出现什么才能出手"}
  能   → 贡献并输出：
  {"can_contribute": true,
   "contribution": {"type": "fact|hypothesis|partial_solution|contradiction",
                    "content": "...", "confidence": 0-1,
                    "based_on": "你依据了黑板上的哪些条目"},
   "triggers": "你的贡献可能让哪类专家现在能出手了"}
规则：只在真有把握时贡献；发现黑板上的矛盾要主动标记；不要覆盖他人条目，追加。
```

## Workflow 示例

```
问题：一个线上系统间歇性故障的根因调查
黑板初始：{症状: "每天凌晨 3 点 API 延迟飙升"}
控制器激活序列（顺序由黑板状态动态决定，非预设）：
  [日志专家] 看到症状 → 贡献"3点有批量任务启动"→ 触发...
  [资源专家] 被触发 → 贡献"该时段 DB 连接池打满"假设 → 触发...
  [数据库专家] → 验证假设，贡献"批任务未复用连接"→ 部分解成形
  [矛盾检测] → 发现"但故障上周才开始，批任务存在半年"→ 标记矛盾
  [变更专家] 被矛盾触发 → 贡献"上周连接池配置被调小"→ 根因闭合
终止：黑板达成完整因果链（症状→根因→证据）→ 输出诊断报告
```

## 未来还能如何改进

- **LLM 作为智能控制器**：用模型读黑板全局状态来决定激活谁，替代僵硬的规则控制器——这是黑板模式在 LLM 时代复兴的最大机会
- **黑板的结构化与检索**：大型黑板本身会超上下文，需要给 KS 提供"按需检索黑板相关部分"的能力（黑板 + RAG）
- **僵局打破机制**：检测到无 KS 可贡献时，自动放宽触发条件或引入"探索性假设"KS，避免停摆
- **写入冲突的乐观并发控制**：借鉴数据库事务，让 KS 并行贡献 + 冲突时合并/回滚，提升吞吐
- **与其他模式复合**：黑板作为多个子系统（各自可能是 Pipeline 或 Committee）的共享记忆层，做大型系统的协调基座
