# 模式 11 委员会 Committee（含辩论 Debate 变体）

> **定义归属说明**：本章（含辩论 Debate 变体）是 Debate/Committee 作为多体质量机制的权威定义；推断视角的简述见 [[llm-design-patterns/04_质量控制模式|Design Patterns 家族四]]。

## 为什么存在

有些判断没有客观判据可依（战略选择、伦理权衡、审美裁决），单一视角必然片面，而 Voting 的机械聚合又太粗——它数票，不听理由。Committee 引入**审议（deliberation）**：成员不仅给出意见，还要看到彼此的意见并回应，让理由与理由碰撞，最后由主席综合。核心赌注：**交换理由能产生任何单个成员都没有的判断质量**。

## 适合解决什么问题

高风险、无标准答案、理由比结论更重要的判断：重大技术选型、投资决策、内容伦理审查、复杂案例分析（法律/医疗式多视角会诊）、评审申请与提案。判据：你更想要"一份考虑了所有反对意见的论证"而不是"一个票数"。

## Agent 如何协作

三阶段（阶段一的独立性是全模式的命门）：
1. **独立意见**：成员互不可见地各自给出立场 + 理由（防止从众级联）
2. **审议轮**：公开全部意见，每个成员必须回应与自己相左的最强论点（修改立场需说明被什么说服）
3. **综合**：主席不投票，负责产出决议——吸收共识、裁决冲突、显式保留少数派

**Debate 变体**：成员改为立场固定的正反双方，各为其立场做最强辩护，第三方裁决——用于二元决策，对抗性更强，防和稀泥。

## 信息如何传递

阶段一：只有议题进，意见不互通。阶段二：全部意见广播（附论点编号便于引用回应）。阶段三：主席收全部意见 + 审议记录。**发言必须结构化**（立场/论据/置信度/我可能错在哪），否则审议退化为散文互喷。

## 什么时候结束

固定轮次（通常独立 1 轮 + 审议 1-2 轮）为主流——审议超过 2 轮后新论点产出率断崖式下降,只剩措辞调整。也可用收敛判据：无成员再修改立场即提前结束。主席产出决议为最终终点。

## 优点

- 论证质量的天花板最高：结论自带"已考虑的反对意见"清单
- 强制回应机制逼出隐藏的假设与证据
- 少数派意见被制度性保留，尾部风险不被平均掉
- 决议过程全程留痕，重大决策的可追责性最好

## 缺点

- **从众级联**：一旦泄漏他人意见（阶段一不严格），后发者会锚定先发者——LLM 的顺从倾向使此病比人类委员会更重
- **同源伪多样**：同一模型的五个"委员"可能是同一个观点的五种措辞（INDEX 原则 2 的重灾区）
- 成本最高的质量模式之一：n 成员 × 多轮 × 长发言
- 主席权力过大：综合环节可以悄悄篡改审议结果，需要抽查

## Prompt 示例

（审议轮成员——强制回应是审议的灵魂）

```
这是全体成员对议题的第一轮独立意见（含你自己的 #{k}）。
你的任务：
1. 找出与你立场相左的最强论点（不是最弱的——攻击稻草人无效）
2. 认真回应它：反驳（给证据）或接受（修改你的立场）
3. 输出：{"strongest_opposing": "论点编号+复述（须让对方认可你复述准确）",
   "response": "...", "position_change": "none|modified|reversed",
   "updated_position": "...", "confidence": 0-1}
规则：修改立场不是失败，被证据说服是审议的目的；
但"为了和谐"的趋同是渎职——只有论据能改变你。
```

## Workflow 示例

```
议题：'开源我们的核心引擎吗？'
[阶段1] 5 成员独立作答（商业/技术/社区/法务/竞争 5 个专属知识配置）
   → 3 支持 2 反对，论点共 14 个
[阶段2] 审议 2 轮：法务的合规论点使 1 名支持者转为有条件支持;
   竞争成员的"护城河"论点被商业成员用数据反驳后撤回
[阶段3] [主席] 决议：有条件开源（核心保留、SDK开源）
   + 共识依据 5 条 + 保留的少数派意见（竞争成员的残余担忧）+ 触发重审的条件
成本：单 Agent 的 11×。用于该量级决策：值得。
```

## 未来还能如何改进

- **强制去相关**：成员用不同基座模型 + 不同知识库 + 不同论证风格指令，把伪多样变真多样（当前最要紧的改进）
- **主席审计**：独立 Judge 抽查"决议是否忠实反映审议"（防主席篡改），或主席轮换制
- **论点图谱化**：把审议记录自动整理为论点-反驳-证据的图结构，人类可以直接读图而非读记录全文
- **动态成员招募**：审议中发现缺某专业视角（如"这里需要税务知识"）时动态加委员，而非预设固定名单
