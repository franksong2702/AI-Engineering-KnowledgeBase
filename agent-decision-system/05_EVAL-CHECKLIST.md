# Agent Decision System · 评价清单（05_EVAL-CHECKLIST）

> 10 个"评价一个 AI 系统/自己的产出是否优秀"必答的问题，做成可运行的清单。用于交付前、上线前、或自评时。深度→[[evaluation-of-ai-systems/00_INDEX|Evaluation]]。
> 中心命题：**优秀 = 在真正重要的事上、以可接受代价、可靠可信地交付价值，且错得起。** 十问是它的十个切面。

---

## 运行方式

```
FOR each 待评价的系统/产出:
  逐条回答 Q-01..Q-10 (不是勾"做了"，是勾"验证过")
  任何 🔴 项不通过 → BLOCK(不可交付/上线)
  🟠 项不通过 → WARN(记录风险，需明确接受)
```

---

## Q-01 · 它服务的真实目标是什么？🔴
- **必答**: 这个系统/产出要让什么"真正重要的事"变好？
- **通过判据**: 你测的东西 == 用户真正在意的东西（而非容易测的代理）。
- **失败信号**: 优化了跑题的、可测但无关的目标。
- **Relevant**: LAW-04 · Q-05

## Q-02 · 它可靠吗——看分布不是峰值？🔴
- **必答**: 它的成功率、方差、最坏情况是多少（不是"最好的一次"）？
- **通过判据**: 有成功率分布数据，且最坏情况可接受。
- **失败信号**: 只有 demo/峰值表现，无重复测量的分布。
- **Relevant**: 能力-可靠性剪刀 · 长尾定律 · SIT-02

## Q-03 · 它错得起吗——失败廉价可查？🔴
- **必答**: 它失败时，多快多便宜能被发现？波及范围多大？
- **通过判据**: 失败显式报警 + 爆炸半径可控。
- **失败信号**: 存在会静默酿成大祸的失败模式。
- **Relevant**: LAW-06 · 显式失败 · ANTI-01

## Q-04 · 代价可接受吗？🟠
- **必答**: 每个任务的 token/延迟/人工核查成本是多少？规模化后可持续吗？
- **通过判据**: "质量÷成本"划算，含人工成本后仍可持续。
- **失败信号**: 只测质量没测成本；规模化后单价不可行。
- **Relevant**: 质量有成本 · 成本结构决定架构

## Q-05 · 我优化的是真实目标还是代理？🔴
- **必答**: 我盯着的指标，与真实价值的相关性检验过吗？
- **通过判据**: 指标改善时真实目标被独立验证也改善（未脱钩）。
- **失败信号**: 分数刷高了但真实价值没动/反向。
- **Relevant**: LAW-04(古德哈特) · ANTI-03 · SIT-16

## Q-06 · 它在分布外/长尾/对抗下如何？🔴
- **必答**: 用没见过的、刁钻的、边界的、对抗的输入测过吗？
- **通过判据**: 评测集含长尾+边界+对抗样本，表现可接受。
- **失败信号**: 只测了典型/顺手样本。
- **Relevant**: 长尾定律 · 分布漂移 · ANTI-05

## Q-07 · 它的置信度校准吗？🟠
- **必答**: 它说 80% 确信的事，长期真有约 80% 为真吗？
- **通过判据**: 有可靠性图/校准数据，置信度可用于分流。
- **失败信号**: 对确定和不确定的输出一样自信。
- **Relevant**: LAW-03(校准) · SIT-15

## Q-08 · 对自主系统：轨迹合理吗，不只结果？🔴（仅自主系统）
- **必答**: 它是怎么做到的——工具选对了吗、推理路径合理吗、有没有绕远/蒙对？
- **通过判据**: 评了轨迹层，结果对且过程稳健（非靠运气）。
- **失败信号**: 结果全对但轨迹显示经常靠运气纠正。
- **Relevant**: 评价必须分层 · SIT-13

## Q-09 · 它长期让用户变好还是变差？🟠
- **必答**: 长期使用后，用户的真实能力/处境是变好还是变差（依赖/退化/被误导）？
- **通过判据**: 长期价值被纳入评价；健康依赖(增强能力)而非有害依赖(替代能力)。
- **失败信号**: 优化即时满意，养出上瘾/谄媚/让用户退化的系统。
- **Relevant**: 长期价值 · ANTI-11

## Q-10 · 评价者自己被校准了吗？🔴
- **必答**: 我用的 benchmark/裁判模型/人类评价，与真实价值的相关性检验过吗？
- **通过判据**: 评价体系本身被质疑和校准过（元评价）。
- **失败信号**: 把评价分数当客观真理，从不质疑评价本身。
- **Relevant**: LAW-04 · 地图非疆域 · PAT-06

---

## 交付判定

```
IF 任何 🔴(Q-01,02,03,05,06,08,10) 未通过:
   → BLOCK. 不可交付/上线。记录哪条、为什么。
IF 任何 🟠(Q-04,07,09) 未通过:
   → WARN. 可交付但必须明确记录并接受该风险。
IF 全部通过:
   → PASS. 但记住(LAW-04+地图非疆域): 评价是"好"的代理不是"好"本身。
     PASS 不等于完美，只等于"已知的检验都过了"。持续评价不停。
```

## 最终锚点

评价服务于判断，不取代判断（LAW-12）。这 10 问帮你系统地看，但“这真的是用户需要的吗、代价值得吗”这类价值判断，仍应由制度授权且掌握必要信息的人作出；相关问责按角色落到自然人或法人，不能停在 AI。**评价错了比不评价更危险——它给你虚假的信心。所以永远对你的评价本身保持怀疑。**
