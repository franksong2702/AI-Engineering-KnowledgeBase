# Part 2 单 Agent 评价框架

> 一个 Agent 是一台在循环里推理、行动、观察的机器（[[01_推理模式|ReAct]]）。评价它需要拆到它的构成能力上。以下十二个维度，每个含六项：定义、为什么重要、如何测试、常见失败、评价指标、改进方法。
>
> **一条贯穿的原则先行**：这十二维不能只在"结果层"评，必须在"轨迹层"评——一个 Agent 结果对了但过程靠运气/绕远路/用错工具，上线就翻车（[[evaluation-of-ai-systems/00_INDEX|评价必须分层]]）。看它怎么做的，比看它做出什么更能预测它未来的表现。

---

## 2.1 规划 Planning

**定义**：把一个目标分解为有序、有依赖、可执行的步骤的能力（[[05_Planner-Executor|Planner-Executor]]的规划端）。

**为什么重要**：规划是复杂任务成败的上游——规划错了，执行再好也是高效地做错事（[[06_循环执行型|双环学习]]）。规划质量决定了任务的天花板。

**如何测试**：给复杂多步任务，评估其计划的（a）完整性（是否覆盖必要步骤）、（b）依赖正确性（顺序和并行判断）、（c）可行性（每步是否真能执行）、（d）应变（前提变化时能否重规划）。用需要探路的任务测试它是否把探路步骤前置。

**常见失败**：跳过规划直接冲执行；计划过于僵化不留重规划空间；漏掉关键依赖导致执行卡壳；把不可预知的探索型任务硬做成固定计划（[[02_计算与验证定律#Law 16 — 不可预验证定律（Undecidability Law）|不可预验证]]）；规划谬误（系统性低估步数/难度）。

**评价指标**：计划完整性（覆盖率）、依赖正确率、重规划触发的恰当性、计划与实际执行的偏差度、探路步骤前置率。

**改进方法**：交错规划（每步后更新计划而非一次定死）；用历史执行反馈校准估计；规划自检（拆完先审"漏了什么维度"）；对高不确定任务改用 [[01_推理模式|ReAct]] 式边做边想而非预先规划。

## 2.2 推理 Reasoning

**定义**：从已知信息推导出正确结论的能力，含逻辑、因果、数值、常识推理。

**为什么重要**：推理是 Agent 决策的核心；推理错误会沿轨迹传播放大（[[02_计算与验证定律#Law 14 — 误差累积定律（Error Compounding Law）|误差累积]]）。

**如何测试**：用需要多步推理的任务，且**看推理链而非只看结论**——结论对但推理错说明它蒙对了，不可靠。用[[01_推理模式|Self-Consistency]]测稳定性（多次采样答案是否一致）。用反事实/对抗题测它是真推理还是模式匹配。

**常见失败**：跳步导致错误；推理链看似合理实则错误（[[07_认识论与真理定律#Law 62 — 流畅度非正确性定律（Fluency-Is-Not-Truth Law）|流畅非正确]]）；后合理化（先有结论再编推理，[[07_认识论与真理定律#Law 68 — 后合理化定律（Post-Hoc-Rationalization Law）|解释不忠实]]）；被表面相似误导（[[01_信息与压缩定律#Law 11 — 语义邻近非相关定律（Semantic-Proximity-Is-Not-Relevance Law）|语义邻近非相关]]）；长推理链中途漂移。

**评价指标**：结论正确率、推理链忠实度（推理是否真导向结论）、自洽性（多次采样一致度）、分布外推理保持率、每步推理的可验证性。

**改进方法**：要求"先推理后结论"而非"先结论后解释"；[[01_推理模式|分解]]大推理为可验证小步；接入验证器核查中间步；对难题上更多推理计算（[[02_计算与验证定律#Law 19 — 计算可换质量定律（Compute-Quality Tradeoff Law）|计算换质量]]）。

## 2.3 执行 Execution

**定义**：把计划/决策转化为实际行动并完成的能力——不只是想对，还要做对、做完。

**为什么重要**：规划推理再好，执行不到位就没有价值交付。执行是"想"到"做"的兑现环节，也是[[01_评价的基础理论|能力变有用]]的最后一公里。

**如何测试**：端到端任务完成度——不是"开始做了"，是"做完了且达标"。测试它在执行中遇到障碍时的表现（放弃？绕路？硬撑？）。测试长任务的执行贯彻度（会不会中途忘记目标）。

**常见失败**：半途而废（做了一部分就停）；执行漂移（越做越偏离原目标）；遇障碍即放弃或无效重试；忽略计划擅自行动；把"尝试了"当成"完成了"。

**评价指标**：任务完成率（真完成，非启动率）、目标一致性（执行是否贯穿原目标）、障碍恢复率、执行步骤的有效率（多少步是有用的 vs 空转）。

**改进方法**：执行中定期回看目标（防漂移）；障碍时触发[[01_推理模式|反思]]而非盲目重试；[[03_知识与记忆模式|状态检查点]]支持长任务续跑；明确的完成判据（[[04_最值得记忆的设计原则|为验证而设计]]）。

---

## 2.4 工具使用 Tool Use

**定义**：正确判断何时用工具、选对工具、传对参数、正确处理返回值的能力（[[03_知识与记忆模式|工具使用]]）。

**为什么重要**：工具是 Agent 突破自身局限的方式（精确计算、实时信息、执行操作）；工具用错是 Agent 失败的高频来源。

**如何测试**：给需要工具的任务，评估（a）该用时用没用、不该用时是否克制、（b）选对工具没、（c）参数对不对、（d）工具返回错误时能否自愈。故意让工具返回错误/空/异常，测其鲁棒性。

**常见失败**：该用工具时凭记忆瞎编（[[01_信息与压缩定律#Law 4 — 信息守恒定律（No-Information-From-Nothing Law）|信息守恒]]）；不该用时滥用（简单问题也调工具）；选错工具或传错参数；**吞掉工具错误静默失败**（[[08_可靠性与失败定律#Law 71 — 显式失败定律（Fail-Loudly Law）|显式失败]]——最阴险）；把工具返回的不可信内容当指令执行（[[10_对抗与安全定律|注入]]）。

**评价指标**：工具调用恰当率（该用/不该用的判断）、选择准确率、参数正确率、错误自愈率、无效调用比例。

**改进方法**：清晰的工具描述（模型只凭 description 决策）；工具返回有用的错误信息（支持自愈）；限制工具数量（[[04_系统与控制定律|3-5 个起步]]防选择困难）；把工具返回值当不可信内容处理。

## 2.5 记忆 Memory

**定义**：在任务内和跨任务保持、检索、更新相关信息的能力（[[03_知识与记忆模式|记忆机制]]）。

**为什么重要**：无记忆的 Agent 每次从零开始，无法处理长任务、无法积累经验、无法个性化。记忆是连续性和成长的基础。

**如何测试**：长任务中测它是否记得早期的关键信息（[[01_信息与压缩定律#Law 10 — 有效注意力有限定律（Finite-Effective-Attention Law）|lost in the middle]]）；跨会话测它是否记得用户偏好；测记忆的准确性（检索回来的对不对）；测冲突处理（旧信息过时了怎么办）。

**常见失败**：遗忘关键信息（尤其上下文中段）；检索到错误/过时记忆并误用；记忆膨胀导致噪声；冲突记忆处理不当（用户偏好变了仍用旧的）；[[10_对抗与安全定律#Law 92 — 数据即攻击面定律（Data-Is-Attack-Surface Law）|记忆污染]]（一次注入长期潜伏）。

**评价指标**：关键信息保持率、记忆检索准确率、跨会话一致性、过时记忆的更新率、无关记忆的干扰度。

**改进方法**：分层记忆（短期上下文/中期状态摘要/长期外部检索，[[llm-design-patterns/00_INDEX|见记忆模式]]）；[[03_知识与记忆模式|压缩]]保留关键、丢弃冗余；记忆的时间戳与置信度；遗忘/更新机制处理陈旧。

---

## 2.6 学习 Learning

**定义**：从经验、反馈、错误中改进未来表现的能力——不重复同样的错误。

**为什么重要**：会学习的系统随时间变好，不会学习的系统停在原地。学习能力决定了系统的成长曲线（区别于静态能力）。

**如何测试**：给同类任务的序列，看它是否从前面的错误中改进（错误率是否下降）；给一次纠正后看它是否泛化到相似情况；**关键——区分"真学习"和"上下文内的临时适应"**（关掉记忆后是否还保留改进）。

**常见失败**：反复犯同样的错误（没有从反馈学习）；过度拟合单次反馈（一次纠正矫枉过正）；学到的东西不泛化（只在完全相同的情况有效）；把噪声当信号学（[[03_统计与泛化定律#Law 29 — 回归均值定律（Regression-to-Mean Law）|回归均值]]误读）。

**评价指标**：同类任务的错误率下降斜率、单次纠正的泛化率、学习的持久性（跨会话保留）、学习的样本效率（几个例子学会）。

**改进方法**：把[[01_推理模式|反思教训]]沉淀为可检索的经验库；结构化的错误归因（学根因而非表面）；区分该学的信号和不该学的噪声；用[[06_循环执行型|PDCA]]式的显式改进循环。

---

## 2.7 适应 Adaptation

**定义**：面对变化的环境、新的任务类型、意外情况时调整策略的能力（区别于学习——学习是跨时间积累，适应是当下应变）。

**为什么重要**：真实环境是动态的（[[03_统计与泛化定律#Law 25 — 分布漂移定律（Distribution Shift Law）|分布漂移]]），僵化的系统会在环境变化时失效。适应力决定系统的鲁棒性边界。

**如何测试**：任务中途改变条件/规则/目标，看它能否调整；给分布外的意外输入，看它是优雅应对还是崩溃；测它区分"该坚持原策略"和"该切换策略"的判断。

**常见失败**：僵化（环境变了仍用旧策略）；过度反应（一点扰动就大改，[[04_系统与控制定律#Law 35 — 延迟致振荡定律（Latency-Oscillation Law）|延迟致振荡]]）；无法识别"情况已变"的信号；在该坚持时动摇、该变时固执（[[06_循环执行型|OODA]] 的 Orient 失灵）。

**评价指标**：环境变化后的表现保持率、策略切换的恰当性（该切换时切换率、不该切换时的稳定性）、分布外输入的优雅降级率、适应的速度。

**改进方法**：[[06_循环执行型|OODA]] 式的持续观察-定向-调整；明确的"情况已变"检测信号；在适应和稳定间设阻尼（防振荡）；[[04_系统与控制定律#Law 42 — 优雅降级定律（Graceful-Degradation Law）|优雅降级]]设计应对分布外。

---

## 2.8 沟通 Communication

**定义**：与人或其他 Agent 清晰、准确、恰当地交换信息的能力——含表达和理解两向。

**为什么重要**：Agent 不是孤岛——它要理解人的意图（[[laws-of-ai-engineering/09_人机与信任定律#Law 83 — 意图-指令鸿沟定律（Intent-Instruction-Gap Law）|意图非指令]]）、向人汇报、与其他 Agent 协作（Part 3）。沟通质量决定协作质量和可用性。

**如何测试**：测它对模糊请求的处理（澄清还是瞎猜）；测它汇报的清晰度和准确性（结论先行？暴露不确定性？）；测它传递给其他 Agent 的信息是否自包含、无损、结构化。

**常见失败**：误解意图照字面执行（[[laws-of-ai-engineering/09_人机与信任定律#Law 83 — 意图-指令鸿沟定律（Intent-Instruction-Gap Law）|意图非指令鸿沟]]）；汇报冗长埋没重点或过简丢失关键；不暴露不确定性（伪装确定，[[07_认识论与真理定律#Law 63 — 不确定性外显定律（Surface-Uncertainty Law）|不确定性外显]]失败）；传给其他 Agent 的信息不自包含（对方缺上下文）。

**评价指标**：意图理解准确率、模糊请求的澄清率（该问时问）、汇报的信息密度与准确性、不确定性表达的校准度、Agent 间信息传递的无损率。

**改进方法**：模糊时先[[02_提示结构模式|Rephrase]]确认理解；结论先行的汇报结构；强制标注置信度和 gaps；Agent 间传结构化结论而非原始对话（[[multi-agent-patterns-handbook/00_INDEX|Multi-Agent 定律 3]]）。

---

## 2.9 自我纠正 Self-Correction

**定义**：识别自己的错误并修正的能力——在没有外部指出的情况下发现"我错了"。

**为什么重要**：能自纠的系统能在部署中止损，不能自纠的系统会把错误进行到底。这是可靠性的关键内在机制。详见 [[04_自我评价|Part 4 自我评价]]。

**如何测试**：给它会出错的任务，看它是否自己发现错误；给它一个错误的中间结果，看它能否察觉并回退；**关键——测试它自纠的真实性**（是真发现了问题，还是无论对错都"反思"一通）。

**常见失败**：察觉不到自己的错误（尤其[[03_统计与泛化定律|系统性盲区]]）；自我批评流于形式（[[04_自我评价|自我表扬]]，无客观信号时的反思常无效）；过度自我怀疑把对的改错；无法回退到错误前的状态。

**评价指标**：错误自检出率、自纠的正确率（改对 vs 改错）、无客观信号时自纠的有效性、自纠触发的恰当性（该纠时纠、不该纠时稳定）。

**改进方法**：给自纠接**客观信号**（测试、执行、检索——无信号的自纠是空转，[[04_自我评价|Part 4 核心]]）；跨模型批评破除[[04_自我评价|自我盲区]]；错误检测与修正分离（先独立判错，再修）。

## 2.10 目标达成 Goal Achievement

**定义**：最终真正达成用户目标的程度——不是完成了任务的字面要求，是实现了背后的真实目的。

**为什么重要**：这是[[01_评价的基础理论|价值交付]]的最终检验，是所有其他维度的汇合点。前面十一维都强，但目标没达成，系统就没有价值。

**如何测试**：用真实目标（而非代理指标）衡量——它有没有让用户真正想要的事变好。**警惕[[03_统计与泛化定律#Law 24 — 古德哈特定律（Goodhart's Law）|古德哈特]]**：测的是真实目标达成，不是某个容易测的代理。用端到端的、情境完整的任务，而非孤立的能力测试。

**常见失败**：达成了字面任务但错过真实意图（[[laws-of-ai-engineering/09_人机与信任定律#Law 83 — 意图-指令鸿沟定律（Intent-Instruction-Gap Law）|意图非指令]]）；优化了代理指标而非真实目标（古德哈特）；解决了跑题的问题（[[01_评价的基础理论|能力强但没用]]）；短期达成但长期有害（[[05_人类评价|长期价值]]）。

**评价指标**：真实目标达成率（非代理）、意图匹配度、用户的实际问题是否解决、达成的可持续性（长期是否仍成立）。

**改进方法**：始终从真实意图而非字面请求出发；用多个代理指标交叉防古德哈特；把长期价值纳入达成的定义；[[05_人类评价|真实用户]]的价值反馈闭环。

---

## 2.11 效率 Efficiency

**定义**：达成目标所消耗的资源（token、延迟、算力、调用次数、人工介入）——同样的价值，代价越小越高效。

**为什么重要**：效率是[[01_评价的基础理论|"好"的内在组成]]，不是外部约束。一个高质量但极其昂贵/缓慢的系统在很多场景不可用。效率决定可规模化性和可持续性。

**如何测试**：测量完成任务的资源消耗——token 数、延迟、工具调用次数、需要的人工核查量。**关键是测"质量÷成本"而非只测质量**（[[06_经济与资源定律#Law 54 — 质量有成本定律（Quality-Costs Law）|质量有成本]]）。测它在质量-成本曲线上的位置。

**常见失败**：为微小质量提升消耗巨大资源（[[06_经济与资源定律#Law 52 — 边际定律（Marginal Law）|边际递减]]无视）；无效的空转步骤（推理绕圈、重复调用）；过度使用昂贵资源（简单任务上大模型/多次采样）；隐藏的人工成本（表面自动实则需大量人工核查）。

**评价指标**：质量÷成本比、每任务的 token/延迟/调用数、有效步骤比例（非空转）、人工介入量、成本随规模的增长曲线。

**改进方法**：按难度[[07_动态路由DynamicRouting|路由]]（简单任务给便宜资源）；[[03_知识与记忆模式|缓存]]复用；剪掉空转步骤；在质量-成本曲线上找[[06_经济与资源定律#Law 52 — 边际定律（Marginal Law）|边际]]最优点而非盲目追质量。

## 2.12 可靠性 Reliability

**定义**：跨时间、跨输入、跨条件稳定交付正确结果的程度（[[01_评价的基础理论|见 Part 1 定义]]）——是前面所有维度的稳定性度量。

**为什么重要**：这是**对多数真实应用最决定性的维度**。因为你无法部署一个"有时对有时错且不知何时"的系统。可靠性是能力转化为价值的前提，是[[laws-of-ai-engineering/00_INDEX|信任]]的基础。

**如何测试**：**不用"最好的一次"，用分布**——大量重复测量成功率和方差；用[[03_统计与泛化定律|长尾/边界/对抗]]输入测鲁棒性；跨时间测一致性；**重点测失败的可预测性**（错误是否集中在可识别的地方）。

**常见失败**：高峰值低稳定（惊艳但不可依赖）；长尾脆弱（常见输入好、边角崩）；分布漂移后静默退化（[[08_可靠性与失败定律#Law 76 — 静默降级危险定律（Silent-Degradation-Danger Law）|静默降级]]）；失败随机不可预测（无法工程化围堵）；被"平均分"掩盖的严重尾部失败。

**评价指标**：成功率及其方差、最坏情况表现（非平均）、长尾/对抗鲁棒性、跨时间一致性、失败的可预测性与可预警性。

**改进方法**：为可靠性而非峰值优化；[[04_系统与控制定律#Law 42 — 优雅降级定律（Graceful-Degradation Law）|优雅降级]]处理分布外；[[08_可靠性与失败定律#Law 71 — 显式失败定律（Fail-Loudly Law）|显式失败]]替代静默降级；持续监控防漂移退化；把不可靠的能力用[[04_质量控制模式|冗余/投票/校验]]围起来。

## Part 2 收束：十二维不是清单，是一张相互关联的网

这十二维不能孤立打分再相加——它们相互依赖、相互权衡。规划错了执行再好也白搭；能力再强不可靠也没用；效率和质量此消彼长；自主性要被可靠性证明。**评价一个 Agent 不是给十二个分数，是理解这些维度如何在这个特定系统、这个特定任务上相互作用。**

而所有维度最终服务于一个问题（Part 1 的中心命题）：**它在真正重要的事上，可靠、划算、可信地交付了价值吗？** 十二维是这个问题的十二个切面，不是十二个独立目标。

最后一条纪律，贯穿整个 Part 2：**永远优先在轨迹层评价**。结果对了不代表系统好——它可能蒙对、绕远、用错工具、靠运气。看它怎么做的，才能预测它下次还行不行。这是自主系统评价区别于传统软件测试的根本之处。
